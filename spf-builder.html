SPF 레코드 생성기 · 검사기

메일을 보내는 서버를 나열해 SPF TXT 레코드를 만들고, 이미 쓰고 있는 레코드의 문법 오류, ptr·+all 같은 위험 설정, DNS 조회 10회 한도 초과 여부를 검사합니다.

사용 예시

✅ SPF 레코드를 만들었습니다 (DNS 조회 3/10)

입력 — 발신 출처 (한 줄에 하나)

mx
include:_spf.google.com
ip4:203.0.113.10
ip4:198.51.100.0/24
ip6:2001:db8::/32
a:mail.example.com

입력 — 검사할 SPF 레코드

v=spf1 mx include:_spf.google.com include:spf.protection.outlook.com ptr ip4:203.0.113.10 ?all

결과 — SPF TXT 값

v=spf1 mx include:_spf.google.com ip4:203.0.113.10 ip4:198.51.100.0/24 ip6:2001:db8::/32 a:mail.example.com -all

example.com.  IN  TXT  "v=spf1 mx include:_spf.google.com ip4:203.0.113.10 ip4:198.51.100.0/24 ip6:2001:db8::/32 a:mail.example.com -all"

결과 — 항목별 해석

항목 | 한정자 | 의미 | DNS 조회
mx | 허용 | 이 도메인의 MX 서버가 발신 서버 | 1
include:_spf.google.com | 허용 | _spf.google.com 의 SPF 정책을 포함 (Google Workspace / Gmail) | 1
ip4:203.0.113.10 | 허용 | 203.0.113.10 대역에서 발송 허용 (1개 주소) | 0
ip4:198.51.100.0/24 | 허용 | 198.51.100.0/24 대역에서 발송 허용 (256개 주소) | 0
ip6:2001:db8::/32 | 허용 | 2001:db8::/32 대역에서 발송 허용 (2^96개 주소) | 0
a:mail.example.com | 허용 | mail.example.com 의 A/AAAA 주소가 발신 서버 | 1
-all | 거부 | 위에 나열되지 않은 모든 서버의 메일을 거부 | 0

이 도구로 할 수 있는 일

SPF는 어떤 서버가 내 도메인 이름으로 메일을 보낼 수 있는지 DNS에 선언하는 레코드입니다. 잘못 쓰면 정상 메일이 스팸함으로 가거나 아무나 위장할 수 있습니다.

  • 만들기: mx, a, include:, ip4:, ip6: 를 한 줄씩 입력하고 -all / ~all / ?all 선택. google, microsoft365, sendgrid, mailgun, ses, mailchimp, zoho 단축어 지원
  • 검사: v=spf1 시작 여부, 알 수 없는 항목, all 뒤의 무시되는 항목, 중복, redirect와 all 충돌
  • 위험 설정: +all(누구나 발송 허용), ?all(보호 없음), ptr(사용 금지 권고), 0.0.0.0/0, 호스트 비트가 남은 CIDR
  • DNS 조회 횟수(include·a·mx·ptr·exists·redirect)를 세어 10회 한도 초과(PermError) 경고
  • 255자를 넘으면 여러 문자열로 나눠 등록하는 형식으로 DNS 값을 출력

💡 Tips

  • SPF 레코드는 도메인당 하나만 둘 수 있습니다. 서비스를 추가할 때 TXT를 새로 만들지 말고 기존 레코드에 include를 더하세요.
  • ~all(소프트페일)로 시작해 DMARC 보고서로 정상 발신원을 확인한 뒤 -all 로 올리는 것이 안전합니다.
  • include 안에서도 DNS 조회가 일어나 합산됩니다. 한도에 가까우면 사용하지 않는 서비스를 정리하세요.

자주 묻는 질문

조회 10회 한도를 넘으면 어떻게 되나요?

수신 서버가 SPF를 PermError로 처리해 인증이 실패합니다. include가 중첩된 서비스(Google 등)는 내부 조회도 합산되므로 실제로는 더 빨리 한도에 도달합니다.

이 도구가 DNS를 직접 조회하나요?

아니요. 입력한 문자열만 정적으로 분석합니다. include 내부의 조회 수와 실제 게시된 레코드는 확인하지 않으므로 DNS 조회 도구와 함께 쓰세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
