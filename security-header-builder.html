보안 헤더 생성기 — Nginx · Apache · Caddy · helmet

HSTS, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy, CORS, COOP/COEP를 골라 서버 종류에 맞는 설정 코드를 바로 만들어 줍니다.

사용 예시

✅ 헤더 5개 설정을 만들었습니다

결과 — 보안 헤더 설정

# server { … } 또는 location 블록 안에
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "DENY" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), interest-cohort=()" always;

결과 — 적용되는 헤더

헤더 | 값 | 의미
Strict-Transport-Security | max-age=31536000; includeSubDomains | HTTPS만 사용하도록 브라우저에 기억시킴
X-Content-Type-Options | nosniff | MIME 스니핑 방지
X-Frame-Options | DENY | 클릭재킹 방지 (CSP frame-ancestors로 대체 가능)
Referrer-Policy | strict-origin-when-cross-origin | Referer 헤더로 새는 정보 제한
Permissions-Policy | camera=(), microphone=(), geolocation=(), interest-cohort=() | 브라우저 기능 사용 제한

이 도구로 할 수 있는 일

보안 점검 사이트에서 헤더 누락 경고를 받았을 때, 어떤 헤더를 어떤 값으로 넣어야 하는지 설정 코드까지 만들어 줍니다.

  • 출력 형식: Nginx add_header, Apache .htaccess, Caddy, Express helmet + cors, Netlify/Cloudflare Pages _headers, 단순 목록
  • 프리셋(권장·엄격·최소)과 HSTS(max-age, includeSubDomains, preload) 세부 설정
  • CORS: 허용 출처·메서드·헤더·자격 증명, * 와 자격 증명 동시 사용 등 잘못된 조합 경고
  • 교차 출처 격리(COOP + COEP) 선택과 영향 안내
  • 각 헤더가 하는 일을 표로 설명

💡 Tips

  • HSTS preload는 되돌리기 어렵습니다. 모든 하위 도메인이 HTTPS를 지원하는지 확인한 뒤 켜세요.
  • Nginx에서는 add_header 에 always 를 붙여야 오류 응답(4xx/5xx)에도 헤더가 붙습니다.
  • CSP는 사이트마다 달라 별도 도구(CSP 생성기)에서 만드세요.

자주 묻는 질문

X-Frame-Options 대신 CSP를 써도 되나요?

네. CSP의 frame-ancestors 가 더 유연하고 최신 방식입니다. 오래된 브라우저 호환을 위해 둘 다 두는 경우가 많습니다.

Access-Control-Allow-Origin: * 는 안전한가요?

공개 API라면 괜찮지만 쿠키·인증이 필요한 요청에는 쓸 수 없고(자격 증명과 함께 불가), 특정 출처만 허용하는 편이 안전합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
