IEEE 754 부동소수점 변환기

숫자를 float16·32·64 비트 패턴(16진수)으로, 비트 패턴을 숫자로 바꾸고 부호·지수·가수와 반올림 오차를 보여 줍니다.

사용 예시

✅ 32비트 IEEE 754 — 부호 1 / 지수 8 / 가수 23비트

입력 — 숫자 또는 16진수 비트열 (한 줄에 하나)

0.1
-3.14159
1e-320
0x40490FDB
Infinity
NaN

결과 — 변환 결과

이 도구로 할 수 있는 일

0.1 + 0.2 ≠ 0.3 같은 현상은 모두 부동소수점 표현에서 나옵니다. 숫자가 실제로 어떤 비트로 저장되는지, 얼마나 오차가 생기는지 직접 볼 수 있습니다.

  • 숫자 → 비트: 부호 1비트 | 지수(5/8/11비트) | 가수(10/23/52비트)로 분해하고 16진수로 표시
  • 비트 → 숫자: 0x40490FDB 같은 비트 패턴을 float로 해석 (또는 일반 정수로 취급 선택)
  • 저장되는 실제 값과 입력과의 절대 오차를 표시 (예: float32의 0.1 = 0.10000000149011612)
  • 정규수·비정규수(subnormal)·0·무한대·NaN(quiet/signaling) 분류와 지수
  • 16비트(half) 변환은 머신러닝·그래픽에서 쓰는 형식 확인에 유용

💡 Tips

  • float32는 약 7자리, float64는 약 15~16자리까지만 10진수를 정확히 표현합니다.
  • 2의 거듭제곱 분수(0.5, 0.25, 0.125)는 오차 없이 저장됩니다. 0.1처럼 이진 무한소수가 되는 값이 오차의 원인입니다.
  • 비정규수는 0 근처에서 정밀도를 희생하며 값을 이어 주는 영역입니다.

자주 묻는 질문

0.1을 float로 저장하면 왜 정확하지 않나요?

0.1은 2진수로 0.0001100110011… 처럼 무한히 반복되어 유한한 가수 비트로는 근삿값만 담을 수 있기 때문입니다.

quiet NaN과 signaling NaN의 차이는?

가수의 최상위 비트가 1이면 quiet NaN(연산을 조용히 전파), 0이면 signaling NaN(예외를 일으킬 수 있음)입니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
