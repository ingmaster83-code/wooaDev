XSD → JSON Schema 변환기

XSD 의 최상위 요소를 JSON Schema 로 바꿉니다. complexType 은 object, maxOccurs>1 은 array, 속성은 "@이름" 속성, 단순 타입은 type/format, 패싯은 enum·pattern·minimum·maxLength 로 옮기고 이름 있는 타입은 $defs 로 분리합니다.

사용 예시

✅ "library" 을(를) JSON Schema 로 변환했습니다

입력 — XSD 스키마

<?xml version="1.0"?>
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  <xs:simpleType name="IsbnType">
    <xs:restriction base="xs:string">
      <xs:pattern value="\d{3}-\d{10}"/>
    </xs:restriction>
  </xs:simpleType>
  <xs:complexType name="PersonType">
    <xs:sequence>
      <xs:element name="name" type="xs:string"/>
      <xs:element name="email" type="xs:string" minOccurs="0"/>
    </xs:sequence>
    <xs:attribute name="id" type="xs:ID" use="required"/>
  </xs:complexType>
  <xs:element name="library">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="book" maxOccurs="unbounded">
          <xs:complexType>
            <xs:sequence>
              <xs:element name="isbn" type="IsbnType"/>
              <xs:element name="title" type="xs:string"/>
              <xs:element name="author" type="PersonType" maxOccurs="3"/>
              <xs:choice>

결과 — 변환 규칙·참고

xs:choice 는 속성을 모두 나열한 뒤 oneOf/anyOf 로 필수 조합만 구분합니다 (근사)
XML 의 속성은 "@이름" 속성으로, 반복 요소(maxOccurs>1)는 배열로 옮겼습니다. XML→JSON 변환기마다 규칙이 다르니(속성 접두사, 단일 요소의 배열 여부) 실제 변환 결과와 맞는지 확인하세요
XML 요소의 순서(sequence)와 key/unique 제약은 JSON Schema 로 표현할 수 없어 생략했습니다

이 도구로 할 수 있는 일

XML 기반 API 를 JSON 으로 옮기면서 스키마도 함께 변환할 때 씁니다. 스키마는 브라우저 밖으로 나가지 않습니다.

  • 구조: element → 속성, 필수 여부(minOccurs) → required, maxOccurs>1 → array(minItems·maxItems), complexType → object, additionalProperties 옵션
  • 타입: 정수군(범위 → minimum/maximum), decimal/float/double → number, boolean, date·dateTime·time·duration·anyURI → format, hexBinary·base64Binary
  • 패싯: enumeration → enum, pattern, length·minLength·maxLength, min/maxInclusive·Exclusive, fractionDigits → multipleOf, list → array, union → anyOf
  • 특수: simpleContent+속성은 "#text" 키, 속성 접두사(@ 기본) 지정, choice → oneOf(필수 조합), nillable → null 허용, mixed
  • 이름 있는 simpleType/complexType 은 $defs(draft-07 은 definitions) 와 $ref, 루트 요소 선택과 요소 이름으로 한 단계 감싸기

💡 Tips

  • XML→JSON 변환기마다 규칙이 다릅니다. 속성 접두사와 단일 요소가 배열인지 여부를 실제 변환 결과에 맞게 옵션으로 조정하세요.
  • XML 의 요소 순서(sequence)는 JSON 객체에서 의미가 없어 JSON Schema 로 표현하지 않습니다.
  • 64비트 정수(long)는 JSON 숫자의 안전 범위를 넘을 수 있으니 문자열 처리가 필요한지 확인하세요.

자주 묻는 질문

xs:choice 는 정확히 변환되나요?

근사입니다. 모든 선택지를 속성으로 나열하고 oneOf 로 필수 조합만 구분하므로 선택지끼리 동시에 있으면 안 되는 제약은 완전히 표현되지 않을 수 있습니다.

import 한 스키마는요?

import/include 는 지원하지 않으며 해당 타입 참조는 빈 스키마가 됩니다. 필요한 정의를 한 파일로 합쳐 넣으세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
