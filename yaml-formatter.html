YAML 포맷터 — 주석과 구조를 지키며 들여쓰기 정리

들여쓰기가 제각각인 YAML을 2칸·4칸으로 통일합니다. 주석과 키 순서를 그대로 두고, 결과가 원본과 같은 의미인지 검증합니다.

사용 예시

✅ 정리 완료 — 주석과 키 순서를 유지했고, 의미가 같은지 검증했습니다.

입력 — YAML 입력

# service config
service:
    name: api      # keep this comment
    ports:
        - 80
        - 443
    env:
        - name: MODE
          value: prod
    script: |
        echo "start"
        run --fast
  
limits: {cpu: 2, mem: 512}

결과 — 정리된 YAML

# service config
service:
  name: api      # keep this comment
  ports:
    - 80
    - 443
  env:
    - name: MODE
      value: prod
  script: |
    echo "start"
    run --fast

limits: {cpu: 2, mem: 512}

이 도구로 할 수 있는 일

많은 YAML 포맷터가 파일을 파싱해서 다시 쓰기 때문에 주석이 모두 사라집니다. 이 도구의 기본 모드는 텍스트의 들여쓰기만 다시 계산해서 주석·키 순서·따옴표 스타일을 건드리지 않습니다.

  • 들여쓰기만 정리: 2·3·4칸 통일, 불필요한 줄 끝 공백 제거, 블록 스칼라(|, >) 내용 보존
  • 정리 결과를 다시 파싱해 원본과 같은 데이터인지 확인하고, 다르면 결과를 내지 않고 알려 줌
  • 구조 다시 쓰기: js-yaml 방식으로 완전히 재작성 (주석 제거, 키 정렬·긴 줄 접기·앵커 옵션)
  • 여러 문서(---)와 시퀀스 안의 매핑(- name: x)도 올바르게 처리

문법 오류는 줄·열 위치와 함께 알려 줍니다.

💡 Tips

  • docker-compose.yml, GitHub Actions, Kubernetes 매니페스트처럼 주석이 중요한 파일은 기본 모드를 쓰세요.
  • 탭 문자로 들여쓴 YAML은 허용되지 않으므로 공백으로 바꾸라는 안내가 표시됩니다.
  • 키 정렬이 필요하면 "구조 다시 쓰기" 모드를 선택하세요 (주석은 사라집니다).

자주 묻는 질문

정리하면 값이나 의미가 바뀔 수 있나요?

기본 모드는 정리 후 다시 파싱해 원본과 동일한 데이터인지 비교하고, 달라지면 결과를 내지 않습니다. 따라서 의미가 바뀌는 상태로 출력되지 않습니다.

블록 스칼라(|)의 들여쓰기 지시자(|2)는 지원하나요?

자동 정리에서는 지원하지 않고 안내 메시지를 표시합니다. 그런 경우 "구조 다시 쓰기" 모드를 사용하세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
