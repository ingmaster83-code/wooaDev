W3C Trace Context 도구 — traceparent · tracestate

분산 추적 헤더 traceparent(00-trace-id-span-id-flags)와 tracestate 를 분석해 유효성을 확인하고, 새 trace 를 시작하거나 부모에서 자식 span 을 만들어 curl·B3·Datadog 헤더 예시까지 보여 줍니다.

사용 예시

✅ 유효한 traceparent 입니다

입력 — traceparent 헤더 값

00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01

입력 — tracestate 헤더 값 (선택)

congo=t61rcWkgMzE,rojo=00f067aa0ba902b7

입력 — 부모 traceparent (자식 span 만들기)

00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01

결과 — 필드

필드 | 값
version | 00
trace-id | 4bf92f3577b34da6a3ce929d0e0e4736
parent-id (span) | 00f067aa0ba902b7
trace-flags | 01 (0b00000001)
sampled | 예 — 이 trace 를 기록·내보내기
random-trace-id | 아니오/알 수 없음
tracestate[1] | congo = t61rcWkgMzE
tracestate[2] | rojo = 00f067aa0ba902b7

결과 — 헤더

traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
tracestate: congo=t61rcWkgMzE,rojo=00f067aa0ba902b7

이 도구로 할 수 있는 일

OpenTelemetry 등 분산 추적에서 서비스 사이를 넘나드는 traceparent 가 올바른지, 샘플링되는지 확인합니다.

  • 분석: version, 32자 trace-id, 16자 span-id, flags(sampled=01, random=02), tracestate 항목
  • 검증: 소문자 16진수, 길이, 전부 0인 ID 금지, version ff 금지, version 00의 추가 필드 금지, tracestate 키·값·32개/512자 한도
  • 생성: 암호학적 난수로 새 trace, 부모 trace-id 를 유지한 자식 span
  • curl 헤더, B3(Zipkin), Datadog 형식으로 변환한 예시
  • 잘못된 tracestate 는 traceparent 와 별개로 무시된다는 점을 안내

💡 Tips

  • sampled 플래그가 00 이면 그 trace 는 기록·전송되지 않을 수 있습니다.
  • 서비스는 받은 trace-id 를 유지하고 span-id 만 새로 만들어 다음 호출에 전달해야 이어집니다.
  • trace-id 를 로그에 함께 남기면 로그와 추적을 연결할 수 있습니다.

자주 묻는 질문

traceparent 와 tracestate 의 차이는요?

traceparent 는 모든 시스템이 이해하는 표준 필드이고, tracestate 는 벤더별 추가 정보를 담는 선택 필드입니다.

대문자 16진수는 왜 안 되나요?

규격이 소문자 16진수만 허용하기 때문입니다. 대문자로 만들면 수신 측이 헤더를 무시합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
