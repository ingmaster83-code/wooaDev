이 도구로 할 수 있는 일

Athena 를 쓰기엔 가벼운 확인이 필요할 때, 로그 몇 줄을 바로 읽기 좋은 형태로 바꿉니다. 로그는 브라우저에서만 처리됩니다.

  • 자동 판별: ALB(http/https/h2/ws…), NLB(tls), CloudFront(#Fields 헤더 + 탭), S3 서버 액세스 로그
  • ALB: 30개 필드 CSV, 시각·클라이언트·요청·ELB/타깃 상태·처리 시간 요약, 5xx와 502(타깃 무응답)·느린 요청 표시
  • CloudFront: 헤더의 필드 이름으로 CSV, 엣지 위치·결과 유형, 캐시 적중률
  • S3: 버킷 소유자부터 TLS 버전까지 필드 이름 부여, 작업·키·상태
  • 큰따옴표로 묶인 값(요청 줄, User-Agent)을 올바르게 분리

함께 쓰면 좋은 도구

💡 Tips

  • ALB 502 에서 타깃 상태가 - 이면 타깃이 연결을 끊었거나 응답이 없었다는 뜻입니다. 헬스체크와 keep-alive 시간을 확인하세요.
  • CloudFront 의 Error 결과는 오리진 오류이거나 요청 오류일 수 있습니다. x-edge-detailed-result-type 필드를 보세요.
  • 대량 분석은 Athena 테이블을 만들어 SQL 로 조회하는 것이 효율적입니다.

자주 묻는 질문

로그가 gzip 파일인데요?

먼저 압축을 풀어 텍스트를 붙여 넣으세요. 이 도구는 텍스트만 처리합니다.

CloudFront 로그 헤더가 없으면?

#Fields 줄이 있어야 필드 이름을 알 수 있습니다. 파일의 앞 두 줄(#Version, #Fields)을 함께 붙여 넣으세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
