AWS ARN 분석기 · 생성기

arn:aws:iam::123456789012:role/MyRole 같은 ARN을 파티션, 서비스, 리전, 계정, 리소스로 나눠 보여 주고 형식 오류를 찾습니다. 필드를 입력해 새 ARN을 만들 수도 있습니다.

사용 예시

✅ ARN 5개를 분석했습니다

입력 — ARN (한 줄에 하나)

arn:aws:s3:::my-bucket/logs/2026/app.log
arn:aws:iam::123456789012:role/service-role/MyLambdaRole
arn:aws:lambda:ap-northeast-2:123456789012:function:order-handler:prod
arn:aws:dynamodb:ap-northeast-2:123456789012:table/Orders/stream/2026-10-01T00:00:00.000
arn:aws-cn:ec2:cn-north-1:123456789012:instance/i-0abc123def456789a

입력 — partition

aws

입력 — service

sqs

입력 — region

ap-northeast-2

입력 — account-id

123456789012

입력 — resource

my-queue

결과 — 필드별 분석

ARN | 상태 | 서비스 / 파티션 | 리전 / 계정 | 리소스 | 문제
arn:aws:s3:::my-bucket/logs/2026/app.log | ✅ | s3 · Amazon S3 / aws | — / — | my-bucket → logs/2026/app.log | 
arn:aws:iam::123456789012:role/service-role/MyLambdaRole | ✅ | iam · IAM / aws | — / 123456789012 | role → service-role/MyLambdaRole | 
arn:aws:lambda:ap-northeast-2:123456789012:function:order… | ✅ | lambda · AWS Lambda / aws | ap-northeast-2 / 123456789012 | function → order-handler:prod | 
arn:aws:dynamodb:ap-northeast-2:123456789012:table/Orders… | ✅ | dynamodb · DynamoDB / aws | ap-northeast-2 / 123456789012 | table → Orders/stream/2026-10-01T00:00:00.000 | 
arn:aws-cn:ec2:cn-north-1:123456789012:instance/i-0abc123… | ✅ | ec2 · Amazon EC2 / aws-cn | cn-north-1 / 123456789012 | instance → i-0abc123def456789a |

결과 — 결과

arn:aws:s3:::my-bucket/logs/2026/app.log
  partition=aws service=s3 region= account= resource=my-bucket/logs/2026/app.log
arn:aws:iam::123456789012:role/service-role/MyLambdaRole
  partition=aws service=iam region= account=123456789012 resource=role/service-role/MyLambdaRole
arn:aws:lambda:ap-northeast-2:123456789012:function:order-handler:prod
  partition=aws service=lambda region=ap-northeast-2 account=123456789012 resource=function:order-handler:prod
arn:aws:dynamodb:ap-northeast-2:123456789012:table/Orders/stream/2026-10-01T00:00:00.000
  partition=aws service=dynamodb region=ap-northeast-2 account=123456789012 resource=table/Orders/stream/2026-10-01T00:00:00.000
arn:aws-cn:ec2:cn-north-1:123456789012:instance/i-0abc123def456789a
  partition=aws-cn service=ec2 region=cn-north-1 account=123456789012 resource=instance/i-0abc123def456789a

이 도구로 할 수 있는 일

IAM 정책, 리소스 기반 정책, CLI 명령에서 ARN은 끊임없이 등장하지만 서비스마다 resource 부분의 구조가 달라 읽기 어렵습니다.

  • 분해: partition(aws, aws-cn, aws-us-gov), service, region, account-id, resource(타입/이름/버전·별칭 추정)
  • 한 줄에 하나씩 여러 ARN을 붙여 넣어 표로 비교
  • 검증: 계정 ID 12자리, 리전 형식, 파티션, 빈 resource, 리전/계정이 비어야 하는 S3·IAM 서비스
  • 정책용 와일드카드(*)가 들어 있으면 알려 줌
  • 생성 모드: partition·service·region·account·resource를 입력해 ARN 조립

💡 Tips

  • S3 버킷 ARN은 arn:aws:s3:::버킷 이고, 객체는 arn:aws:s3:::버킷/키 입니다. 정책에서 둘을 모두 써야 하는 경우가 많습니다.
  • IAM과 Route 53, CloudFront는 전역 서비스라 region 칸이 비어 있습니다.
  • Lambda 별칭·버전은 function:이름:별칭 형식으로 resource 안에 콜론이 들어갑니다.

자주 묻는 질문

ARN의 resource 부분은 왜 서비스마다 다른가요?

형식이 서비스별로 정해져 있기 때문입니다. 슬래시(/)로 나누는 것, 콜론(:)으로 나누는 것이 섞여 있어 이 도구는 첫 토큰을 타입으로 추정해 보여 줍니다.

계정 ID는 어디서 확인하나요?

콘솔 우측 상단 메뉴나 aws sts get-caller-identity 명령으로 12자리 숫자를 확인할 수 있습니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
