Server-Sent Events (SSE) 스트림 파서

curl 이나 브라우저 개발자도구에서 복사한 text/event-stream 원문을 이벤트 단위로 나눠 event, id, retry, data 필드와 주석 줄을 보여 주고, data 가 JSON 이면 파싱하며 이어붙인 스트리밍 결과도 만들어 줍니다.

사용 예시

🔍 이벤트 4개 · 마지막 블록 미완성

입력 — SSE 스트림 원문 (text/event-stream)

: keep-alive comment
retry: 3000

event: message
id: 101
data: {"delta":"Hel"}

event: message
id: 102
data: {"delta":"lo"}

data: first line
data: second line

event: done
data: [DONE]

data: truncated, no blank line at the end

결과 — 이벤트

# | event | id | 형식 | data
1 | message | 101 | JSON | {"delta":"Hel"}
2 | message | 102 | JSON | {"delta":"lo"}
3 | message | 102 | text | first line ⏎ second line
4 | done | 102 | 종료 신호 | [DONE]
 |  |  |  | 
요약 | message ×3, done ×1 | Last-Event-ID=102 | retry=3000ms | 1개 주석(:)

결과 — data 이어붙인 결과

Hello

이 도구로 할 수 있는 일

LLM 스트리밍 응답이나 알림 스트림을 디버깅할 때 원문을 이벤트로 풀어 봅니다. 데이터는 브라우저 밖으로 나가지 않습니다.

  • 규격 파싱: 빈 줄이 이벤트 경계, 'field: value' 의 첫 콜론 뒤 한 칸 공백 제거, 콜론으로 시작하는 줄은 주석
  • 필드: event(기본 message), data(여러 줄은 \n 으로 결합), id, retry(숫자만 유효)
  • data 가 JSON 이면 파싱해 표시하고 delta/content 필드를 이어붙인 결과 제공
  • [DONE] 같은 종료 표지와 알 수 없는 필드, 마지막 빈 줄 없이 끝난 미완성 이벤트 알림
  • CRLF·CR 줄바꿈 처리

함께 쓰면 좋은 도구

🔁JSON-RPC 2.0 뷰어 📃JSON Lines 뷰어 📨HTTP 헤더 파서 📡MQTT 토픽 필터 테스터

💡 Tips

  • 이벤트는 빈 줄로 끝나야 전달됩니다. 마지막에 빈 줄이 없으면 브라우저는 그 이벤트를 버립니다.
  • 연결이 끊기면 EventSource 는 마지막 id 를 Last-Event-ID 헤더로 보내 재연결합니다.
  • 주석 줄(: keep-alive)은 프록시가 연결을 끊지 않도록 주기적으로 보내는 용도입니다.

자주 묻는 질문

SSE 와 WebSocket 의 차이는요?

SSE 는 서버→클라이언트 단방향 HTTP 스트림이고 자동 재연결이 내장되어 있습니다. WebSocket 은 양방향입니다.

data 여러 줄은 어떻게 합쳐지나요?

같은 이벤트의 data 줄들은 줄바꿈(\n)으로 이어 붙여 하나의 문자열이 됩니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
