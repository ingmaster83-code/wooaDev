package.json exports 시각화 · 해석기

package.json 을 붙여 넣으면 exports 의 부분 경로와 조건(import, require, types, browser, default)을 표로 펼치고, Node import/require, 번들러, TypeScript 환경에서 각각 어떤 파일로 해석되는지 한눈에 보여 줍니다. import 경로를 입력하면 Node.js 의 해석 규칙대로 결과를 계산하고 types 순서, default 위치, 듀얼 패키지 하자드 같은 문제를 점검합니다.

사용 예시

⛔ 오류 1건 · 경고 0건 — demo-lib

입력 — package.json

{
  "name": "demo-lib",
  "version": "1.0.0",
  "type": "module",
  "main": "./dist/index.cjs",
  "module": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "files": [
    "dist"
  ],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js",
      "require": "./dist/index.cjs",
      "default": "./dist/index.js"
    },
    "./feature": {
      "import": "./dist/feature.js",
      "require": "./dist/feature.cjs"
    },
    "./utils/*": "./dist/utils/*.js",
    "./internal/*": null,
    "./legacy/": "./legacy/"
  }
}

결과 — 환경별 해석 결과

부분 경로 | Node import | Node require | 번들러/브라우저 | TypeScript
. | ./dist/index.js | ./dist/index.cjs | ./dist/index.js | ./dist/index.d.ts
./feature | ./dist/feature.js | ./dist/feature.cjs | ./dist/feature.js | ./dist/feature.js
./utils/* | (패턴) |  |  | 
./internal/* | (패턴) |  |  | 
./legacy/ | ./legacy/ | ./legacy/ | ./legacy/ | ./legacy/

결과 — exports 항목 (조건 경로)

부분 경로 | 조건 경로 | 대상
. | types | ./dist/index.d.ts
. | import | ./dist/index.js
. | require | ./dist/index.cjs
. | default | ./dist/index.js
./feature | import | ./dist/feature.js
./feature | require | ./dist/feature.cjs
./utils/* | — | ./dist/utils/*.js
./internal/* | — | null (차단)
./legacy/ | — | ./legacy/

이 도구로 할 수 있는 일

라이브러리를 배포하기 전에 exports 가 의도대로 해석되는지 브라우저에서 확인합니다. package.json 은 전송되지 않습니다.

  • 표: 부분 경로 × Node import / Node require / 번들러·브라우저 / TypeScript 해석 결과
  • 해석기: import 경로와 환경, 추가 조건(development 등)으로 Node.js PACKAGE_EXPORTS_RESOLVE 규칙 계산 (패턴, 가장 긴 접두사, null 차단, 배열 대체)
  • 오류: ./ 로 시작하지 않는 대상, 경로 키와 조건 혼용, 폴더 매핑(./lib/), 키 하나에 * 여러 개, require→.mjs
  • 경고·권고: types 가 뒤에 있음, default 가 마지막이 아님, type 과 확장자 불일치, ./* 전체 공개, files 에 빠진 대상
  • 듀얼 패키지 하자드와 ESM/CJS 가 types 를 공유하는 문제 안내

💡 Tips

  • 조건은 위에서부터 처음 일치하는 것이 쓰입니다. 'types' 는 항상 맨 앞, 'default' 는 항상 맨 뒤에 두세요.
  • TypeScript 사용자를 위해 import 와 require 안에 각각 .d.mts/.d.cts 를 중첩하는 것이 가장 안전합니다.
  • exports 를 추가하면 지정하지 않은 deep import 가 모두 막힙니다. 기존 사용자를 위해 필요한 경로를 남겼는지 확인하세요.

자주 묻는 질문

파일이 실제로 있는지도 확인하나요?

package.json 만 보므로 파일 존재는 확인하지 못합니다. files 필드와 비교해 배포에서 빠질 수 있는 대상만 알려 줍니다.

imports(#내부) 필드도 해석하나요?

키가 # 로 시작하는지만 점검하고 해석은 하지 않습니다. exports 해석에 집중한 도구입니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
