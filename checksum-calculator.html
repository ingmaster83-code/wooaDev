CRC · 체크섬 계산기 — CRC-16/32/64 외 21종

통신 프로토콜과 파일 포맷에서 쓰는 CRC-8, CRC-16(Modbus, XMODEM, CCITT), CRC-32, CRC-32C, CRC-64, Adler-32, Fletcher를 계산하고 표준 검증값과 비교합니다.

사용 예시

✅ 1개 알고리즘이 입력한 값과 일치합니다 (초록색 행)

입력 — 데이터

123456789

입력 — 비교할 값 (선택, 16진수)

CBF43926

이 도구로 할 수 있는 일

PLC·센서·시리얼 통신, ZIP·PNG·이더넷 같은 포맷은 저마다 다른 CRC 변형을 씁니다. 다항식·초기값·반사 설정이 달라 결과가 달라지므로 이름으로 골라 한꺼번에 비교하세요.

  • CRC-8(MAXIM, CDMA2000), CRC-16(ARC, MODBUS, USB, CCITT-FALSE, XMODEM, KERMIT, X-25, GENIBUS, DNP)
  • CRC-32(zlib/PNG), CRC-32C(iSCSI), BZIP2, MPEG-2, JAMCRC, XFER, CRC-64/XZ, Adler-32, Fletcher-16
  • 입력은 텍스트(UTF-8) 또는 16진수 바이트열, 각 알고리즘의 표준 검증값을 함께 표시해 구현 확인
  • 비교할 값을 넣으면 일치하는 알고리즘 행을 강조
  • Modbus RTU처럼 CRC-16을 낮은 바이트 먼저 전송하는 경우를 위한 바이트 순서 뒤집기

💡 Tips

  • Modbus RTU의 CRC-16은 계산값의 낮은 바이트를 먼저 보냅니다. 바이트 순서 뒤집기 옵션으로 전송 순서를 확인하세요.
  • 같은 이름의 CRC라도 구현에 따라 초기값이 달라질 수 있습니다. 표준 검증값(123456789)이 맞는지 먼저 확인하세요.
  • 16진수 입력은 공백·0x 접두사가 있어도 인식합니다.

자주 묻는 질문

왜 CRC-16이 이렇게 많은가요?

다항식, 초기값, 입출력 비트 반사, 최종 XOR 조합이 표준마다 달라서입니다. 장비 문서에 적힌 이름(예: CRC-16/MODBUS)과 같은 행을 보면 됩니다.

CRC로 보안을 지킬 수 있나요?

아니요. CRC는 우연한 전송 오류를 찾는 용도이며 의도적인 변조는 쉽게 맞출 수 있습니다. 보안에는 SHA-256 같은 해시와 HMAC을 쓰세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
