MongoDB ObjectId 분석 · 생성 · 날짜 범위 쿼리

ObjectId 24자리를 생성 시각, 프로세스 난수, 카운터로 풀어 보고, 새 ObjectId 를 만들고, 날짜 범위에 해당하는 _id 경계값으로 바로 쓸 수 있는 쿼리를 만듭니다.

사용 예시

✅ 3개 분석

입력 — ObjectId (한 줄에 하나)

507f1f77bcf86cd799439011
65f1a2b3c4d5e6f708192a3b
ObjectId("6512bd43d9caa6e02c990b0a")

입력 — 시작 일시 (ISO 8601)

2026-10-01T00:00:00Z

입력 — 끝 일시 (ISO 8601)

2026-10-02T00:00:00Z

결과 — 결과

ObjectId | 상태 | 생성 시각 | 난수(5바이트) | 카운터(3바이트)
507f1f77bcf86cd799439011 | ✅ | 2012-10-17T21:13:27Z  (2012-10-18 06:13:27 Asia/Seoul) | bcf86cd799 (random) | 4427793 (0x439011)
65f1a2b3c4d5e6f708192a3b | ✅ | 2024-03-13T12:57:23Z  (2024-03-13 21:57:23 Asia/Seoul) | c4d5e6f708 (random) | 1649211 (0x192a3b)
6512bd43d9caa6e02c990b0a | ✅ | 2023-09-26T11:15:15Z  (2023-09-26 20:15:15 Asia/Seoul) | d9caa6e02c (random) | 10029834 (0x990b0a)

결과 — 쿼리 / 목록

507f1f77bcf86cd799439011
6512bd43d9caa6e02c990b0a
65f1a2b3c4d5e6f708192a3b

이 도구로 할 수 있는 일

MongoDB 의 기본 키 ObjectId 는 앞 4바이트가 생성 시각이라 별도 createdAt 필드 없이 시간 범위 조회가 가능합니다.

  • 분석: 12바이트를 [타임스탬프 4][난수 5][카운터 3]으로 나눠 표시, UTC 와 선택한 시간대의 시각
  • ObjectId("…"), {"$oid": "…"} 형태 입력도 인식, 여러 줄을 정렬해 생성 순서 확인
  • 생성: 실제 드라이버처럼 프로세스별 난수와 증가하는 카운터로 N개 생성
  • 날짜 범위 → 경계 ObjectId: 시작·끝 시각을 넣으면 find({_id:{$gte,$lt}}) 쿼리와 JSON 쿼리 생성
  • 비정상 시각(2009년 이전·2040년 이후)은 ObjectId 가 아닌 임의 값일 수 있다고 경고

💡 Tips

  • _id 범위 쿼리는 기본 _id 인덱스를 쓰므로 createdAt 인덱스 없이도 빠릅니다.
  • ObjectId 의 시각은 초 단위입니다. 같은 초 안의 순서는 카운터가 결정합니다.
  • ObjectId 로 생성 시각이 공개되므로 외부에 노출되는 ID 로 쓸 때는 정보 노출을 고려하세요.

자주 묻는 질문

ObjectId 는 UUID 와 어떻게 다른가요?

12바이트(24자리 16진수)로 더 짧고, 앞부분이 시각이라 대략 생성 순서대로 정렬됩니다. UUID v4 는 완전 무작위라 정렬 순서가 없습니다.

ObjectId 가 중복될 수 있나요?

같은 프로세스는 카운터로, 다른 프로세스는 난수로 구분되어 현실적으로 충돌하지 않습니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
