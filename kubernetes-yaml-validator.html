Kubernetes YAML 검증기

여러 문서(---)의 매니페스트를 붙여 넣으면 제거된 apiVersion, Deployment selector 와 파드 레이블 불일치, request/limit 오류, Service·Ingress 가 가리키는 포트와 이름, Secret·ConfigMap 키 참조, 보안 설정을 줄 번호와 함께 검사합니다.

사용 예시

⛔ 오류 3건 · 경고 2건 — 리소스 3개

입력 — 쿠버네티스 매니페스트 (YAML, --- 로 여러 개)

apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
  labels:
    app: web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: webapp
    spec:
      containers:
        - name: web
          image: nginx
          ports:
            - containerPort: 80
              name: http
          env:
            - name: DB_PASS
              valueFrom:
                secretKeyRef:
                  name: db-secret
                  key: password
          resources:
            limits:
              memory: 128Mi
            requests:
              memory: 256Mi
---
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  selector:
    app: web
  ports:
    - port: 80
      targetPort: https
---
apiVersion: extensions/v1beta1
kind: Ingress
metadata:
  name: web
spec:
  rules:
    - host: example.com
      http:
…

결과 — 리소스 목록

종류 | 이름 | 네임스페이스 | apiVersion | 줄
Deployment | web | default | apps/v1 | 1
Service | web | default | v1 | 35
Ingress | web | default | extensions/v1beta1 | 46

결과 — 점검 결과

⛔ 줄 10: selector.matchLabels 가 파드 템플릿 레이블과 맞지 않습니다 (app=web ↔ webapp). 배포가 거부됩니다
ℹ️ 줄 18: 컨테이너 "web" 에 cpu/memory requests 를 모두 지정하세요
ℹ️ 줄 18: 컨테이너 "web" 에 readiness/liveness 프로브가 없습니다
ℹ️ 줄 18: 컨테이너 "web" 에 securityContext(runAsNonRoot, allowPrivilegeEscalation: false, readOnlyRootFilesystem)를 지정하는 것이 좋습니다
⚠️ 줄 19: 이미지 "nginx" 에 태그가 없어 latest 가 쓰입니다 (imagePullPolicy 도 Always 가 됨). 버전을 고정하세요
ℹ️ 줄 24: Secret "db-secret" 이 이 파일에 없습니다 (클러스터에 따로 있어야 함)
⛔ 줄 29: memory limit(128Mi)이 request(256Mi)보다 작습니다. 파드가 생성되지 않습니다
⚠️ 줄 40: Service selector {"app":"web"} 와 일치하는 파드 템플릿이 이 파일에 없습니다
⛔ 줄 46: extensions/v1beta1 는 쿠버네티스 1.22 에서 제거되었습니다. networking.k8s.io/v1 로 바꾸세요
ℹ️ 줄 50: ingressClassName 이 없어 기본 IngressClass 에 의존합니다

이 도구로 할 수 있는 일

kubectl apply 에서 거부되거나 배포 후에야 알게 되는 오류를 미리 찾습니다. 매니페스트는 서버로 전송되지 않습니다.

  • 공통: apiVersion·kind 일치, 제거된 API(extensions/v1beta1, batch/v1beta1, autoscaling/v2beta2 …), 이름 DNS 규칙, 중복 리소스, 레이블 값 규칙
  • 워크로드: selector.matchLabels ↔ 템플릿 레이블, StatefulSet serviceName, CronJob 스케줄, 컨테이너 이름·이미지(latest), 포트·프로브 포트 이름, env value/valueFrom, volumeMounts ↔ volumes
  • 리소스: cpu/memory 수량 형식, limit < request 오류, requests 누락(권고)
  • 참조: Service selector ↔ 파드, targetPort 이름·번호, Ingress v1 의 pathType·backend.service 형식과 대상 Service 포트, Secret/ConfigMap 키 존재, HPA 대상
  • 보안(권고 끌 수 있음): privileged, hostNetwork/hostPID, hostPath, 위험한 capabilities, runAsNonRoot, 평문 시크릿 env, Secret 은 암호화가 아님 안내

💡 Tips

  • Deployment 의 selector 는 생성 후 바꿀 수 없습니다. 레이블을 처음부터 템플릿과 일치시키세요.
  • limit 이 request 보다 작으면 파드가 만들어지지 않습니다. 단위(m, Mi, Gi)를 확인하세요.
  • 이 도구는 파일 안의 리소스끼리의 참조만 확인합니다. 클러스터에 이미 있는 Secret 이나 Service 는 정보로만 알려 줍니다.

자주 묻는 질문

kubectl --dry-run=server 와 같은가요?

서버의 전체 스키마 검증은 아닙니다. 자주 발생하는 구조·참조·운영 문제를 설치 없이 확인하며, 최종 확인은 dry-run 으로 하세요.

CRD 는 어떻게 되나요?

내장 리소스가 아닌 kind 는 기본 필드(apiVersion, kind, metadata.name)만 확인하고 안내를 표시합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
