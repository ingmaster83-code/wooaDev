CBOR 디코더 · 인코더 (RFC 8949)

16진수·Base64·파일로 받은 CBOR 바이트를 주 타입, 바이트 오프셋, 태그와 함께 트리로 풀고 JSON 과 RFC 8949 진단 표기도 만들어 줍니다. JSON 을 CBOR 로 인코딩할 수도 있습니다.

사용 예시

✅ 해석 완료 — 46바이트, 요소 13개

입력 — CBOR (16진수/Base64) 또는 인코딩할 JSON

a4 64 6e 61 6d 65 65 57 6f 6f 61 21 63 61 67 65 18 1e 66 73 63 6f 72 65 73 83 01 fb 40 09 1e b8 51 eb 85 1f c1 1a 65 4f 1f 80 62 6f 6b f5

결과 — 타입 트리 (바이트 오프셋)

오프셋 | 바이트 | 경로 | 타입 | 값
0 | 0xa4 | $ | map | map(4)
6 | 0x65 |   $.name | text string | "Wooa!"
16 | 0x18 |   $.age | unsigned int | 30
25 | 0x83 |   $.scores | array | array(3)
26 | 0x01 |     $.scores[0] | unsigned int | 1
27 | 0xfb |     $.scores[1] | float64 | 3.14
36 | 0xc1 |     $.scores[2] | tag | tag(1) — epoch date/time
37 | 0x1a |       $.scores[2] | unsigned int | 1699684224
45 | 0xf5 |   $.ok | simple | true

결과 — JSON / 인코딩 결과

{
  "name": "Wooa!",
  "age": 30,
  "scores": [
    1,

이 도구로 할 수 있는 일

IoT·WebAuthn·COSE 처럼 CBOR 를 쓰는 데이터를 사람이 읽을 수 있게 풀어 줍니다. 데이터는 브라우저 밖으로 나가지 않습니다.

  • 주 타입 0~7(정수, 바이트·텍스트 문자열, 배열, 맵, 태그, 단순값·실수) 전체
  • 반정밀도(float16)·단정밀도·배정밀도 실수와 Infinity·NaN, 64비트 정수
  • 태그: 날짜 문자열, 에포크 시간(ISO 로 함께 표시), bignum 2·3, 자기 설명 55799 등 이름 표시
  • 부정 길이(indefinite) 문자열·배열·맵과 break 처리, 결정적 인코딩 위반 안내
  • 출력: JSON, 진단 표기(예: {"a": 1, "b": [2, 3]}), 바이트 오프셋 표 / 인코딩: JSON → CBOR

💡 Tips

  • WebAuthn 의 attestationObject, COSE 키는 CBOR 맵입니다. 정수 키(1, 3, -1 …)가 많아 JSON 에서는 문자열이 됩니다.
  • 태그 24(내장 CBOR)는 바이트 문자열 안에 또 다른 CBOR 가 들어 있다는 뜻입니다. 안쪽 바이트를 따로 복사해 다시 해석하세요.
  • 결정적 인코딩이 필요한 서명용 데이터는 부정 길이를 쓰지 않고 키를 정렬해야 합니다.

자주 묻는 질문

CBOR 과 MessagePack 은 어떻게 다른가요?

둘 다 JSON 비슷한 바이너리 형식이지만 CBOR 는 IETF 표준(RFC 8949)이며 태그, 반정밀도 실수, 부정 길이를 지원합니다.

진단 표기란 무엇인가요?

CBOR 데이터를 사람이 읽도록 적는 규격 표기입니다. h'0102' 는 바이트 문자열, 1(1699684224) 는 태그 1 이 붙은 값입니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
