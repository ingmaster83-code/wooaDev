패키지 버전 제약 해석기 — Composer · Cargo · NuGet · Go

^1.2.3 || ~2.0 (Composer), ^0.2.3 (Cargo), [1.0,2.0) (NuGet), v1.2.3 모듈 버전 같은 제약을 사람이 읽는 범위로 풀어 주고, 후보 버전 목록 중 어떤 것이 일치하는지 판정합니다.

사용 예시

이 도구로 할 수 있는 일

생태계마다 다른 버전 표기를 한 곳에서 해석합니다. 입력은 브라우저에서만 처리됩니다.

  • Composer: ^, ~, *, 하이픈 범위, >=1.0 <2.0, ||, 쉼표/공백 AND, 안정성(-dev, @beta)
  • Cargo: ^ (기본), ~, *, =, 비교 연산자, 쉼표 AND, 0.x 의 특수한 caret 동작
  • NuGet: 1.0 (최소 이상), [1.0], [1.0,2.0), (,1.0], 프리릴리스 라벨
  • Go: 모듈 경로 버전 접미사(/v2), v0 불안정, pseudo-version, +incompatible
  • 범위 해석 표와 후보 버전별 일치 판정

💡 Tips

  • Cargo 에서 ^0.2.3 은 <0.3.0 까지만 허용합니다. 0.x 는 마이너가 호환 경계입니다.
  • NuGet 의 1.0 은 '정확히 1.0'이 아니라 '1.0 이상'이라는 점을 주의하세요.
  • Go 는 v2 이상이면 모듈 경로가 /v2 로 끝나야 합니다.

자주 묻는 질문

Composer 의 ~1.2 와 ^1.2 는 어떻게 다른가요?

~1.2 는 >=1.2,<2.0, ~1.2.3 은 >=1.2.3,<1.3.0 이고 ^1.2.3 은 >=1.2.3,<2.0.0 입니다.

프리릴리스도 일치하나요?

생태계 규칙을 따릅니다. 명시하지 않은 프리릴리스는 보통 제외되고 결과 표에 사유가 표시됩니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
