문자열 이스케이프 · 언이스케이프 변환기

줄바꿈과 따옴표가 섞인 문자열을 JSON, JavaScript, Python, Java, C, SQL, 정규식 규칙에 맞게 이스케이프하거나 되돌립니다.

사용 예시

✅ 이스케이프 완료

입력 — 입력

He said "안녕"
	Path: C:\Users\wooa
😀

결과 — 결과

"He said \"안녕\"\n\tPath: C:\\Users\\wooa\n😀"

이 도구로 할 수 있는 일

코드에 긴 텍스트나 JSON을 문자열로 넣을 때 따옴표, 역슬래시, 줄바꿈을 일일이 처리하기는 번거롭고 실수하기 쉽습니다.

  • 이스케이프: 실제 문자열 → 코드에 붙여 넣을 수 있는 리터럴 (따옴표 종류, 앞뒤 따옴표 포함 여부 선택)
  • 언이스케이프: "a\nb\u0041" 같은 리터럴 → 실제 문자열 (\xHH, \u{1F600}, 8진수, 줄 이음 처리)
  • 대상: JSON, JavaScript(작은/큰따옴표/템플릿), Python, Java·C#, C·C++, SQL(작은따옴표 두 번), MySQL, 정규식 리터럴
  • "ASCII 밖 문자도 \uXXXX" 옵션으로 한글·이모지(서로게이트 쌍)를 이스케이프

JSON 규격에 맞는지는 JSON 유효성 검사기로 확인하세요.

💡 Tips

  • 여러 줄 JSON을 코드에 넣을 때는 JSON 대상으로 이스케이프한 뒤 앞뒤 따옴표를 포함해 복사하세요.
  • SQL 값 삽입은 이스케이프 대신 파라미터 바인딩을 사용하는 것이 안전합니다. 이 도구는 문자열 리터럴 작성용입니다.
  • 알 수 없는 이스케이프(\q 등)는 문자 그대로 두고 개수를 알려 줍니다.

자주 묻는 질문

JSON.stringify와 같은 결과인가요?

JSON 대상은 JSON.stringify 규칙(\n, \t, \", \\, 제어 문자 \u00XX)을 따릅니다. 나머지 언어는 각 언어의 리터럴 규칙을 따라 약간 다를 수 있습니다.

SQL 이스케이프로 SQL 인젝션을 막을 수 있나요?

권장하지 않습니다. 인젝션 방지는 항상 준비된 쿼리(파라미터 바인딩)로 하세요. 이 도구는 쿼리를 손으로 작성하거나 로그에 값을 표기할 때 쓰는 보조 용도입니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
