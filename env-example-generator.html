.env.example 생성기 — 비밀 값을 지운 예시 파일

실제 .env에서 비밀 값만 안전하게 비우고, 포트·모드 같은 일반 설정은 남겨 저장소에 올릴 .env.example을 만들어 줍니다.

사용 예시

✅ 변수 7개 — 값 유지 4 · 비움/대체 3. 커밋 전에 한 번 더 확인하세요.

입력 — .env 입력

# Server
NODE_ENV=production
PORT=8080

# Database
DATABASE_URL=postgres://app:s3cret@db.internal:5432/app
REDIS_URL=redis://localhost:6379

# Secrets
JWT_SECRET=9f8d7c6b5a
STRIPE_API_KEY=sk_live_abcdef
FEATURE_FLAG=true

결과 — .env.example

# Server
NODE_ENV=production
PORT=8080

# Database
DATABASE_URL=
REDIS_URL=redis://localhost:6379

# Secrets
JWT_SECRET=
STRIPE_API_KEY=
FEATURE_FLAG=true

결과 — 처리 내역

변수 | 처리 | 예시 파일의 값
NODE_ENV | 값 유지 | production
PORT | 값 유지 | 8080
DATABASE_URL | 비움 | 
REDIS_URL | 값 유지 | redis://localhost:6379
JWT_SECRET | 비움 | 
STRIPE_API_KEY | 비움 | 
FEATURE_FLAG | 값 유지 | true

이 도구로 할 수 있는 일

프로젝트에 .env.example을 두면 새 팀원이 어떤 환경 변수가 필요한지 바로 알 수 있습니다. 하지만 실제 .env를 복사해 값을 손으로 지우다가 키 하나를 남기는 사고가 자주 생깁니다.

  • 이름에 SECRET, PASSWORD, TOKEN, KEY, DSN 등이 들어간 변수는 값을 항상 비움
  • user:pass@host 형태의 접속 문자열도 비움
  • NODE_ENV=production, PORT=8080, DEBUG=true처럼 민감하지 않은 값은 그대로 유지(선택)
  • 비운 값은 빈칸, your_key_here, <KEY>, xxx 중 원하는 형식으로 채움
  • 주석과 빈 줄을 보존하고, 처리한 변수별 내역을 표로 표시

자동 판별은 보조 수단입니다. 커밋 전에 결과를 한 번 더 훑어보세요.

💡 Tips

  • 이름만으로 판별할 수 없는 값(예: 사설 URL)은 "민감하지 않은 기본값 유지"를 끄면 전부 비워집니다.
  • # secret 표시를 켜면 비밀 키 옆에 주석이 붙어 팀원이 구분하기 쉽습니다.
  • .env 자체는 .gitignore에 추가하는 것을 잊지 마세요 (.gitignore 생성기 이용).

자주 묻는 질문

민감한 값이 남을 수도 있나요?

키 이름과 값 모양으로 판별하기 때문에 이름만으로는 비밀인지 알 수 없는 값이 남을 수 있습니다. 확실히 하려면 "민감하지 않은 기본값 유지"를 끄고 모두 비운 뒤 필요한 값만 직접 채우세요.

입력한 .env가 서버로 전송되나요?

아니요. 모든 처리는 브라우저에서만 이루어지며 입력한 내용은 저장되거나 전송되지 않습니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
