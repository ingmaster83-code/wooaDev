HMAC 생성기 · 검증기 — 웹훅 서명 확인

비밀 키와 메시지로 HMAC을 계산하고 받은 서명과 비교합니다. GitHub·Stripe·Slack 같은 웹훅 서명을 확인하거나 API 요청 서명을 만들 때 쓰세요.

사용 예시

✅ HMAC-SHA256 계산 완료 (256비트)

입력 — 메시지

GET
/api/v1/orders?id=100
1760577000

입력 — 비밀 키

my-secret-key

결과 — HMAC 결과

형식 | 값
hex | 992e0355fd3aadb66a5885a757a90d1dba0104871215eb40cc5150d42e621a32
HEX (대문자) | 992E0355FD3AADB66A5885A757A90D1DBA0104871215EB40CC5150D42E621A32
Base64 | mS4DVf06rbZqWIWnV6kNHboBBIcSFetAzFFQ1C5iGjI=
Base64URL | mS4DVf06rbZqWIWnV6kNHboBBIcSFetAzFFQ1C5iGjI

결과 — HMAC (hex)

992e0355fd3aadb66a5885a757a90d1dba0104871215eb40cc5150d42e621a32

이 도구로 할 수 있는 일

HMAC은 비밀 키를 아는 쪽만 만들 수 있는 서명으로, 웹훅 검증과 API 인증에 널리 쓰입니다. 입력과 결과 모두 브라우저에서만 계산됩니다.

  • 알고리즘: HMAC-SHA256(기본), SHA-1, SHA-384, SHA-512
  • 키·메시지를 텍스트, 16진수, Base64 중 선택해 입력
  • 결과를 16진수, Base64, Base64URL로 동시에 표시
  • 받은 서명(sha256=… 접두사 포함 가능)을 붙여 넣으면 일치 여부를 확인
  • 긴 키는 해시로 먼저 줄이는 HMAC 규칙을 그대로 따름

💡 Tips

  • 웹훅 서명은 파싱한 JSON이 아니라 '받은 원문 그대로의 바이트'로 계산해야 맞습니다. 줄바꿈·공백도 포함됩니다.
  • 서버에서 서명을 비교할 때는 일반 == 대신 상수 시간 비교(timingSafeEqual 등)를 쓰세요.
  • 키가 16진수 문자열이라면 키 형식을 hex 로 바꿔야 합니다. 텍스트로 넣으면 전혀 다른 값이 됩니다.

자주 묻는 질문

HMAC과 그냥 해시는 무엇이 다른가요?

해시는 누구나 계산할 수 있지만 HMAC은 비밀 키가 있어야만 계산할 수 있어, 메시지가 바뀌지 않았고 키를 가진 쪽이 보냈음을 확인할 수 있습니다.

SHA-1 HMAC도 안전한가요?

HMAC은 해시 충돌에 덜 민감해 HMAC-SHA1도 당장 깨진 것은 아니지만 새 시스템에는 SHA-256 이상을 권장합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
