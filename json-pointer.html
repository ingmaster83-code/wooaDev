JSON 포인터(RFC 6901) 도구

/users/0/name 같은 JSON Pointer로 정확한 값을 찾고, 모든 값의 포인터와 URI 조각 표기를 만들어 줍니다.

사용 예시

✅ 값을 찾았습니다 (string)

입력 — JSON 데이터

{
  "users": [
    { "name": "Kim", "tags": ["a/b", "c~d"] },
    { "name": "Lee" }
  ],
  "a/b": { "m~n": 100 },
  "my key": true
}

입력 — JSON Pointer

/users/0/tags/0

결과 — 포인터 정보

정규화된 포인터: /users/0/tags/0
URI 조각 형식: #/users/0/tags/0
JSONPath 표기: $['users'][0]['tags'][0]

결과 — 값

"a/b"

이 도구로 할 수 있는 일

JSON Pointer는 JSON 안의 한 값을 가리키는 표준 경로 표기(RFC 6901)로, JSON Schema의 $ref와 JSON Patch(RFC 6902)에서 사용됩니다.

  • /users/0/name 형태 입력 → 값, 정규화된 포인터, URI 조각(#/users/0/name), JSONPath($['users'][0]['name']) 표시
  • 키에 포함된 / 와 ~ 는 ~1, ~0 으로 이스케이프하는 규칙을 자동 적용
  • #/my%20key 처럼 URI 조각 형식의 입력도 지원
  • "모든 포인터 목록" 모드는 문서의 모든 노드에 대한 포인터와 타입·값을 표로 제공

여러 값을 조건으로 찾아야 한다면 JSONPath 테스터가 더 적합합니다.

💡 Tips

  • $ref 값(예: #/definitions/User)을 입력하면 그 경로가 가리키는 스키마 조각을 바로 확인할 수 있습니다.
  • 키 이름에 / 가 있으면 ~1 로 써야 합니다. 이 도구의 정규화 결과를 복사해서 쓰세요.
  • 배열 인덱스는 0부터 시작하며 "-"(배열 끝 다음)는 읽기에 쓸 수 없습니다.

자주 묻는 질문

JSON Pointer와 JSONPath는 무엇이 다른가요?

JSON Pointer는 정확히 하나의 값을 가리키는 단순한 경로이고, JSONPath는 와일드카드·필터로 여러 값을 조회하는 쿼리 언어입니다.

빈 포인터 "" 는 무엇을 가리키나요?

문서 전체(루트)를 가리킵니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
