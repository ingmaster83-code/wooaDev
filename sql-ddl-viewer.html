SQL DDL 뷰어 · ERD 생성기

CREATE TABLE, CREATE INDEX, ALTER TABLE 문을 붙여 넣으면 테이블·컬럼·키를 표로 정리하고 외래 키 관계를 ERD 그림과 Mermaid erDiagram 코드로 만들어 줍니다. 없는 테이블 참조, 타입 불일치, 인덱스 없는 외래 키 같은 설계 문제도 줄 번호와 함께 알려 줍니다.

사용 예시

⛔ 오류 1건 · 경고 1건 — 테이블 4개

입력 — SQL DDL (CREATE TABLE · CREATE INDEX · ALTER TABLE)

CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  email VARCHAR(255) NOT NULL UNIQUE,
  name VARCHAR(100),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE posts (
  id BIGINT NOT NULL,
  user_id INT NOT NULL,
  title VARCHAR(200) NOT NULL,
  body TEXT,
  category_id BIGINT,
  PRIMARY KEY (id),
  CONSTRAINT fk_posts_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
);

CREATE TABLE tags (id INT PRIMARY KEY, label TEXT NOT NULL);
CREATE TABLE post_tags (post_id BIGINT NOT NULL REFERENCES posts(id), tag_id INT NOT NULL REFERENCES tags(id), PRIMARY KEY (post_id, tag_id));
CREATE INDEX idx_posts_title ON posts (title);
ALTER TABLE posts ADD CONSTRAINT fk_posts_cat FOREIGN KEY (category_id) REFERENCES categories(id);

이 도구로 할 수 있는 일

DDL 스크립트만으로 데이터베이스 구조를 한눈에 봅니다. SQL 은 서버로 전송되지 않습니다.

  • 해석: CREATE TABLE(인라인·테이블 제약 모두), CREATE [UNIQUE] INDEX, ALTER TABLE ADD FOREIGN KEY/PRIMARY KEY/UNIQUE/COLUMN
  • 방언: MySQL 백틱, PostgreSQL 큰따옴표, SQL Server 대괄호, 주석과 문자열 안의 세미콜론 처리
  • 출력: ERD(SVG), 테이블·컬럼 표(타입·NULL·키·기본값·주석), 관계 표(ON DELETE/UPDATE, 필수/선택), Mermaid erDiagram
  • 점검: 없는 테이블·컬럼 참조, FK 타입 불일치, PK 없음, 인덱스 없는 FK, NOT NULL 컬럼의 ON DELETE SET NULL
  • 권고(끌 수 있음)

💡 Tips

  • 외래 키 컬럼에는 인덱스를 만들어 두면 조인과 부모 행 삭제가 훨씬 빨라집니다. PostgreSQL 은 자동으로 만들지 않습니다.
  • 참조하는 컬럼과 참조되는 컬럼의 타입(특히 정수 크기와 부호)을 같게 맞추세요.
  • Mermaid 코드를 마크다운 문서나 GitHub README 에 붙이면 ERD 가 그려집니다.

자주 묻는 질문

모든 SQL 방언을 지원하나요?

MySQL·PostgreSQL·SQLite·SQL Server 의 일반적인 CREATE/ALTER 문을 해석합니다. 뷰·트리거·함수 같은 문은 건너뛰며, 방언 고유 문법은 일부 해석하지 못할 수 있습니다.

실제 DB 에 연결하나요?

아니요. 붙여 넣은 DDL 텍스트만 해석하며 데이터베이스에 접속하지 않습니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
