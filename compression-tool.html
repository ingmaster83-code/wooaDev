gzip · deflate 압축 · 해제 · 헤더 분석

텍스트나 파일을 gzip, deflate(zlib), deflate-raw 로 압축하거나 Base64·16진수 압축 데이터를 풀어 줍니다. 형식별 크기를 한 번에 비교하고, gzip 의 수정 시각·OS·원본 파일 이름·CRC-32 와 zlib 의 윈도 크기·Adler-32 를 트레일러와 대조해 손상 여부도 확인합니다.

이 도구로 할 수 있는 일

서버 없이 브라우저의 CompressionStream 으로 압축과 해제를 처리합니다. 데이터는 전송되지 않습니다.

  • 작업: 압축, 압축 해제, 헤더 분석, 형식별 크기 비교
  • 형식: gzip, deflate(zlib 래퍼), deflate-raw — 해제 시 매직 바이트로 형식을 자동 보정
  • gzip 헤더: 수정 시각, OS, XFL, 원본 파일 이름·주석, CRC-32, 원본 크기(ISIZE)
  • zlib 헤더: 윈도 크기, 압축 수준 힌트, 사전 여부, Adler-32 — 해제 결과와 트레일러 대조
  • 입출력: 텍스트, Base64, 16진수, 파일 (결과가 텍스트가 아니면 Base64/16진수로 표시)

💡 Tips

  • HTTP Content-Encoding: gzip 응답 본문을 Base64 로 받았다면 '압축 해제'에 붙여 넣으세요.
  • 아주 짧은 데이터는 헤더(gzip 18 B, zlib 6 B) 때문에 오히려 커집니다. '크기 비교'로 확인하세요.
  • '헤더 분석'에서 무결성 불일치가 나오면 전송 중 손상되었거나 잘린 데이터입니다.

자주 묻는 질문

압축 수준을 고를 수 있나요?

브라우저의 CompressionStream 은 수준을 지정할 수 없어 기본값으로 압축합니다. 최대 압축이 필요하면 서버의 zlib 이나 7-Zip 을 사용하세요.

zip 이나 brotli 도 되나요?

gzip, deflate, deflate-raw 만 지원합니다. zip 아카이브와 brotli 는 형식이 달라 다루지 않습니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
