JSON 모의 데이터 생성기 — 스키마에 맞는 테스트 데이터

JSON Schema를 붙여 넣으면 타입, 범위, enum, format, pattern, 배열 길이 같은 제약을 지키는 가짜 JSON 데이터를 만들어 줍니다.

사용 예시

✅ 3개를 생성했습니다 (시드 1)

입력 — JSON Schema

{
  "type": "object",
  "required": ["id", "name", "email", "role"],
  "properties": {
    "id": { "type": "integer", "minimum": 1000, "maximum": 9999 },
    "name": { "type": "string", "minLength": 2 },
    "email": { "type": "string", "format": "email" },
    "role": { "enum": ["admin", "editor", "viewer"] },
    "code": { "type": "string", "pattern": "^[A-Z]{3}-[0-9]{4}$" },
    "score": { "type": "number", "minimum": 0, "maximum": 5, "multipleOf": 0.5 },
    "tags": { "type": "array", "items": { "type": "string" }, "minItems": 1, "maxItems": 3, "uniqueItems": true },
    "created": { "type": "string", "format": "date-time" }
  }
}

이 도구로 할 수 있는 일

프런트엔드 개발이나 API 테스트에서 백엔드가 준비되기 전에 그럴듯한 데이터가 필요할 때가 많습니다. 스키마가 있다면 그에 맞는 데이터를 바로 만들 수 있습니다.

  • 숫자: minimum/maximum, exclusive*, multipleOf를 지키는 정수·실수
  • 문자열: minLength/maxLength, format(email, uuid, date, date-time, uri, ipv4…), pattern(정규식에 맞는 문자열 생성)
  • enum, const, default/examples(옵션), 배열의 minItems/maxItems/uniqueItems와 tuple(prefixItems)
  • $ref(#/definitions, #/$defs), allOf 병합, oneOf/anyOf 선택
  • 선택 속성의 포함 여부, 생성 개수, 시드(같은 값이면 같은 결과)

생성된 데이터는 스키마 검증기에서 다시 검증해 볼 수 있습니다.

💡 Tips

  • 시드를 고정하면 테스트 픽스처를 재현 가능하게 만들 수 있습니다.
  • pattern은 문자 클래스·수량자·그룹·대안(|) 중심의 일반적인 정규식을 지원하며, lookahead 같은 고급 구문은 오류로 알려 줍니다.
  • name, city, title 같은 속성 이름이면 사람이 읽을 만한 값이 만들어집니다.

자주 묻는 질문

생성된 데이터가 항상 스키마를 통과하나요?

지원하는 키워드 범위에서는 통과하도록 만들어지며, 내부적으로도 여러 스키마·시드로 검증 도구와 교차 검증했습니다. 다만 매우 복잡한 조건(if/then/else, not 등)은 보장하지 않습니다.

실제 개인정보가 만들어지나요?

아니요. 이름은 임의의 예시 이름 목록에서, 이메일은 example.com 도메인으로만 만들어지는 가짜 데이터입니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
