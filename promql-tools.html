PromQL 검사 · 정리 · 설명기

PromQL 식을 붙여 넣으면 구문과 타입(인스턴트/레인지 벡터, 스칼라, 문자열)을 Prometheus 규칙으로 검사하고, 긴 식을 줄바꿈해 정리하며, 안쪽 식부터 단계별로 의미를 설명합니다. rate 의 범위, histogram_quantile 의 le 누락, 카운터와 게이지 혼동 같은 흔한 실수도 알려 줍니다.

사용 예시

⛔ 오류 1건 · 경고 1건 — 결과 타입 인스턴트 벡터

입력 — PromQL 식

histogram_quantile(0.95, sum by (job) (rate(http_request_duration_seconds_bucket{job=~"api.*", status!~"5.."}[5m]))) > 0.5
and on(job) sum by (job) (rate(http_requests_total[30s])) > 100

결과 — 정리된 PromQL

histogram_quantile(
  0.95,
  sum by (job) (
    rate(http_request_duration_seconds_bucket{job=~"api.*", status!~"5.."}[5m])
  )
)
>
0.5
and on (job)
sum by (job) (rate(http_requests_total[30s])) > 100

이 도구로 할 수 있는 일

Prometheus 에 보내기 전에 쿼리를 브라우저에서 검증하고 이해합니다. 쿼리는 서버로 전송되지 않으며 Prometheus 에 연결하지도 않습니다.

  • 파서: 선택자(매처 4종, offset, @), 범위·서브쿼리, 집계(by/without 앞뒤 위치), 이항 연산(bool, on/ignoring, group_left/right), 단항, 80여 개 함수, 기간(1h30m)
  • 타입 검사: 함수 인자 타입·개수, 집계 파라미터, 집합 연산과 스칼라, bool 사용처, 최종 결과가 레인지 벡터인 경우
  • 정리: 지정한 너비를 넘는 식만 함수·집계·연산자 단위로 줄바꿈
  • 설명: 안쪽 식부터 번호를 매겨 타입과 의미(초 단위 변환 포함)를 표로 정리, 구문 트리 출력
  • 점검: rate 범위가 너무 짧음, irate 긴 범위, histogram_quantile 의 le·rate·_bucket, 카운터/게이지, avg 의 avg, count()==0, 불필요한 정규식

💡 Tips

  • rate() 범위는 수집 주기(scrape_interval)의 최소 4배로 잡으세요. 30초 수집이면 2m 이상입니다.
  • 히스토그램 분위수는 histogram_quantile(0.95, sum by (le, job) (rate(x_bucket[5m]))) 처럼 by 에 le 를 반드시 포함해야 합니다.
  • 라벨 매처의 정규식은 자동으로 전체 일치입니다. ^ 와 $ 를 붙일 필요가 없습니다.

자주 묻는 질문

쿼리를 실제로 실행하나요?

아니요. 문법과 타입만 검사하고 설명합니다. 메트릭 이름이 실제로 존재하는지, 결과 값이 무엇인지는 알 수 없습니다.

Prometheus 3.x 의 새 기능도 되나요?

histogram_avg·mad_over_time·limitk 등 널리 쓰이는 최신 함수는 포함했지만 모든 실험 기능을 지원하지는 않습니다. 알 수 없는 함수는 오류로 표시됩니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
