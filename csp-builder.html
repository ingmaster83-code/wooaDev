CSP 생성기 · 분석기 — Content-Security-Policy

Content-Security-Policy 헤더를 프리셋으로 만들고, 이미 가진 정책의 약점(unsafe-inline, 와일드카드)을 찾아내며, 특정 스크립트·이미지 요청이 허용되는지 직접 테스트합니다.

사용 예시

🔍 점검할 항목 4개

입력 — 분석·테스트할 CSP

default-src 'self'; script-src 'self' https://cdn.example.com 'unsafe-inline'; img-src 'self' data: https:; object-src *; frame-ancestors 'self'

입력 — 테스트할 요청 (한 줄에 하나: 종류 URL)

script https://cdn.example.com/app.js
script https://evil.example.net/x.js
img https://images.example.org/a.png
style inline
connect https://api.example.com/v1

입력 — 페이지 출처 (self)

https://www.example.com

결과 — CSP

default-src 'self'; script-src 'self' https://cdn.example.com 'unsafe-inline'; img-src 'self' data: https:; object-src *; frame-ancestors 'self'

결과 — 지시어

지시어 | 출처 | 의미
default-src | 'self' | 다른 *-src가 없을 때의 기본 출처
script-src | 'self' https://cdn.example.com 'unsafe-inline' | 스크립트 출처
img-src | 'self' data: https: | 이미지 출처
object-src | * | <object>/<embed> 출처
frame-ancestors | 'self' | 이 페이지를 임베드할 수 있는 출처 (클릭재킹 방지)

이 도구로 할 수 있는 일

CSP는 XSS 피해를 줄이는 가장 강력한 헤더이지만 잘못 쓰면 사이트가 깨집니다. 만들고, 점검하고, 시험해 볼 수 있습니다.

  • 만들기: 엄격 / SPA + 외부 API / 일반 사이트 프리셋에 script·style·img·connect·frame 출처 추가, upgrade-insecure-requests, report-uri, Report-Only
  • 점검: unsafe-inline·unsafe-eval, 와일드카드(*), http: 출처, object-src·base-uri·form-action 누락
  • 테스트: 페이지 출처와 요청 목록(종류 URL)을 넣으면 어떤 요청이 차단되는지 지시어별로 판정
  • default-src 로의 폴백, 'self', 호스트·스킴 출처 매칭을 브라우저와 같은 방식으로 처리
  • 각 지시어의 의미를 표로 설명

💡 Tips

  • 처음에는 Content-Security-Policy-Report-Only 로 배포해 위반 보고만 모은 뒤 차단 모드로 바꾸세요.
  • 인라인 스크립트가 필요하다면 unsafe-inline 대신 nonce 또는 해시(sha256-…)를 쓰세요.
  • object-src 'none'; base-uri 'self'; 두 줄은 거의 모든 사이트에서 안전하게 추가할 수 있습니다.

자주 묻는 질문

CSP를 넣었더니 사이트가 깨져요.

인라인 스크립트·스타일, 외부 CDN, 구글 애널리틱스 등이 차단된 것입니다. Report-Only 로 위반 목록을 보고 필요한 출처만 허용하세요.

meta 태그로도 CSP를 쓸 수 있나요?

일부 지시어는 가능하지만 frame-ancestors, report-uri, sandbox 는 meta 에서 동작하지 않습니다. 가능하면 HTTP 헤더로 보내세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
