이메일 주소 검사 · 정리 · mailto 링크 생성

여러 이메일 주소를 한꺼번에 붙여 넣어 형식을 검사하고 중복을 제거하며 오타 도메인을 찾습니다. 받는 사람·참조·제목·본문이 들어간 mailto 링크와 HTML 태그도 만들어 줍니다.

사용 예시

🔍 8개 중 2개가 올바르지 않습니다

입력 — 이메일 주소 (줄바꿈·쉼표·세미콜론으로 구분, "이름 <주소>" 형식 가능)

Kim <kim@example.com>
lee@exmaple.com; park@gmial.com
kim@example.com
bad@@example.com
"john doe"@example.org
user+tag@xn--bcher-kva.example
someone@localhost

입력 — 받는 사람 (쉼표 구분)

team@example.com, boss@example.com

입력 — 참조 (cc)

manager@example.com

입력 — 제목

문의 드립니다 / Inquiry

입력 — 본문

안녕하세요,
견적을 요청드립니다.
감사합니다.

이 도구로 할 수 있는 일

고객 목록이나 메일링 주소를 정리하거나, 웹페이지에 문의 링크를 넣을 때 자주 필요한 두 가지를 한 도구에 담았습니다.

  • 검사: 로컬 파트 규칙(연속된 점, 64자, 인용 형식), 도메인 레이블(63자, 하이픈 위치), 숫자뿐인 TLD, IP 리터럴, 한글 도메인(IDN→punycode)
  • 구분자: 줄바꿈·쉼표·세미콜론, "이름" <주소> 형식의 표시 이름도 해석
  • 정리: 도메인 소문자 정규화, 중복 제거, +태그 주소의 기본 주소 안내, 오타 도메인 제안
  • mailto: 받는 사람·참조·숨은 참조·제목·본문을 RFC 6068에 맞게 인코딩 (공백 %20, 줄바꿈 %0D%0A)
  • 한글 제목·본문도 안전하게 인코딩하고 HTML a 태그까지 생성

💡 Tips

  • 형식이 올바르다고 실제로 존재하는 메일함은 아닙니다. 확인하려면 인증 메일을 보내 확인 링크를 누르게 하세요.
  • mailto 링크가 2,000자를 넘으면 일부 메일 앱에서 잘립니다. 긴 본문은 양식을 쓰는 편이 좋습니다.
  • 웹페이지에 주소를 그대로 적으면 스팸 수집 봇에 노출됩니다. 문의 양식이나 난독화를 고려하세요.

자주 묻는 질문

RFC 5322의 모든 형식을 허용하나요?

인용된 로컬 파트와 IP 리터럴까지 받아들이지만, 주석((…))이나 구식 문법은 실무에서 거의 쓰이지 않아 제외했습니다.

mailto 에서 bcc 는 안전한가요?

링크 자체에 숨은 참조 주소가 그대로 적혀 있어 페이지 소스를 보면 노출됩니다. 공개 페이지에는 쓰지 않는 것이 좋습니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
