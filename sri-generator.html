SRI 해시 생성기 — integrity 속성

CDN에서 불러오는 JS·CSS 파일에 붙이는 integrity(Subresource Integrity) 값을 sha256/384/512 로 만들고, 완성된 script·link 태그까지 만들어 줍니다.

사용 예시

✅ 22바이트의 SRI 해시를 만들었습니다

입력 — 파일 내용 붙여넣기

console.log("hello");

입력 — 리소스 URL (태그 예시용)

https://cdn.example.com/lib/app.min.js

결과 — integrity 값

sha384-M5mGpKxRozBpvsX+PXs0ssm1NdoBYDPN4gQsyCwq+RTqmuLt5T6LWQKklQd4sArc

결과 — HTML 태그 예시

<script src="https://cdn.example.com/lib/app.min.js" integrity="sha384-M5mGpKxRozBpvsX+PXs0ssm1NdoBYDPN4gQsyCwq+RTqmuLt5T6LWQKklQd4sArc" crossorigin="anonymous"></script>

<!-- SRI는 CORS를 허용하는 서버(Access-Control-Allow-Origin)에서 제공되는 리소스에만 동작합니다. 파일이 한 글자라도 바뀌면 브라우저가 로드를 차단합니다 -->

이 도구로 할 수 있는 일

CDN이 해킹되거나 파일이 바뀌어도 브라우저가 해시가 다른 스크립트를 실행하지 않도록 막는 기능이 SRI입니다. 파일 내용만 있으면 값을 만들 수 있습니다.

  • 파일을 선택하거나 내용을 붙여 넣으면 sha384(권장)/sha256/sha512 integrity 값 생성
  • 세 알고리즘을 공백으로 이어 붙인 값도 생성 가능
  • URL이 .css 면 link 태그, 아니면 script 태그를 crossorigin=anonymous 와 함께 생성
  • 이미 가진 integrity 값을 붙여 넣으면 현재 파일과 일치하는지 확인
  • 파일은 서버로 전송되지 않고 브라우저에서만 처리

💡 Tips

  • SRI는 해당 리소스가 CORS를 허용(Access-Control-Allow-Origin)해야 동작합니다. crossorigin=anonymous를 빼먹지 마세요.
  • CDN 주소에 버전을 고정(예: lib@3.7.1)하고 그 파일로 해시를 만들어야 값이 바뀌지 않습니다.
  • 파일이 한 글자라도 바뀌면 브라우저가 로드를 차단하므로 배포 파이프라인에서 해시도 함께 갱신하세요.

자주 묻는 질문

sha384를 권장하는 이유는요?

W3C 명세가 sha384를 권장하며 대부분의 브라우저가 sha256/384/512를 모두 지원합니다. 보안 강도와 길이의 균형이 좋은 값입니다.

SRI가 실패하면 어떻게 되나요?

브라우저가 해당 스크립트/스타일을 실행하지 않고 콘솔에 오류를 남깁니다. 사이트가 깨질 수 있으므로 폴백 로직을 준비하세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
