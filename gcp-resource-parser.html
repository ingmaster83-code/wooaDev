GCP 리소스 · GCS URL · 서비스 계정 분석기

projects/…/locations/… 형식의 리소스 이름, gs:// 와 storage.googleapis.com 주소, 서비스 계정 이메일과 키 JSON을 분석합니다. 비공개 키는 마스킹하고 노출 위험을 알려 줍니다.

사용 예시

🔍 위험 항목 1개

입력 — GCP 리소스 이름, GCS 주소, 서비스 계정 이메일 또는 키 JSON

projects/my-project/locations/asia-northeast3/services/api
gs://my-bucket/exports/2026/data.csv
https://storage.googleapis.com/my-bucket/exports/data.csv
build-bot@my-project.iam.gserviceaccount.com
{"type":"service_account","project_id":"my-project","private_key_id":"abc123","private_key":"-----BEGIN PRIVATE KEY-----\nMIIE...\n-----END PRIVATE KEY-----\n","client_email":"build-bot@my-project.iam.gserviceaccount.com","client_id":"1234567890"}

이 도구로 할 수 있는 일

Google Cloud는 API마다 projects/{id}/locations/{loc}/… 형태의 리소스 이름을 쓰고, 스토리지는 gs:// 와 HTTPS 주소를 번갈아 씁니다.

  • 리소스 이름: 컬렉션/ID 쌍으로 분해하고 짝이 맞지 않으면 알림
  • GCS: gs://, storage.googleapis.com/버킷/객체, 버킷.storage.googleapis.com 입력을 받아 모든 형식과 gsutil 명령으로 변환
  • 서비스 계정 이메일: 계정 ID와 프로젝트 ID 분리, 기본 Compute Engine 계정 경고
  • 키 JSON: type·project_id·client_email 확인, private_key 마스킹, 필수 필드 누락 점검
  • 버킷 이름 규칙(goog/google 포함 불가 등) 점검

💡 Tips

  • 서비스 계정 키(JSON)는 유출되면 영구 자격 증명입니다. 가능하면 Workload Identity나 연결된 서비스 계정으로 대체하세요.
  • 기본 Compute Engine 서비스 계정은 편집자 권한이 있는 경우가 많으므로 전용 계정을 만드세요.
  • storage.cloud.google.com 은 로그인 후 브라우저로 보는 주소이고, storage.googleapis.com 은 API/공개 접근 주소입니다.

자주 묻는 질문

키 JSON이 노출되면 어떻게 하나요?

즉시 해당 키를 삭제하고 새로 발급하세요(IAM → 서비스 계정 → 키). 저장소에 올렸다면 기록에서도 제거해야 합니다.

gs:// 주소를 HTTP로 접근하려면요?

https://storage.googleapis.com/버킷/객체 형태이며 객체가 공개이거나 서명된 URL/인증 헤더가 있어야 합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
