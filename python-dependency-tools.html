requirements.txt 분석 · 변환기

requirements.txt 줄을 패키지, extras, 지정자, 환경 마커, 옵션(-r, -e, --hash)으로 나누고 고정되지 않은 의존성을 점검한 뒤 pyproject.toml, Pipfile, Poetry, 정리된 requirements.txt 로 변환합니다.

사용 예시

✅ 패키지 10개 · 옵션 2개

입력 — requirements.txt (또는 pyproject 의 dependencies 줄)

# 웹
Django>=4.2,<5.0
requests[security]==2.31.0
PyYAML
numpy~=1.26
uvicorn[standard] ; python_version >= "3.9"
flask==2.3.*
-r dev-requirements.txt
-e .
git+https://github.com/org/private-lib.git@v1.2#egg=private_lib
some_pkg==1.0 --hash=sha256:abc123
requests>=2.0
Pillow

이 도구로 할 수 있는 일

오래된 requirements.txt 를 현대적인 pyproject 형식으로 옮기거나 문제를 찾을 때 씁니다. 파일은 서버로 가지 않습니다.

  • 분석: 패키지명(정규화: 대소문자·_ . → -), extras [security], 지정자, 환경 마커 ; python_version<"3.9"
  • 옵션 줄: -r 포함 파일, -e 편집 설치, --index-url, --hash 는 별도 표시
  • 점검: 버전 미지정, == 가 아닌 범위, 같은 패키지 중복, VCS/URL 의존성
  • 출력: pyproject.toml [project] dependencies, Pipfile [packages], Poetry 표기, 정렬된 requirements.txt
  • 잘못된 줄은 위치와 함께 알림

함께 쓰면 좋은 도구

🐍PEP 440 버전 테스터 🧰package.json 검사·정리기 ☕Maven ↔ Gradle 의존성 변환기 📦패키지 버전 제약 해석기

💡 Tips

  • 재현 가능한 빌드가 필요하면 pip-tools 나 uv 로 잠금 파일(==)을 만들고 직접 의존성은 pyproject 에 두세요.
  • 패키지명은 Django 와 django, python_dateutil 과 python-dateutil 이 같은 것으로 취급됩니다.
  • 환경 마커는 변환 결과에 그대로 유지됩니다.

자주 묻는 질문

Poetry 출력은 pip 지정자와 같나요?

Poetry 는 ^ 와 ~ 표기를 주로 쓰지만 이 도구는 의미를 바꾸지 않도록 원래 지정자를 그대로 옮깁니다.

-r other.txt 는 어떻게 처리하나요?

다른 파일을 읽을 수 없어 포함 선언으로만 표시합니다. 해당 파일 내용도 함께 붙여 넣으세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
