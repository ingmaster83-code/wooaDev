설정 파일 비교 도구 — 키 순서·주석 무시

TOML, INI, .properties, YAML, JSON, .env 두 파일을 데이터로 읽어 비교하므로 키 순서·공백·주석이 달라도 실제 변경만 보여 줍니다.

사용 예시

🔍 추가 1 · 삭제 1 · 변경 2

입력 — 원본 설정 (A)

[server]
host = "localhost"
port = 8080

[database]
url = "postgres://localhost/app"
pool = 5

[features]
beta = false

입력 — 비교할 설정 (B)

[database]
pool = 10
url = "postgres://localhost/app"

[server]
port = 8080
host = "0.0.0.0"

[logging]
level = "info"

결과 — 변경 사항 (키 순서는 무시)

구분 | 경로 | 이전(A) | 이후(B)
변경 | $.server.host | "localhost" | "0.0.0.0"
변경 | $.database.pool | 5 | 10
삭제 | $.features | {"beta":false} | 
추가 | $.logging |  | {"level":"info"}

이 도구로 할 수 있는 일

환경별 설정 파일(application-dev.properties vs application-prod.properties, config.ini 등)을 텍스트 diff로 비교하면 순서와 공백 때문에 노이즈가 많습니다. 이 도구는 파일을 형식에 맞게 읽어 값만 비교합니다.

  • 지원 형식: TOML, INI, Java .properties, YAML, JSON, .env
  • 섹션/키 순서, 공백, 주석 차이는 무시하고 추가·삭제·변경을 경로와 함께 표시
  • INI·.properties·.env는 "8080"과 8080을 같은 값으로 보는 타입 맞춤 비교 옵션 제공
  • 배열 순서 무시 옵션
  • 파싱 오류가 있으면 A/B 중 어느 쪽인지 알려 줌

💡 Tips

  • 개발/운영 설정 비교에는 .properties 형식과 "값 타입 맞춰 비교"를 켜 두면 노이즈가 줄어듭니다.
  • 형식이 서로 다른 두 파일은 먼저 설정 파일 변환기로 같은 형식으로 맞춘 뒤 비교하세요.
  • .env는 ENV 비교 도구가 누락 확인에 더 편리합니다.

자주 묻는 질문

서로 다른 형식(TOML과 YAML)을 직접 비교할 수 있나요?

한 번에 하나의 형식만 선택해 두 입력을 같은 형식으로 읽습니다. 다른 형식은 변환기로 같은 형식으로 맞춘 뒤 비교하세요.

주석만 다르면 같은 설정인가요?

네. 주석은 데이터가 아니므로 무시하고 값만 비교합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
