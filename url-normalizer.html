URL 정규화 · 경로 결합 도구

URL을 표준 형태로 정리합니다. 스킴·호스트 소문자, 기본 포트 제거, ../ 해석, 쿼리 정렬, utm 같은 추적 파라미터 제거, 상대 경로 해석을 한 번에 합니다.

사용 예시

✅ 5개 정규화, 중복 제거 시 5개

입력 — URL (한 줄에 하나)

HTTP://WWW.Example.COM:80/a/./b/../c/?b=2&a=1&utm_source=news&utm_medium=email#top
https://example.com/%7Euser/%e2%82%ac/index.html?x=%7e
//cdn.example.com/lib.js
../images/logo.png
https://한글.kr/경로/파일

입력 — 기준 URL (상대 경로를 풀 때)

https://example.com/docs/guide/intro.html

결과 — 정규화 결과

입력 | 정규화 | 변경 내용
HTTP://WWW.Example.COM:80/a/./b/../c/?b=2&a=1&utm_source=news&utm_medium=email#top | http://www.example.com/a/c/?a=1&b=2 | 프래그먼트 제거 · 추적 파라미터 2개 제거 · 쿼리 정렬 · 스킴·호스트 소문자
https://example.com/%7Euser/%e2%82%ac/index.html?x=%7e | https://example.com/~user/%E2%82%AC/index.html?x=%7E | 퍼센트 인코딩 정리
//cdn.example.com/lib.js | https://cdn.example.com/lib.js | 상대 경로를 기준 URL로 해석
../images/logo.png | https://example.com/docs/images/logo.png | 상대 경로를 기준 URL로 해석
https://한글.kr/경로/파일 | https://xn--bj0bj06e.kr/%EA%B2%BD%EB%A1%9C/%ED%8C%8C%EC%9D%BC | 표준 형태로 정리 (기본 포트·점 경로·인코딩)

결과 — 정규화된 URL 목록

http://www.example.com/a/c/?a=1&b=2
https://example.com/~user/%E2%82%AC/index.html?x=%7E
https://cdn.example.com/lib.js
https://example.com/docs/images/logo.png
https://xn--bj0bj06e.kr/%EA%B2%BD%EB%A1%9C/%ED%8C%8C%EC%9D%BC

이 도구로 할 수 있는 일

같은 페이지가 HTTP://Example.com:80/a/./b/../c?b=2&a=1 처럼 다양한 모양으로 불리면 로그 집계, 중복 제거, 캐시 키, canonical 태그가 어긋납니다. 하나의 표준 형태로 맞춰 줍니다.

  • 항상 적용: 스킴·호스트 소문자, 기본 포트(80/443) 제거, ./ 와 ../ 해석, 호스트 Punycode 변환
  • 옵션: 프래그먼트 제거, 추적 파라미터(utm_*, fbclid, gclid, msclkid …) 제거, 쿼리 파라미터 정렬, www. 제거, http→https, index.html 제거, 끝 슬래시 제거/추가
  • 퍼센트 인코딩 정리: %7E → ~ 처럼 불필요한 인코딩은 풀고 나머지 16진수는 대문자로
  • 기준 URL을 넣으면 ../images/a.png, //cdn.example.com/x.js, ?page=2 같은 상대 참조를 절대 URL로 해석(경로 결합)
  • 줄마다 어떤 변경이 일어났는지와 중복 제거 후 개수를 표시

💡 Tips

  • SEO canonical을 정할 때는 추적 파라미터 제거 + 쿼리 정렬 + 끝 슬래시 통일 조합을 쓰세요.
  • 쿼리 순서가 의미 있는 API라면 "쿼리 정렬"을 끄세요.
  • 대소문자는 호스트까지만 같다고 보며 경로는 대소문자를 구분하므로 바꾸지 않습니다.

자주 묻는 질문

정규화하면 다른 페이지로 바뀌지는 않나요?

표준에서 같다고 규정한 변경(호스트 대소문자, 기본 포트, 점 경로)과 옵션으로 선택한 변경만 적용합니다. 추적 파라미터 제거 같은 선택 옵션은 사이트마다 의미가 다를 수 있으니 확인하세요.

경로의 대소문자는 왜 바꾸지 않나요?

RFC 3986에서 경로는 대소문자를 구분하며 서버에 따라 /A와 /a가 다른 리소스일 수 있기 때문입니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
