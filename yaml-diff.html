YAML 비교 도구 — 들여쓰기·주석이 달라도 내용만 비교

두 YAML을 데이터로 읽어 비교하므로 들여쓰기, 주석, 키 순서가 달라도 실제로 바뀐 값만 경로와 함께 보여 줍니다.

사용 예시

🔍 추가 1 · 삭제 0 · 변경 3

입력 — 원본 YAML (A)

name: api
replicas: 2
image: app:1.0
env:
  - name: MODE
    value: dev
labels:
  tier: backend

입력 — 비교할 YAML (B)

name: api
replicas: 3
image: app:1.1
env:
  - name: MODE
    value: prod
labels:
  tier: backend
  team: core

결과 — 변경 사항

구분 | 경로 | 이전(A) | 이후(B)
변경 | $.replicas | 2 | 3
변경 | $.image | "app:1.0" | "app:1.1"
변경 | $.env[0].value | "dev" | "prod"
추가 | $.labels.team |  | "core"

이 도구로 할 수 있는 일

텍스트 diff는 들여쓰기만 바뀌어도 수십 줄이 달라 보입니다. 이 도구는 두 YAML을 먼저 데이터로 읽은 뒤 값 단위로 비교하므로 의미가 달라진 부분만 남습니다.

  • 들여쓰기, 주석, 키 순서, 따옴표 유무("1" vs 1은 별도 표시) 차이를 구분
  • 추가/삭제/변경을 경로($.spec.template.spec.containers[0].image)와 함께 표로 표시
  • 여러 문서(---)가 있으면 배열로 묶어 비교
  • 앵커(&)와 별칭(*)은 펼쳐서 비교

배열 순서가 중요하지 않다면 "배열 순서 무시"를 켜세요.

💡 Tips

  • Helm values.yaml을 환경별로 비교하거나 Kubernetes 매니페스트의 배포 전후 변경을 확인할 때 유용합니다.
  • 숫자로 쓴 값과 따옴표로 감싼 문자열은 다른 타입으로 취급됩니다.
  • 한쪽에 문법 오류가 있으면 A/B 중 어느 쪽인지와 줄·열을 알려 줍니다.

자주 묻는 질문

주석만 다르면 같은 YAML로 보나요?

네. 주석, 들여쓰기, 키 순서는 데이터가 아니므로 무시하고 값만 비교합니다.

YAML 앵커와 병합 키(<<)는 어떻게 비교되나요?

파싱 단계에서 앵커·별칭이 펼쳐지므로 최종적으로 적용되는 값을 기준으로 비교합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
