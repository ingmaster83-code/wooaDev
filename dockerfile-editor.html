Dockerfile 검사기 · 정리기

Dockerfile 을 붙여 넣으면 줄 이음과 here-doc 을 해석해 명령어를 표로 정리하고, FROM 순서, 스테이지 이름, COPY --from 참조, EXPOSE 범위 같은 오류와 latest 태그, apt-get 사용법, root 실행, 비밀 값 같은 모범 사례 문제를 줄 번호와 함께 알려 줍니다.

사용 예시

⛔ 오류 3건 · 경고 5건 — 스테이지 2개, 명령어 12개

입력 — Dockerfile

# syntax=docker/dockerfile:1
FROM node:latest AS build
WORKDIR /app
COPY . .
RUN npm install && npm run build
RUN apt-get update
RUN apt-get install curl

FROM nginx
COPY --from=build /app/dist /usr/share/nginx/html
COPY --from=builder /app/conf /etc/nginx
ENV API_TOKEN=abc123
EXPOSE 80 99999
CMD nginx -g "daemon off;"

결과 — 명령어 목록

줄 | 명령어 | 인자
2 | FROM | node:latest AS build
3 | WORKDIR | /app
4 | COPY | . .
5 | RUN | npm install && npm run build
6 | RUN | apt-get update
7 | RUN | apt-get install curl
9 | FROM | nginx
10 | COPY | --from=build /app/dist /usr/share/nginx/html
11 | COPY | --from=builder /app/conf /etc/nginx
12 | ENV | API_TOKEN=abc123
13 | EXPOSE | 80 99999
14 | CMD | nginx -g "daemon off;"

결과 — 점검 결과

⚠️ 줄 2: 이미지 "node:latest" 는 latest 태그라 빌드가 재현되지 않습니다. 버전을 고정하세요
ℹ️ 줄 4: COPY . . 뒤에 의존성 설치가 있어 소스가 바뀔 때마다 캐시가 깨집니다. 의존성 파일(package.json 등)만 먼저 복사해 설치하세요
ℹ️ 줄 5: 재현 가능한 빌드에는 npm install 대신 npm ci 를 쓰세요
⚠️ 줄 6: apt-get update 를 별도 RUN 에 두면 캐시된 오래된 목록으로 설치할 수 있습니다. 같은 RUN 에서 && apt-get install 로 이으세요
⛔ 줄 7: apt-get install 에 -y 가 없어 빌드가 입력을 기다리며 실패합니다
ℹ️ 줄 7: --no-install-recommends 로 불필요한 패키지를 줄이세요
ℹ️ 줄 7: 같은 RUN 끝에 rm -rf /var/lib/apt/lists/* 로 캐시를 지워 이미지를 줄이세요
⚠️ 줄 9: 이미지 "nginx" 에 태그가 없어 latest 가 쓰입니다. 버전을 고정하세요
⚠️ 줄 9: 마지막 스테이지가 root 로 실행됩니다. USER 로 비특권 사용자를 지정하세요
ℹ️ 줄 9: HEALTHCHECK 가 없습니다. 오케스트레이터가 상태를 알 수 있도록 추가를 고려하세요
⛔ 줄 11: --from=builder 에 해당하는 스테이지가 없습니다 (이전에 FROM … AS builder 가 필요)
⚠️ 줄 12: ENV 의 API_TOKEN 에 비밀 값을 넣으면 이미지 레이어와 history 에 남습니다. 빌드 시크릿(--mount=type=secret)이나 런타임 환경 변수를 쓰세요
⛔ 줄 13: EXPOSE 포트 99999 가 1~65535 범위를 벗어납니다
ℹ️ 줄 14: CMD 의 shell 형식은 PID 1 이 sh 가 되어 SIGTERM 이 전달되지 않습니다. exec 형식 ["실행파일", "인자"] 를 쓰세요

이 도구로 할 수 있는 일

이미지를 빌드하기 전에 흔한 실수를 브라우저에서 바로 찾습니다. Dockerfile 은 서버로 전송되지 않습니다.

  • 해석: 줄 이음(\ 또는 `), 주석, 파서 지시문(# escape=), here-doc, 대소문자 섞인 명령어
  • 오류: FROM 앞의 명령, 알 수 없는 명령어, 중복 스테이지 이름, 정의되지 않은 --from 스테이지, EXPOSE 범위, COPY 인자 부족, exec 형식 JSON 오류, apt-get install 의 -y 누락
  • 경고: latest·태그 없는 이미지, 별도 RUN 의 apt-get update, curl | sh, sudo, chmod 777, ENV/ARG 의 비밀 값, 상대 WORKDIR, 마지막 스테이지 root 실행
  • 권고(끌 수 있음): ADD 대신 COPY, npm ci, --no-install-recommends, 캐시 정리, HEALTHCHECK, COPY . . 앞에 의존성 설치, exec 형식 CMD
  • 줄 이음을 합치고 명령어를 대문자로 정리한 Dockerfile 출력

💡 Tips

  • 의존성 파일(package.json 등)만 먼저 COPY 해 설치하고 소스는 나중에 복사하면 빌드 캐시가 잘 유지됩니다.
  • 비밀 값은 ENV/ARG 가 아니라 RUN --mount=type=secret 으로 전달하세요. 이미지 history 에 남지 않습니다.
  • CMD 를 exec 형식(JSON 배열)으로 쓰면 컨테이너 종료 신호(SIGTERM)가 앱에 직접 전달됩니다.

자주 묻는 질문

hadolint 와 같은 결과인가요?

비슷한 규칙을 다루지만 모든 규칙을 구현한 것은 아닙니다. 핵심 오류와 자주 쓰는 모범 사례를 브라우저에서 빠르게 확인하는 용도입니다.

멀티스테이지는 어떻게 검사하나요?

FROM 마다 스테이지를 나누고 AS 이름, COPY --from 참조, 사용되지 않는 스테이지, 마지막 스테이지의 USER·HEALTHCHECK 를 확인합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
