Cache-Control 헤더 생성 · 분석기

정적 파일·HTML·API 상황별 프리셋으로 Cache-Control 헤더를 만들고, 이미 있는 헤더를 지시어별로 풀어 설명하며 모순을 찾아 줍니다.

사용 예시

✅ 브라우저: 1년 / 공유 캐시: 1년

입력 — 분석할 Cache-Control 값

public, max-age=31536000, immutable, stale-while-revalidate=600

결과 — Cache-Control 헤더

Cache-Control: public, max-age=31536000, immutable, stale-while-revalidate=600

결과 — 지시어 설명

지시어 | 값 | 의미
public |  | 모든 캐시(CDN·프록시 포함)에 저장 가능
max-age | 31536000 | 신선한 것으로 간주하는 시간(초) → 1년
immutable |  | 신선한 동안 재검증 요청(새로고침 포함) 불필요
stale-while-revalidate | 600 | 만료 후 지정 시간 동안은 낡은 응답을 먼저 쓰고 뒤에서 갱신 → 10분

이 도구로 할 수 있는 일

캐시 설정을 잘못하면 배포했는데 사용자 화면이 안 바뀌거나, 반대로 CDN이 매번 서버를 두드립니다. 상황에 맞는 값을 만들고 이미 쓰는 값이 의도대로인지 확인하세요.

  • 만들기: 공개 범위(public/private), max-age, s-maxage, no-cache, no-store, must-revalidate, immutable, stale-while-revalidate, stale-if-error 등을 선택
  • 프리셋: 해시가 붙은 정적 파일(1년+immutable), HTML(매번 재검증), 개인 API(no-store), CDN 위주, SWR
  • 분석: 붙여 넣은 헤더를 지시어별 의미와 시간(예: 31536000 → 1년)으로 설명하고 브라우저/공유 캐시 신선 시간을 요약
  • 점검: public·private 동시 사용, no-store와 max-age 충돌, immutable 단독 사용, max-age=0만 쓴 경우, 1년 초과, stale-* 단독 사용 등

함께 쓰면 좋은 도구

📨HTTP 헤더 파서 🌐HTTP 상태코드 🗜️CSS·JS·HTML 압축 🍪쿠키 파서

💡 Tips

  • 파일명에 해시가 들어가는 JS·CSS는 max-age=31536000, immutable로 영구 캐시하고 HTML만 짧게 두는 것이 정석입니다.
  • no-cache는 "캐시하지 말라"가 아니라 "쓰기 전에 재검증하라"입니다. 저장 자체를 막으려면 no-store를 쓰세요.
  • CDN과 브라우저 시간을 다르게 하려면 s-maxage를 쓰세요.

자주 묻는 질문

no-cache와 no-store의 차이는 무엇인가요?

no-cache는 저장은 하되 매번 서버에 재검증(304 가능)하고, no-store는 아예 저장하지 않습니다. 민감한 개인 정보에는 no-store를 쓰세요.

stale-while-revalidate는 무엇인가요?

만료된 응답을 지정한 시간 동안 우선 보여 주면서 뒤에서 새 응답을 받아 오는 방식입니다. 체감 속도가 빨라집니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
