PKCE 생성기 — code_verifier · code_challenge

OAuth 2.0 인가 코드 흐름을 보호하는 PKCE 값을 만듭니다. 안전한 난수 code_verifier와 S256 code_challenge, 인가 요청·토큰 교환 예시까지 한 번에 보여 줍니다.

사용 예시

✅ PKCE 값을 만들었습니다. verifier는 세션에만 보관하고 challenge만 인가 요청에 보냅니다.

입력 — code_verifier (비우면 새로 생성)

dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk

결과 — PKCE 값

항목 | 값
code_verifier | dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk
code_challenge | E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM
code_challenge_method | S256
verifier 길이 | 43

결과 — 요청 예시

# 1) 인가 요청 (브라우저 리다이렉트)
GET https://auth.example.com/authorize?response_type=code&client_id=my-client&redirect_uri=https%3A%2F%2Fapp.example.com%2Fcallback&scope=openid%20profile&code_challenge=E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM&code_challenge_method=S256

# 2) 토큰 교환 (서버/앱에서)
POST https://auth.example.com/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code&code=<AUTH_CODE>&client_id=my-client&redirect_uri=https%3A%2F%2Fapp.example.com%2Fcallback&code_verifier=dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk

이 도구로 할 수 있는 일

SPA와 모바일 앱처럼 client_secret을 숨길 수 없는 공개 클라이언트는 PKCE로 인가 코드 탈취를 막습니다. 값 만드는 방법을 눈으로 확인하세요.

  • code_verifier: 43~128자의 영문·숫자·-._~ 난수를 브라우저 CSPRNG로 생성 (직접 입력도 가능)
  • code_challenge: S256 = BASE64URL(SHA-256(verifier)), plain 방식도 지원하며 위험성 안내
  • 인가 요청(authorize) URL과 토큰 교환(token) 요청 예시를 바로 복사
  • state, nonce 같이 생성 옵션, RFC 7636 부록 B 예제 값과 일치
  • 모든 값은 브라우저에서만 만들어지며 서버로 전송되지 않음

💡 Tips

  • verifier는 로그인 시작 시 만들어 세션(또는 메모리)에만 보관하고, challenge만 인가 서버로 보냅니다.
  • plain 방식은 verifier가 그대로 노출되어 의미가 약합니다. 가능하면 항상 S256을 쓰세요.
  • verifier는 로그인 시도마다 새로 만들고 한 번만 사용하세요.

자주 묻는 질문

PKCE가 정확히 무엇을 막나요?

인가 코드를 가로챈 공격자가 토큰으로 교환하지 못하게 합니다. 교환 시 처음 만든 verifier를 증명해야 하기 때문입니다.

client_secret이 있어도 PKCE를 써야 하나요?

OAuth 2.1은 모든 클라이언트에 PKCE를 권장합니다. 비밀 키를 가진 서버 앱에도 추가 방어선이 됩니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
