인증서 체인 검증기

서버가 보내는 인증서 번들을 붙여 넣으면 리프에서 루트까지 발급자를 따라 체인을 만들고, 각 서명을 발급자의 공개키로 직접 검증합니다. 순서 오류, 누락된 중간 CA, 만료, CA 제약 위반을 알려 줍니다.

이 도구로 할 수 있는 일

일부 클라이언트에서만 TLS 오류가 날 때 서버 인증서 체인이 올바른지 확인합니다. 인증서는 브라우저 밖으로 나가지 않습니다.

  • 번들에서 리프를 찾고 발급자 이름·키 식별자로 체인을 자동 구성 (중복 제거, 체인에 속하지 않는 인증서 표시)
  • 서명 검증: RSA(PKCS#1 v1.5 SHA-1·256·384·512), ECDSA(P-256·384·521), Ed25519 — Web Crypto 로 실제 검증
  • 점검: 번들 순서(리프 → 중간 → 루트), 중간 CA 누락, 만료·임박, CA 플래그·keyCertSign·pathlen 제약, 약한 서명·짧은 키
  • 리프의 SAN 과 호스트 이름 일치, 기준 시각 지정
  • 루트가 신뢰 저장소에 있는지는 확인하지 않음 (서명 체인만 검증)

💡 Tips

  • 서버는 리프와 중간 CA 만 보내면 됩니다. 루트는 클라이언트가 이미 가지고 있습니다.
  • 브라우저는 AIA 로 누락된 중간 CA 를 내려받아 채워 주지만 Android, Java, curl 은 그러지 않아 오류가 납니다.
  • 번들 순서가 틀리면 일부 클라이언트가 거부합니다. 리프가 맨 앞, 그 발급자가 다음이어야 합니다.

자주 묻는 질문

서명이 일치하지 않는다고 나와요.

같은 이름의 다른 CA 인증서를 섞었거나 리프가 다른 키로 서명된 경우입니다. 갱신된 중간 CA 와 짝이 맞는지 확인하세요.

크로스 서명 루트도 되나요?

같은 주체 이름의 후보가 여럿이면 AKI 로 고릅니다. 완전한 경로 탐색은 하지 않으므로 복잡한 크로스 서명은 직접 확인하세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
