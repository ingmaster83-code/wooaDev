JMESPath 테스트기

people[?age > `30`].name 같은 JMESPath 식을 JSON에 실행해 필터·투영·함수 결과를 확인합니다.

사용 예시

✅ 결과 타입: array (2)

입력 — JSON 데이터

{
  "people": [
    { "name": "Kim", "age": 29, "state": { "name": "WA" }, "tags": ["dev", "ops"] },
    { "name": "Lee", "age": 41, "state": { "name": "NY" }, "tags": ["dev"] },
    { "name": "Park", "age": 35, "state": { "name": "WA" }, "tags": [] }
  ]
}

입력 — JMESPath 식

people[?age > `30`].{name: name, state: state.name}

결과 — 결과

[
  {
    "name": "Lee",
    "state": "NY"
  },
  {
    "name": "Park",
    "state": "WA"
  }
]

이 도구로 할 수 있는 일

JMESPath는 AWS CLI(--query), Azure CLI, Ansible, Terraform 등에서 JSON 출력을 가공할 때 쓰는 쿼리 언어입니다. 명령에 넣기 전에 실제 응답으로 식을 시험해 볼 수 있습니다.

  • 필터 people[?age > 30], 투영 people[*].name, 슬라이스 items[1:3]
  • 멀티셀렉트 {name: name, state: state.name}, 파이프 a | b
  • 함수 length(), sort_by(), max_by(), join(), contains(), keys(), values() 등 공식 함수 지원
  • 리터럴은 백틱(30, "text"), 문자열 비교는 작은따옴표('WA')를 사용

경로 목록까지 필요하면 JSONPath 테스터를, 정확한 한 값의 위치는 JSON 포인터 도구를 사용하세요.

💡 Tips

  • AWS CLI의 --query 옵션에 넣을 식은 여기서 먼저 결과를 확인하고 작은따옴표로 감싸 붙여 넣으세요.
  • 숫자·문자열 리터럴은 백틱으로, 필드 비교 문자열은 작은따옴표로 씁니다.
  • 결과가 null이면 경로 이름이나 대소문자를 먼저 확인하세요.

자주 묻는 질문

JMESPath와 JSONPath는 어떻게 다른가요?

JMESPath는 명세와 함수가 엄격히 정의된 별도의 언어(프로젝션·파이프 등)이고, JSONPath는 XPath를 닮은 경로 표기입니다. 구문이 서로 호환되지 않습니다.

식에 오류가 있으면 어떻게 표시되나요?

라이브러리가 보고하는 구문 오류 메시지를 그대로 보여 줍니다. 괄호·백틱·따옴표가 짝이 맞는지 확인하세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
