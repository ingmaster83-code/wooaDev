syslog 메시지 파서 (RFC 3164 · RFC 5424)

<34>Oct 16 09:12:03 web01 sshd[2412]: … 같은 전통 형식과 <165>1 2026-10-16T… 같은 RFC 5424 메시지를 PRI(facility·severity), 시각, 호스트, 앱, 프로세스 ID, 구조화 데이터, 본문으로 나눕니다.

사용 예시

✅ 4건 파싱 (crit 1, notice 2, info 1)

입력 — syslog 메시지 (한 줄에 하나, RFC 3164 / RFC 5424)

<34>Oct 16 09:12:03 web01 sshd[2412]: Failed password for root from 203.0.113.5 port 51234 ssh2
<165>1 2026-10-16T09:12:05.003Z web01.example.com myapp 2518 ID47 [exampleSDID@32473 iut="3" eventSource="Application"] Request handled in 35ms
<13>Oct  6 23:59:59 db01 kernel: Out of memory: Killed process 8123 (mysqld)
<190>1 2026-10-16T09:13:00+09:00 gw01 nginx - - - upstream timed out

결과 — 파싱 결과

형식 | 상태 | facility.severity | 시각 | 호스트 / 앱 | 메시지 | 비고

이 도구로 할 수 있는 일

장비·리눅스 로그를 사람이 읽을 수 있게 풀고 JSON 으로 옮깁니다.

  • PRI: <숫자> = facility × 8 + severity 를 facility 이름(auth, local4 …)과 severity(emerg~debug)로 변환
  • RFC 3164: 월 일 시:분:초 호스트 태그[PID]: 메시지 (연도·시간대 없음 → 입력한 연도, UTC 가정, ? 표시)
  • RFC 5424: 버전, ISO 8601 시각(오프셋 → UTC), 호스트, 앱, PROCID, MSGID, 구조화 데이터, 메시지
  • emerg·alert·crit·err 는 🚨 로 강조, 심각도별 건수 요약
  • 해석 결과 JSON 출력

💡 Tips

  • RFC 3164 로그는 연말·연초에 연도가 어긋날 수 있으니 날짜 근처 로그는 주의하세요.
  • 여러 서버의 로그를 합칠 때는 5424 형식과 UTC 사용을 권장합니다.
  • rsyslog 에서 RFC 5424 출력은 템플릿 RSYSLOG_SyslogProtocol23Format 으로 설정합니다.

자주 묻는 질문

PRI 숫자는 어떻게 읽나요?

8로 나눈 몫이 facility, 나머지가 severity 입니다. 34 → 4(auth), 2(crit).

journald 로그도 되나요?

journalctl -o short-iso 같은 출력은 형식이 달라 지원하지 않습니다. syslog 전송 형식(3164/5424)이 대상입니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
