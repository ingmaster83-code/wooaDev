AWS IAM 정책 뷰어 · 점검기

IAM 정책 JSON 을 붙여 넣으면 문장별 Effect·Action·Resource·조건을 표로 보여 주고, 와일드카드 관리자 권한, 권한 상승 가능성, S3 ARN 실수 같은 위험을 점검합니다. 작업과 리소스를 입력하면 이 정책 기준의 허용·거부 여부를 시뮬레이션합니다.

사용 예시

⛔ 오류 2건 · 경고 5건 — 문장 5개

입력 — IAM 정책 (JSON)

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadBucket",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": "arn:aws:s3:::my-bucket"
    },
    {
      "Sid": "Wide",
      "Effect": "Allow",
      "Action": [
        "ec2:*",
        "iam:PassRole"
      ],
      "Resource": "*"
    },
    {
      "Sid": "Wide",
      "Effect": "Allow",
      "NotAction": "iam:*",
      "Resource": "*"
    },
    {
      "Sid": "Deny",
      "Effect": "Deny",
      "Action": "s3:DeleteObject",
      "Resource": "arn:aws:s3:::my-bucket/*",
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    },
    {
      "Effect": "Allow",
      "Action": "sts:AssumeRole",
      "Resource": "*",
      "Principal": "*"
    }
  ]
}

입력 — 접근 시뮬레이션 (선택): 작업 [리소스] 예) s3:GetObject arn:aws:s3:::my-bucket/a.txt

s3:GetObject arn:aws:s3:::my-bucket/a.txt

결과 — 문장(Statement) 해석

# | Sid | Effect | 작업 | 리소스 / 주체 | 조건
1 | ReadBucket | Allow | s3:GetObject, s3:ListBucket | arn:aws:s3:::my-bucket | —
2 | Wide | Allow | ec2:*, iam:PassRole | * | —
3 | Wide | Allow | 제외: iam:* | * | —
4 | Deny | Deny | s3:DeleteObject | arn:aws:s3:::my-bucket/* | Bool {"aws:SecureTransport":"false"}
5 | — | Allow | sts:AssumeRole | P:"*" * | —

결과 — 시뮬레이션 결과

작업 | 리소스 | 결과 | 근거 문장
s3:GetObject | arn:aws:s3:::my-bucket/a.txt | ✅ 허용 | #3 (Wide) Allow

이 도구로 할 수 있는 일

정책을 적용하기 전에 의도와 위험을 브라우저에서 확인합니다. 정책은 서버로 전송되지 않습니다.

  • 표: 문장별 Sid·Effect·Action·Resource/Principal·Condition (Statement 단일 객체도 지원)
  • 위험: Action:* 와 Resource:*, 서비스 전체 와일드카드, iam:PassRole·iam:* 같은 권한 상승 경로, Principal:* 공개 허용
  • 형식: Effect 값, NotAction/NotResource, 버전, S3 버킷/객체 ARN 혼동
  • 시뮬레이션: 'action [resource]' 를 넣으면 명시적 허용/명시적 거부/암묵적 거부 판정과 근거 문장
  • 권고(끌 수 있음)

💡 Tips

  • 명시적 Deny 는 어떤 Allow 보다 우선합니다. 시뮬레이션 결과의 근거 문장을 확인하세요.
  • s3:GetObject 는 버킷 ARN 이 아니라 arn:aws:s3:::bucket/* 객체 ARN 에 적용해야 합니다.
  • 와일드카드를 쓰기 전에 필요한 Action 목록을 CloudTrail 의 실제 호출로 좁혀 최소 권한에 가깝게 만드세요.

자주 묻는 질문

IAM Policy Simulator 와 같은가요?

아니요. 이 정책 하나만 단순 평가합니다. SCP, 권한 경계, 세션 정책, 리소스 정책, 조건 키 평가는 포함되지 않으므로 정확한 판정은 AWS 의 Policy Simulator 를 쓰세요.

조건(Condition)도 평가하나요?

조건은 표에 보여 주지만 값을 평가하지는 않습니다. 조건이 있는 문장은 시뮬레이션에서 조건부로 표시합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
