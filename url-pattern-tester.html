URLPattern 테스터 — 라우팅 패턴 일치 확인

https://shop.example.com/products/:id(\d+)/:section? 같은 URLPattern 을 입력하고 여러 URL 에 대해 일치 여부와 캡처된 :id, :section 값을 확인합니다. 패턴이 어떤 구성요소(protocol, hostname, pathname 등)로 나뉘는지도 보여 줍니다.

사용 예시

✅ 6개 중 2개 일치

입력 — URLPattern 패턴 (전체 URL 또는 pathname)

https://shop.example.com/products/:id(\d+)/:section?

입력 — 테스트할 URL (한 줄에 하나)

https://shop.example.com/products/42
https://shop.example.com/products/42/reviews
https://shop.example.com/products/abc
https://shop.example.com/products/42/reviews/extra
http://shop.example.com/products/7
https://other.example.com/products/7

결과 — 일치 결과

URL | 결과 | 캡처 / 사유
https://shop.example.com/products/42 | ✅ | id=42
https://shop.example.com/products/42/reviews | ✅ | id=42, section=reviews
https://shop.example.com/products/abc | ❌ | pathname: "/products/abc" ≠ /products/:id(\d+)/:section?
https://shop.example.com/products/42/reviews/extra | ❌ | pathname: "/products/42/reviews/extra" ≠ /products/:id(\d+)/:section?
http://shop.example.com/products/7 | ❌ | protocol: "http" ≠ https
https://other.example.com/products/7 | ❌ | hostname: "other.example.com" ≠ shop.example.com

결과 — 패턴 구성

구성 | 패턴 | 캡처 이름
protocol | https | —
hostname | shop.example.com | —
port | * (모두) | —
pathname | /products/:id(\d+)/:section? | id, section
search | * (모두) | —
hash | * (모두) | —

이 도구로 할 수 있는 일

브라우저 URLPattern API 를 쓰기 전에 패턴이 의도한 URL 만 잡는지 테스트합니다. 이 도구는 자체 구현이라 브라우저 지원과 무관하게 동작합니다.

  • 문법: /users/:id, :id(\d+), 와일드카드 *, 선택 :section?, 반복 :path+ / :path*, {…}? 그룹, 이스케이프
  • 전체 URL 패턴과 pathname 만 있는 패턴 모두 지원, 구성요소별(protocol, hostname, port, pathname, search, hash) 패턴
  • 일치 결과: 캡처 이름과 값, 일치하지 않는 이유
  • 점검: 미지원/잘못된 문법, 이름 중복, 선택 세그먼트의 슬래시 처리
  • 한 줄에 URL 하나씩 여러 개

💡 Tips

  • pathname 만 지정하면 호스트 등은 모두 와일드카드로 처리됩니다.
  • :id 는 기본적으로 슬래시를 제외한 한 세그먼트에 일치합니다. 숫자만 받으려면 :id(\d+) 를 쓰세요.
  • 서비스 워커나 Navigation API 에서 같은 패턴 문법을 그대로 쓸 수 있습니다.

자주 묻는 질문

정규식과 무엇이 다른가요?

URLPattern 은 URL 구성요소 단위로 일치시키고 이름 있는 캡처를 제공하며 인코딩 규칙을 적용합니다. 문법은 path-to-regexp 를 기반으로 합니다.

쿼리 문자열도 일치시킬 수 있나요?

search 구성요소에 패턴을 지정할 수 있지만 쿼리 파라미터 순서에 의존하니 파라미터 검사는 코드에서 하는 것이 안전합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
