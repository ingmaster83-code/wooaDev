JSON 병합 도구 — 충돌 우선순위와 배열 처리 선택

기본 설정 JSON 위에 덮어쓸 JSON을 깊이 병합합니다. 충돌 시 우선할 쪽과 배열 처리 방식을 고를 수 있고 충돌 내역도 보여 줍니다.

사용 예시

🔀 병합 완료 — 충돌·변경 3건 (B 우선)

입력 — 기준 JSON (A)

{
  "name": "app",
  "port": 3000,
  "db": { "host": "localhost", "user": "root" },
  "plugins": ["auth", "log"]
}

입력 — 덮어쓸 JSON (B)

{
  "port": 8080,
  "db": { "host": "db.prod", "ssl": true },
  "plugins": ["log", "cache"],
  "debug": null
}

결과 — 병합 결과

{
  "name": "app",
  "port": 8080,
  "db": {
    "host": "db.prod",
    "user": "root",
    "ssl": true
  },
  "plugins": [
    "log",
    "cache"
  ],
  "debug": null
}

결과 — 충돌·변경 내역

경로 | A 값 | B 값 | 결과 | 적용
$.port | 3000 | 8080 | 8080 | B
$.db.host | "localhost" | "db.prod" | "db.prod" | B
$.plugins | ["auth","log"] | ["log","cache"] | ["log","cache"] | B

이 도구로 할 수 있는 일

환경별 설정(base + production)이나 기본값 + 사용자 설정을 합칠 때는 얕은 병합(Object.assign)으로는 중첩 객체가 통째로 사라집니다. 이 도구는 깊은 병합을 하고, 어떤 값이 어느 쪽에서 왔는지 보여 줍니다.

  • 충돌 시 B(덮어쓰기) 또는 A(기준 유지) 중 우선할 쪽 선택
  • 배열 처리: 교체 / 이어 붙이기 / 합집합(중복 제거) / 인덱스별 병합
  • 옵션으로 B의 null을 "키 삭제"로 처리 (RFC 7386 JSON Merge Patch 규칙)
  • 충돌한 경로와 A·B 값, 최종 적용된 값을 표로 확인

두 문서의 차이만 보고 싶다면 JSON 비교 도구를 사용하세요.

💡 Tips

  • 기본 설정에 사용자 설정을 얹을 때는 A=기본값, B=사용자값, 우선순위 B로 두세요.
  • 플러그인·태그 목록을 합칠 때는 "합집합"이 중복을 알아서 제거해 줍니다.
  • RFC 7386 옵션을 켜면 B에서 값을 null로 지정한 키가 결과에서 삭제됩니다.

자주 묻는 질문

얕은 병합과 깊은 병합은 무엇이 다른가요?

얕은 병합은 최상위 키만 덮어써 중첩 객체가 통째로 교체됩니다. 깊은 병합은 객체 안쪽까지 키 단위로 합쳐 서로 다른 하위 키를 모두 보존합니다.

배열은 왜 별도 옵션이 있나요?

배열은 요소를 어떻게 합칠지 정답이 없습니다. 통째로 교체할지, 이어 붙일지, 중복을 제거할지, 같은 위치끼리 합칠지를 상황에 맞게 고를 수 있게 했습니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
