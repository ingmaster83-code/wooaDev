HTTP 헤더 파서 — 요청·응답 헤더 해석과 점검

브라우저 개발자 도구나 curl -I에서 복사한 HTTP 헤더를 붙여 넣으면 헤더마다 의미를 설명하고 쿠키·캐시·보안 설정의 빠진 부분을 알려 줍니다.

사용 예시

🔍 헤더 11개 — 확인할 점 3개

입력 — HTTP 요청·응답 헤더 (원문 그대로)

HTTP/2 200
content-type: text/html; charset=utf-8
cache-control: public, max-age=3600, s-maxage=86400
set-cookie: sid=abc123; Path=/; HttpOnly; Secure; SameSite=Lax; Max-Age=86400
set-cookie: theme=dark; Path=/
strict-transport-security: max-age=31536000; includeSubDomains
x-content-type-options: nosniff
content-encoding: br
vary: Accept-Encoding, Cookie
content-length: 18432
server: nginx
date: Fri, 16 Oct 2026 03:00:00 GMT

결과 — 요약

상태 줄: HTTP/2 200
프로토콜: HTTP/2
상태 코드: 200
헤더 수: 11
종류: 응답

결과 — 헤더 분석

헤더 | 값 | 설명
content-type | text/html; charset=utf-8 | 본문 미디어 타입과 문자 인코딩 — 타입 text/html, 문자셋 utf-8
cache-control | public, max-age=3600, s-maxage=86400 | 캐시 정책 — public · max-age=3600 · s-maxage=86400
set-cookie | sid=abc123; Path=/; HttpOnly; Secure; SameSite=Lax; Max-Age=86400 | 쿠키 설정 — 쿠키 sid — Secure HttpOnly SameSite
set-cookie | theme=dark; Path=/ | 쿠키 설정 — 쿠키 theme — 
strict-transport-security | max-age=31536000; includeSubDomains | HTTPS 강제(HSTS) — 365일간 HTTPS 강제 · 하위 도메인 포함
x-content-type-options | nosniff | MIME 스니핑 방지
content-encoding | br | 본문 압축 방식
vary | Accept-Encoding, Cookie | 캐시 키에 포함되는 요청 헤더
content-length | 18432 | 본문 크기(바이트) — 18 KB
server | nginx | 서버 소프트웨어
date | Fri, 16 Oct 2026 03:00:00 GMT | 응답 생성 시각 — 2026-10-16T03:00:00Z

이 도구로 할 수 있는 일

개발자 도구의 Network 탭이나 curl -i 결과를 이해하기 쉽게 풀어 줍니다. 요청과 응답을 자동으로 구분하고 헤더마다 한 줄 설명을 붙입니다.

  • 요청 줄(GET /path HTTP/1.1)·상태 줄(HTTP/2 200)에서 메서드·경로·프로토콜·상태 코드 추출, 접힌(folded) 헤더 줄 처리
  • 해석: Content-Type(미디어 타입·charset), Cache-Control 지시어, Set-Cookie 속성, Strict-Transport-Security 기간, Accept 계열 우선순위(q 값), 날짜 헤더(ISO 변환), Content-Length 크기
  • 점검: HSTS·X-Content-Type-Options 누락, 쿠키의 Secure·HttpOnly·SameSite, charset 누락, Server 헤더의 버전 노출, 중복된 단일 값 헤더, no-store와 max-age 충돌
  • Authorization·Cookie 값은 일부만 보여 주어 화면 공유 시에도 안전

함께 쓰면 좋은 도구

🗄️Cache-Control 생성·분석기 🌐HTTP 상태코드 🍪쿠키 파서 🕵️User-Agent 파서

💡 Tips

  • curl -sI https://example.com 의 출력을 그대로 붙여 넣을 수 있습니다.
  • HTTP/2·3에서는 헤더 이름이 모두 소문자로 보이는 것이 정상입니다.
  • 인증 헤더가 든 요청을 공유할 때는 값을 지우고 보내세요. 이 도구는 값을 일부만 표시합니다.

자주 묻는 질문

요청 헤더와 응답 헤더는 어떻게 구분하나요?

첫 줄이 "GET /path HTTP/1.1"이면 요청, "HTTP/2 200"이면 응답입니다. 시작 줄이 없으면 Host 헤더가 있는지로 짐작합니다.

입력한 헤더가 서버로 전송되나요?

아니요. 헤더 안에는 쿠키나 인증 토큰이 있을 수 있지만 모든 분석은 브라우저 안에서만 이루어집니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
