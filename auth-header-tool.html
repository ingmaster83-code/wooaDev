Authorization 헤더 도구 — Basic · Bearer · JWT

Authorization 헤더나 토큰을 붙여 넣으면 방식(Basic/Bearer/JWT)을 알아내 해독하고 만료 여부를 점검합니다. 사용자·비밀번호로 Basic 헤더도 만들 수 있습니다.

사용 예시

✅ JWT 토큰을 해석했습니다

입력 — Authorization 헤더 또는 토큰

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTYiLCJuYW1lIjoiS2ltIiwiaWF0IjoxNzAwMDAwMDAwLCJleHAiOjE3MDAwMDM2MDB9.signature

입력 — 사용자 이름

aladdin

입력 — 비밀번호

open sesame

결과 — 결과

{
  "alg": "HS256",
  "typ": "JWT"
}

{
  "sub": "123456",
  "name": "Kim",
  "iat": 1700000000,
  "exp": 1700003600
}

결과 — 상세

클레임 | 값
알고리즘 (alg) | HS256
typ | JWT
sub | "123456"
name | "Kim"
iat | 2023-11-14T22:13:20Z  (1700000000)
exp | 2023-11-14T23:13:20Z  (1700003600)

이 도구로 할 수 있는 일

API 호출이 401을 돌려줄 때 헤더가 제대로 만들어졌는지 확인하는 도구입니다. 모든 해독은 브라우저에서만 이뤄지므로 실제 토큰을 붙여 넣어도 서버로 전송되지 않습니다.

  • Basic: Base64를 풀어 사용자:비밀번호 표시, 사용자 이름의 콜론 같은 문제 점검
  • Bearer/JWT: 헤더 alg, 클레임(sub, iss, aud, iat, nbf, exp)을 사람이 읽는 시각으로 표시
  • 기준 시각을 넣어 '만료까지 N분' 또는 '만료됨(N분 전)' 판정
  • alg=none 같은 위험한 토큰, exp 없는 토큰 경고
  • 사용자·비밀번호를 입력해 Authorization: Basic ... 헤더 생성

💡 Tips

  • Basic 인증은 암호화가 아니라 Base64 인코딩일 뿐입니다. 반드시 HTTPS에서만 사용하세요.
  • 서명은 이 도구가 검증하지 않습니다. 내용은 누구나 읽을 수 있으므로 JWT에 민감 정보를 넣지 마세요.
  • 토큰이 방금 만료된 것 같다면 서버와 클라이언트의 시계 차이(clock skew)도 의심해 보세요.

자주 묻는 질문

Bearer 토큰은 무엇인가요?

토큰을 가진 쪽이면 누구나 사용할 수 있는 방식입니다. 그래서 유출되면 곧바로 악용될 수 있어 HTTPS와 짧은 만료 시간이 중요합니다.

JWT 서명도 검증해 주나요?

아니요. 서명 검증에는 비밀 키/공개 키가 필요합니다. 내용 확인과 만료 점검 용도로 쓰고, 검증은 서버에서 수행하세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
