URI 템플릿(RFC 6570) 테스터

/users/{id}{?page,limit} 같은 URI 템플릿에 변수를 넣어 실제 URL로 확장하고 표현식별 결과를 확인합니다.

사용 예시

✅ 3개 표현식 확장

입력 — URI 템플릿 (RFC 6570)

https://api.example.com/users/{id}/posts{?page,limit,tags*}{#section}

입력 — 변수 (JSON)

{
  "id": "42",
  "page": 2,
  "limit": 20,
  "tags": ["a b", "c&d"],
  "section": "top 10"
}

결과 — 확장된 URI

https://api.example.com/users/42/posts?page=2&limit=20&tags=a%20b&tags=c%26d#top%2010

결과 — 표현식 분석

표현식 | 연산자 | 변수 | 확장 결과
{id} | (없음) | id | 42
{?page,limit,tags*} | ? | page,limit,tags* | ?page=2&limit=20&tags=a%20b&tags=c%26d
{#section} | # | section | #top%2010

이 도구로 할 수 있는 일

REST API의 링크(HAL, OpenAPI Links, GitHub API의 url 필드)는 "https://api.github.com/repos/{owner}/{repo}/issues{/number}" 같은 URI 템플릿으로 주어집니다. 변수를 넣었을 때 실제 URL이 어떻게 되는지 확인할 수 있습니다.

  • 연산자: {var} 단순, {+var} 예약 확장, {#var} 프래그먼트, {.var} 점, {/var} 경로, {;var} 세미콜론, {?var} 쿼리, {&var} 쿼리 연결
  • 변경자: {var:3} 앞 3글자만(접두어), {list*} 배열·객체 폭발(explode)
  • 변수는 JSON 객체(문자열·숫자·배열·객체)로 입력 — 값이 없는 변수는 생략
  • 표현식별 확장 결과를 표로 보여 주고, 퍼센트 인코딩 규칙(예약 문자 허용 여부)을 자동 적용

💡 Tips

  • 쿼리는 {?q,page}처럼 쓰면 첫 변수에 ?, 이후에 &가 붙습니다.
  • 경로에 슬래시를 그대로 두려면 {+path}, 인코딩하려면 {path}를 쓰세요.
  • 배열을 {?tags*}로 쓰면 tags=a&tags=b, {?tags}로 쓰면 tags=a,b 가 됩니다.

자주 묻는 질문

URI 템플릿과 정규식 경로 패턴은 다른가요?

URI 템플릿은 변수를 넣어 URL을 만드는(확장) 규격이고, URLPattern·정규식은 들어온 URL을 매칭하는 용도입니다. 방향이 반대입니다.

정의되지 않은 변수는 어떻게 되나요?

RFC 6570에 따라 표현식에서 그 변수 부분이 통째로 생략됩니다. 도구에서도 어떤 변수가 빠졌는지 알려 줍니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
