S3 URL 변환기 — s3:// · https:// · ARN

S3 객체를 가리키는 s3:// URI, virtual-hosted 방식 HTTPS, path-style HTTPS, 레거시 엔드포인트, ARN을 서로 변환하고 버킷 이름 규칙 위반을 알려 줍니다.

사용 예시

✅ 5개 주소를 변환했습니다

입력 — S3 주소 (s3://, https://, ARN — 한 줄에 하나)

s3://my-bucket/photos/2026/cat.jpg
https://my-bucket.s3.ap-northeast-2.amazonaws.com/photos/cat.jpg
https://s3.us-west-2.amazonaws.com/data-lake/raw/2026/part-0001.parquet
https://legacy-bucket.s3-eu-west-1.amazonaws.com/a/b.txt
arn:aws:s3:::my-bucket/docs/readme.md

이 도구로 할 수 있는 일

S3는 같은 객체를 부르는 주소 형식이 여러 가지라 CLI, SDK, 브라우저, IAM 정책마다 다른 표기를 써야 합니다.

  • 입력: s3:// URI, virtual-hosted(버킷.s3.리전.amazonaws.com), path-style(s3.리전.amazonaws.com/버킷), 레거시 s3-리전, 정적 웹사이트·가속 엔드포인트, ARN
  • 출력: s3 URI, ARN, virtual-hosted, path-style, 글로벌 레거시, 듀얼스택(IPv6), aws s3 ls 명령
  • 키의 특수문자와 한글은 퍼센트 인코딩/디코딩 처리
  • 버킷 이름 검사: 3~63자, 소문자·숫자·.·-, 연속된 점·IP 형식·예약 접두사 불가
  • 리전이 없는 입력은 기본 리전을 가정하고 알려 줌

💡 Tips

  • 버킷 이름에 점(.)이 있으면 virtual-hosted HTTPS의 와일드카드 인증서와 맞지 않아 브라우저 경고가 납니다.
  • 신규 코드는 virtual-hosted 방식을 쓰세요. path-style은 단계적으로 폐지되고 있습니다.
  • 리전이 다르면 301 리다이렉트가 납니다. 버킷의 실제 리전을 확인하세요(aws s3api get-bucket-location).

자주 묻는 질문

s3:// 주소는 브라우저에서 열 수 있나요?

아닙니다. s3:// 는 CLI·SDK 용 URI입니다. 브라우저에서 열려면 HTTPS 주소와 공개 권한 또는 사전 서명된 URL이 필요합니다.

Presigned URL도 변환되나요?

서명 쿼리(X-Amz-Signature 등)는 변환 대상이 아닙니다. 버킷과 키를 확인하는 용도로 쓰고, 서명은 별도로 만드세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
