Snowflake ID 디코더 — 생성 시각과 노드·시퀀스

Twitter(X), Discord, Instagram, Sonyflake 또는 직접 정의한 Snowflake ID에서 생성 시각, 워커, 시퀀스를 뽑아냅니다.

사용 예시

✅ 3개 해석

입력 — Snowflake ID (한 줄에 하나)

1541815603606036480
175928847299117063
1543244810129002496

결과 — 분석 결과

ID | 생성 시각 (UTC) | 선택한 시간대 | 구성 요소
1541815603606036480 | 2022-06-28T16:07:40.105Z | 2022-06-29 01:07:40 (UTC+09:00) | datacenter 11, worker 26, seq 0
175928847299117063 | 2012-03-03T13:01:20.453Z | 2012-03-03 22:01:20 (UTC+09:00) | datacenter 1, worker 0, seq 7
1543244810129002496 | 2022-07-02T14:46:49.493Z | 2022-07-02 23:46:49 (UTC+09:00) | datacenter 26, worker 5, seq 0

이 도구로 할 수 있는 일

Snowflake ID는 상위 비트에 시각, 그 아래에 서버(워커) 번호와 순번을 넣은 64비트 정수입니다. 트윗·디스코드 메시지·사용자 ID만 보고도 만들어진 시각을 알 수 있습니다.

  • Twitter(X): 41비트 시각 + 5비트 데이터센터 + 5비트 워커 + 12비트 시퀀스 (에포크 2010-11-04)
  • Discord: 에포크 2015-01-01, 워커·프로세스·증가값 / Instagram: 13비트 샤드 + 10비트 시퀀스
  • Sonyflake: 10ms 단위 시각 + 시퀀스 + 머신 ID / 사용자 정의: 에포크와 비트 폭을 직접 지정
  • UTC와 선택한 시간대(예: Asia/Seoul)로 함께 표시, 한 줄에 하나씩 여러 ID 분석

💡 Tips

  • 플랫폼을 잘못 고르면 시각이 엉뚱한 해(1970년대나 먼 미래)로 나옵니다. 그럴 땐 다른 플랫폼을 선택해 보세요.
  • JavaScript의 Number로 읽으면 정밀도가 깨지므로 ID는 항상 문자열로 다루세요. 이 도구는 BigInt로 계산합니다.
  • 같은 밀리초 안에서 만들어진 ID는 시퀀스 값으로 구분됩니다.

자주 묻는 질문

ID 하나로 정확한 생성 시각을 알 수 있나요?

네. 시각 부분은 밀리초 단위로 정확합니다. 다만 서버가 시계를 조금 틀리게 쓰는 경우의 오차까지 알 수는 없습니다.

에포크가 플랫폼마다 다른 이유는 무엇인가요?

Snowflake는 시각을 에포크 이후 경과 시간으로 저장해 41비트로 약 69년을 표현합니다. 각 서비스가 시작 시점 근처로 에포크를 잡아 사용 가능 기간을 늘렸습니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
