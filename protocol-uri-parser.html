프로토콜 URI 파서 (mqtt · amqp · ws · redis · postgres)

mqtt://user:pass@broker:1883/topic, amqps://…, redis://…, postgres://… 같은 연결 URI 를 스킴, 인증 정보, 호스트, 포트, 경로, 쿼리로 나누고 암호화 여부, 기본 포트, 비밀번호 노출 같은 문제를 점검합니다.

사용 예시

🔍 문제 1건

입력 — URI (mqtt, mqtts, amqp, amqps, ws, wss, redis, postgres … — 한 줄에 하나)

mqtt://user:pa%40ss@broker.example.com:1883/telemetry?clientId=dev1
mqtts://broker.example.com
amqp://guest:guest@rabbit.local:5672/%2F
amqps://user:pw@mq.example.com/prod?heartbeat=30
ws://localhost:8080/socket
wss://stream.example.com/v1/feed?token=abc123
redis://:secret@cache.local:6379/2

결과 — 점검 사항

🔐 암호화되지 않은 mqtt 연결로 비밀번호를 보냅니다 — mqtts 사용을 권장
🔐 암호화되지 않은 amqp 연결로 비밀번호를 보냅니다 — amqps 사용을 권장
🚨 RabbitMQ 기본 계정(guest/guest)은 원격에서 거부되는 것이 기본입니다
쿼리 문자열의 토큰·비밀은 프록시/서버 로그에 남을 수 있습니다 — 헤더나 첫 메시지로 보내세요
🔐 암호화되지 않은 redis 연결로 비밀번호를 보냅니다 — rediss 사용을 권장

이 도구로 할 수 있는 일

연결 문자열이 의도한 대로 읽히는지, 비밀번호의 @ : / 가 올바르게 인코딩됐는지 확인합니다. 입력은 브라우저 밖으로 나가지 않습니다.

  • 구성요소: 스킴, 사용자, 비밀번호(디코딩), 호스트(IPv6 포함), 포트, 경로/vhost/DB 번호, 쿼리 파라미터
  • 프로토콜 지식: mqtt/mqtts, amqp/amqps, ws/wss, redis/rediss, postgres(ql), mysql, mongodb(+srv), 기본 포트와 TLS 여부
  • 점검: 비밀번호가 URI 에 포함, 평문 프로토콜, 포트 생략(기본값 안내), 비밀번호 특수문자 미인코딩, 잘못된 포트 범위
  • 한 줄에 URI 하나씩 여러 개
  • 읽기 쉬운 표로 출력

💡 Tips

  • 비밀번호에 @ : / # ? 가 있으면 %40 %3A %2F %23 %3F 로 인코딩해야 호스트 경계가 깨지지 않습니다.
  • 연결 문자열은 코드 저장소가 아니라 환경 변수나 비밀 관리 도구에 두세요.
  • amqp 의 vhost / 는 URI 에서 %2F 로 써야 합니다.

자주 묻는 질문

mqtt 와 mqtts 는 어떻게 다른가요?

mqtts 는 TLS 로 암호화된 연결이며 기본 포트가 8883, 평문 mqtt 는 1883 입니다.

scheme 이 목록에 없으면요?

알려지지 않은 스킴도 기본 구성요소로는 나뉘지만 기본 포트·보안 안내는 제공되지 않습니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
