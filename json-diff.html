JSON 비교 도구 — 두 JSON의 차이를 경로별로

두 JSON을 의미 단위로 비교해 추가·삭제·변경된 값을 경로와 함께 보여 주고, 이를 JSON Patch로 만들어 줍니다.

사용 예시

🔍 추가 2 · 삭제 1 · 변경 2

입력 — 원본 JSON (A)

{
  "name": "WooaDev",
  "version": "1.0.0",
  "tags": ["json", "tool"],
  "author": { "name": "Kim", "email": "kim@example.com" },
  "legacy": true
}

입력 — 비교할 JSON (B)

{
  "name": "WooaDev",
  "version": "1.1.0",
  "tags": ["json", "tool", "free"],
  "author": { "name": "Kim", "email": "kim@wooahouse.com" },
  "license": "MIT"
}

결과 — 변경 사항

구분 | 경로 | 이전(A) | 이후(B)
변경 | $.version | "1.0.0" | "1.1.0"
추가 | $.tags[2] |  | "free"
변경 | $.author.email | "kim@example.com" | "kim@wooahouse.com"
삭제 | $.legacy | true | 
추가 | $.license |  | "MIT"

결과 — JSON Patch (A → B)

[
  {
    "op": "replace",
    "path": "/version",
    "value": "1.1.0"
  },
  {
    "op": "add",
    "path": "/tags/2",
    "value": "free"
  },
  {
    "op": "replace",
    "path": "/author/email",
    "value": "kim@wooahouse.com"
  },
  {
    "op": "add",
    "path": "/license",
    "value": "MIT"
  },
  {
    "op": "remove",
    "path": "/legacy"
  }
]

이 도구로 할 수 있는 일

텍스트 비교 도구는 들여쓰기나 키 순서만 달라도 모두 다른 줄로 표시합니다. 이 도구는 JSON을 먼저 파싱해서 값 단위로 비교하므로 의미가 달라진 부분만 정확히 보여 줍니다.

  • 키 순서·공백·줄바꿈 차이는 무시하고 추가/삭제/변경만 경로($.user.tags[1])와 함께 표시
  • 타입이 바뀐 경우(숫자 1 → 문자열 "1")는 별도로 표시
  • "배열 순서 무시"를 켜면 요소만 같으면 같은 JSON으로 판단
  • A를 B로 바꾸는 JSON Patch(RFC 6902)를 함께 생성해 API PATCH 요청이나 변경 이력에 활용

텍스트 줄 단위 비교가 필요하면 Diff 비교기를 사용하세요.

💡 Tips

  • API 응답이 배포 전후로 어떻게 달라졌는지 확인할 때, 두 응답을 그대로 붙여 넣기만 하면 됩니다.
  • 순서가 중요하지 않은 태그·ID 목록은 "배열 순서 무시"를 켜세요.
  • 생성된 JSON Patch는 배열 끝 요소 삭제 순서까지 고려해 순서대로 적용하면 A가 B가 되도록 만들어집니다.

자주 묻는 질문

키 순서만 다르면 다른 JSON인가요?

아니요. JSON 객체의 키 순서는 의미가 없으므로 이 도구는 순서가 달라도 같다고 판단합니다. 배열은 기본적으로 순서까지 비교합니다.

1과 1.0은 같은 값인가요?

JSON에는 정수와 실수의 구분이 없어 같은 숫자로 취급합니다. 숫자와 문자열(1과 "1")은 다른 타입으로 표시됩니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
