OpenAPI · Swagger 검사기

OpenAPI 3.0·3.1 또는 Swagger 2.0 문서(YAML·JSON)를 붙여 넣으면 엔드포인트 표를 만들고, $ref 대상, 경로 변수와 path 파라미터 일치, operationId 중복, 응답 코드, 스키마 오류, 인증 정의를 줄 번호와 함께 점검합니다.

사용 예시

⛔ 오류 9건 · 경고 1건 — OpenAPI 3.0.3, 엔드포인트 3개

입력 — OpenAPI / Swagger 문서 (YAML 또는 JSON)

openapi: 3.0.3
info:
  title: Pet Store
paths:
  /pets/{petId}:
    get:
      operationId: getPet
      parameters:
        - name: limit
          in: query
          schema: { type: integer, minimum: 1 }
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema: { $ref: "#/components/schemas/Pet" }
        "404": { $ref: "#/components/responses/Missing" }
    delete:
      operationId: getPet
      requestBody: { content: { application/json: { schema: { type: object } } } }
      responses: {}
  /pets:
    post:
      security: [{ apiKey: [] }]
      responses:
        "201": { description: Created }
        "2xx": { description: Any }
components:
  schemas:
    Pet:
      type: object
      required: [id, name]
      properties:
        id: { type: integer, format: int64 }
        tags: { type: array }
…

결과 — 엔드포인트

메서드 | 경로 | operationId | 응답 | 태그 | 줄
GET | /pets/{petId} | getPet | 200, 404 | — | 7
DELETE | /pets/{petId} | getPet | — | — | 20
POST | /pets | — | 201, 2xx | — | 25

결과 — 점검 결과

⛔ 줄 3: info.version 이 필요합니다
⛔ 줄 7: GET /pets/{petId}: 경로 변수 {petId} 에 해당하는 in: path 파라미터가 없습니다
ℹ️ 줄 7: GET /pets/{petId} 에 summary/description 이 없습니다
⛔ 줄 18: $ref #/components/responses/Missing 대상을 찾을 수 없습니다
⛔ 줄 20: DELETE /pets/{petId}: 경로 변수 {petId} 에 해당하는 in: path 파라미터가 없습니다
⛔ 줄 20: operationId "getPet" 가 GET /pets/{petId} 와 중복됩니다
⛔ 줄 20: DELETE /pets/{petId}: responses 에 응답이 하나 이상 필요합니다
ℹ️ 줄 20: DELETE /pets/{petId} 에 summary/description 이 없습니다
ℹ️ 줄 21: DELETE 에 requestBody 는 의미가 정의되지 않았습니다 (일부 서버·프록시가 무시)
ℹ️ 줄 25: POST /pets 에 operationId 가 없습니다 (SDK 생성 시 필요)
⛔ 줄 25: security 의 "apiKey" 가 securitySchemes 에 정의되지 않았습니다
ℹ️ 줄 25: POST /pets 에 summary/description 이 없습니다
⛔ 줄 28: 응답 코드 "2xx" 가 올바르지 않습니다 (100~599, 1XX~5XX, default)
⚠️ 줄 33: required 의 "name" 가 properties 에 없습니다
⛔ 줄 36: type: array 에는 items 가 필요합니다
ℹ️ 줄 37: format "int32" 은(는) type string 와 맞지 않거나 표준 포맷이 아닙니다
ℹ️ 줄 38: schemas "Unused" 를 참조하는 곳이 없습니다
이 검사는 OpenAPI 의 구조·참조·자주 쓰는 규칙을 확인하며 JSON Schema 전체 검증(unevaluatedProperties 등)은 하지 않습니다. 배포 전에는 Spectral 이나 공식 검증기로 한 번 더 확인하세요

이 도구로 할 수 있는 일

API 문서를 배포하기 전에 구조와 참조 오류를 브라우저에서 바로 찾습니다. 문서는 서버로 전송되지 않습니다.

  • 형식: OpenAPI 3.0 · 3.1 · Swagger 2.0, YAML 과 JSON 모두 지원
  • 오류: 필수 필드 누락, 존재하지 않는 $ref, 경로 변수에 해당하는 in: path 파라미터 없음, operationId 중복, 올바르지 않은 응답 코드
  • 스키마: type: array 의 items 누락, required 가 properties 에 없음, 표준과 맞지 않는 format, 정의되지 않은 보안 스킴 참조
  • 권고(끌 수 있음): summary 없음, operationId 없음, 사용되지 않는 components, 인증 방식 미정의
  • 엔드포인트 표: 메서드·경로·operationId·응답 코드·태그와 줄 번호

💡 Tips

  • 경로의 {id} 마다 같은 이름의 in: path, required: true 파라미터가 있어야 합니다. 가장 흔한 오류입니다.
  • operationId 는 SDK 메서드 이름이 되므로 문서 전체에서 고유하게 정하세요.
  • 공통 응답과 스키마는 components 로 빼고 $ref 로 참조하면 문서가 짧아지고 검사하기 쉬워집니다.

자주 묻는 질문

Spectral 이나 공식 검증기와 같은가요?

자주 쓰는 구조·참조·규칙을 점검하는 빠른 검사기입니다. JSON Schema 전체 검증(unevaluatedProperties 등)은 하지 않으므로 배포 전에는 Spectral 같은 도구로 한 번 더 확인하세요.

외부 파일 $ref 도 따라가나요?

아니요. 한 문서 안의 #/ 로 시작하는 내부 참조만 확인합니다. 다른 파일을 가리키는 참조는 건너뜁니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
