ENV 비교 도구 — 누락·추가·변경된 환경 변수 찾기

두 .env 파일을 비교해 한쪽에만 있는 변수와 값이 달라진 변수를 표로 보여 주고, 빠진 키를 붙여 넣기 좋은 형태로 뽑아 줍니다.

사용 예시

🔍 B에 누락 1 · B에만 있음 1 · 값 다름 3 · 동일 2

입력 — 기준 파일 (A) — 예: .env.example

# app
NODE_ENV=development
PORT=3000
DATABASE_URL=postgres://user:pass@localhost:5432/app
REDIS_URL=redis://localhost:6379
JWT_SECRET=changeme
SENTRY_DSN=

입력 — 비교 파일 (B) — 예: .env

NODE_ENV=production
PORT=8080
DATABASE_URL=postgres://app:s3cret@db.internal:5432/app
JWT_SECRET=changeme
SMTP_HOST=smtp.example.com
SENTRY_DSN=

결과 — 비교 결과

변수 | 상태 | A | B
NODE_ENV | 값 다름 | development | production
PORT | 값 다름 | 3000 | 8080
DATABASE_URL | 값 다름 | postgres://user:pass@localhost:5432/app | postgres://app:s3cret@db.internal:5432/app
REDIS_URL | B에 누락 | redis://localhost:6379 | 
JWT_SECRET | 동일 | changeme | changeme
SENTRY_DSN | 동일 |  | 
SMTP_HOST | B에만 있음 |  | smtp.example.com

결과 — B에 없는 키 (붙여넣기용)

REDIS_URL=

이 도구로 할 수 있는 일

새 팀원이 프로젝트를 받았을 때, 혹은 배포 서버에 환경 변수를 옮길 때 가장 흔한 문제가 변수 하나가 빠져 앱이 죽는 것입니다. 기준 파일(A)과 실제 파일(B)을 붙여 넣으면 차이를 바로 확인할 수 있습니다.

  • B에 누락 / B에만 있음 / 값 다름 / 동일로 분류해 색으로 구분
  • export 접두사, 따옴표, 인라인 주석(# …), 여러 줄 값을 올바르게 파싱
  • "값 가리기"로 화면 공유 중에도 비밀 값을 노출하지 않고 비교
  • B에 없는 키를 KEY= 형태로 모아 바로 붙여 넣을 수 있게 제공
  • 중복 키나 형식에 맞지 않는 줄은 경고로 표시

💡 Tips

  • 기준 파일에는 보통 .env.example을 두고, 실제 .env와 비교해 누락만 확인하세요.
  • "값 변경도 비교"를 끄면 키 존재 여부만 확인합니다 (환경마다 값이 다른 파일 비교에 적합).
  • 비밀 키가 포함된 파일을 화면에 띄울 때는 "값 가리기"를 켜세요.

자주 묻는 질문

비교하는 .env 내용이 어딘가에 저장되나요?

아니요. 모든 처리는 브라우저에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다.

따옴표가 있는 값과 없는 값은 다르게 비교되나요?

아니요. KEY="a b"와 KEY=a b 처럼 따옴표 유무가 달라도 파싱된 실제 값이 같으면 같은 값으로 봅니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
