ULID 생성기 · 분석기

시간순으로 정렬되는 26자 식별자 ULID를 만들고, 이미 있는 ULID에서 생성 시각과 난수 부분을 읽어 냅니다.

사용 예시

✅ 입력 순서가 ULID 정렬(생성 시각) 순서와 같습니다

입력 — ULID (한 줄에 하나)

01ARZ3NDEKTSV4RRFFQ69G5FAV
01ARZ3NDEKTSV4RRFFQ69G5FAW
01HZX3Q8V5K9N2M4P7R6T1W0YB

결과 — 분석 결과

ULID | 생성 시각 (UTC) | Unix ms | 무작위 80비트 (hex)
01ARZ3NDEKTSV4RRFFQ69G5FAV | 2016-07-30T23:54:10.259Z | 1469922850259 | D6764C61EFB99302BD5B
01ARZ3NDEKTSV4RRFFQ69G5FAW | 2016-07-30T23:54:10.259Z | 1469922850259 | D6764C61EFB99302BD5C
01HZX3Q8V5K9N2M4P7R6T1W0YB | 2024-06-08T23:42:43.557Z | 1717890163557 | 9A6A2A12C7C1B41E03CB

이 도구로 할 수 있는 일

ULID는 앞 10자가 시각(밀리초), 뒤 16자가 난수인 26자 Crockford Base32 문자열입니다. 사전순으로 정렬하면 곧 시간순이 되어 UUID v4보다 DB 인덱스에 유리하고, URL에 쓰기에도 짧고 안전합니다.

  • 생성: 개수 지정, 같은 밀리초 안에서는 난수를 1씩 증가시키는 단조(monotonic) 모드, 소문자 옵션, 임의 시각 지정
  • 분석: ULID에서 생성 시각(UTC ISO, Unix ms)과 80비트 난수(16진수) 추출
  • 여러 ULID를 넣으면 입력 순서가 ULID 정렬 순서와 일치하는지 확인
  • I·L·O 같은 헷갈리는 문자는 자동으로 1·1·0으로 정정, 첫 글자가 7을 넘으면(48비트 초과) 오류로 안내
  • 난수는 crypto.getRandomValues로 만들어 예측할 수 없음

💡 Tips

  • 테스트 데이터를 만들 때는 시각을 지정해 생성하면 정렬 순서를 예측할 수 있습니다.
  • ULID는 대소문자를 구분하지 않지만 보통 대문자로 표기합니다.
  • 시간 정보가 노출되어도 괜찮은 곳에 쓰세요. ULID는 생성 시각을 숨기지 않습니다.

자주 묻는 질문

ULID와 UUID v7은 무엇이 다른가요?

둘 다 앞부분에 밀리초 시각을 가져 정렬됩니다. ULID는 26자 Base32 문자열이고, UUID v7은 36자 16진수 표기에 UUID 규격을 따라 기존 UUID 컬럼 타입을 그대로 쓸 수 있습니다.

단조 모드는 왜 필요한가요?

같은 밀리초에 여러 개를 만들면 순서가 뒤섞일 수 있습니다. 직전 난수에 1을 더해 만들면 같은 밀리초 안에서도 생성 순서가 보장됩니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
