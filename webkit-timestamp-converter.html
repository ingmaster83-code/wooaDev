WebKit(Chrome) · PRTime · Cocoa 타임스탬프 변환기

Chrome 쿠키·방문기록 DB의 1601년 기준 마이크로초 값, Firefox PRTime, Apple Core Data 초 값을 날짜로 바꾸고 서로 환산합니다.

사용 예시

✅ 3개 변환

입력 — 타임스탬프 또는 날짜 (한 줄에 하나)

13411234567890123
13300000000000000
2026-10-16T09:30:15.123456Z

결과 — 변환 결과

입력 | UTC (ISO 8601) | 값 (µs)
13411234567890123 | 2025-12-26T14:56:07.890123Z | 13411234567890123
13300000000000000 | 2022-06-18T04:26:40.000000Z | 13300000000000000
2026-10-16T09:30:15.123456Z | 2026-10-16T09:30:15.123456Z | 13436616615123456

이 도구로 할 수 있는 일

브라우저와 앱의 SQLite DB(Chrome의 Cookies·History, Safari, iOS 앱)에는 13300000000000000 같은 큰 정수나 7xxxxxxxx.xxx 같은 소수가 시각으로 들어 있습니다. 기준 에포크가 제각각이라 단순히 Unix 시간으로 읽으면 틀립니다.

  • Chrome/WebKit: 1601-01-01부터의 마이크로초 (쿠키 expires_utc, 방문 시각)
  • Firefox PRTime: 1970-01-01부터의 마이크로초 / Unix 마이크로초
  • Apple Cocoa(Core Data, NSDate): 2001-01-01부터의 초(소수 포함)
  • 어떤 기준으로 입력해도 UTC ISO(마이크로초)와 다른 기준 값들을 함께 보여 줌
  • 날짜를 넣으면 선택한 기준의 정수로 역변환

💡 Tips

  • Chrome 쿠키의 expires_utc 값이 0이면 세션 쿠키입니다.
  • 값의 자릿수로 기준을 짐작할 수 있습니다: 17자리 안팎=WebKit, 16자리=PRTime, 9자리 소수=Cocoa.
  • 결과가 1601년이나 1970년 같은 이상한 연도면 기준 선택이 틀린 것입니다.

자주 묻는 질문

Chrome이 1601년 기준을 쓰는 이유는?

Chrome은 Windows FILETIME과 같은 1601-01-01 에포크를 쓰되 100ns 대신 마이크로초 단위로 저장합니다. 그래서 Unix 마이크로초에 11644473600000000을 더한 값이 됩니다.

Cocoa 타임스탬프에 음수가 있나요?

2001-01-01 이전 시각은 음수입니다. 이 도구는 음수와 소수 값도 처리합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
