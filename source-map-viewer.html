소스 맵(.map) 뷰어 · 위치 변환기

소스 맵 JSON, data URI, sourceMappingURL 주석을 붙여 넣으면 소스 파일 목록과 VLQ 매핑을 풀어 보여 줍니다. 압축된 번들의 줄:열을 입력하면 원본 파일·줄·열·변수 이름과 주변 코드를 알려 주고, 반대로 원본 위치가 어느 번들 위치가 되는지도 찾습니다.

사용 예시

✅ 소스 맵 — 소스 2개, 매핑 14개

입력 — 소스 맵 (.map JSON, data: URI, 또는 sourceMappingURL 주석)

{
 "version": 3,
 "file": "bundle.js",
 "sourceRoot": "",
 "sources": [
  "src/util.ts",
  "src/app.ts"
 ],
 "sourcesContent": [
  "export function add(a: number, b: number) {\n  return a + b;\n}\n",
  "import { add } from './util';\nconst n = add(1, 2);\nconsole.log(n);\n"
 ],
 "names": [
  "add",
  "a",
  "b",
  "n",
  "console"
 ],
 "mappings": "AAAO,SAASA,IAAIC,EAAWC,GAC7B,OAAOD,CAAE,CAAEC,CACb;ACDA,IAAMC,EAAIH,SACVI,QAAQ"
}

결과 — 요약

버전: 3
생성 파일: bundle.js
sourceRoot: —
소스 파일 수: 2
이름(names) 수: 5
매핑 수: 14
생성 코드 줄 수 (매핑 기준): 2
소스 맵 크기: 432 B

결과 — 위치 변환 결과

생성 1:15 → src/util.ts:1:21  (a)   [가장 가까운 앞 매핑: 열 14]

>     1 | export function add(a: number, b: number) {
        |                     ^
      2 |   return a + b;
      3 | }

이 도구로 할 수 있는 일

운영 환경에서 난 압축 코드 오류의 원본 위치를 브라우저에서 바로 찾습니다. 소스 맵은 서버로 전송되지 않습니다.

  • 입력: .map JSON, data:application/json URI, //# sourceMappingURL=data:… 주석, )]}' 접두사, 인덱스 맵(sections)
  • 위치 변환: 스택 트레이스의 줄:열(1부터) → 원본 파일·줄·열·이름, 가장 가까운 앞 매핑과 주변 5줄 코드
  • 역변환: '파일:줄' → 그 줄이 만들어낸 번들 위치 목록
  • 표: 소스 파일별 매핑 수와 내용 크기, 매핑 목록(생성→원본)
  • 점검: version, 범위를 벗어난 소스·이름 인덱스, sourcesContent 누락/노출

💡 Tips

  • 브라우저 콘솔의 스택 트레이스 'bundle.js:1:15234' 의 줄:열을 그대로 넣으면 됩니다. 줄과 열 모두 1부터입니다.
  • 운영에 .map 을 공개하면서 sourcesContent 를 포함하면 원본 소스가 그대로 노출됩니다. 오류 추적 서비스에만 업로드하세요.
  • 열 번호가 매핑과 정확히 맞지 않으면 직전 매핑을 사용합니다. 표준과 같은 동작입니다.

자주 묻는 질문

원본 코드가 소스 맵에 없으면요?

sourcesContent 가 없으면 파일 이름·줄·열만 알려 줍니다. 원본 파일은 별도로 열어서 해당 줄을 확인하세요.

외부 .map 파일 경로만 있으면요?

경로의 파일을 직접 열어 내용을 붙여 넣으세요. 이 도구는 네트워크에서 파일을 가져오지 않습니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
