OpenAPI 비교 · 호환성 검사

이전과 새 OpenAPI 문서를 붙여 넣으면 엔드포인트·파라미터·요청 본문·응답 스키마를 비교해 깨짐, 주의, 호환 변경으로 분류하고 시맨틱 버전 증가(major·minor·patch)를 제안합니다. 요청과 응답은 방향에 따라 다르게 판정합니다.

사용 예시

⛔ 호환성을 깨는 변경 13건 → major 버전

입력 — 이전 OpenAPI (YAML/JSON)

openapi: 3.0.3
info: { title: Pets, version: 1.0.0 }
paths:
  /pets:
    get:
      operationId: listPets
      parameters:
        - { name: limit, in: query, schema: { type: integer } }
        - { name: status, in: query, schema: { type: string, enum: [open, sold, pending] } }
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema: { type: array, items: { $ref: "#/components/schemas/Pet" } }
    post:
      operationId: addPet
      requestBody:
        content: { application/json: { schema: { $ref: "#/components/schemas/NewPet" } } }
      responses: { "201": { description: Created } }
  /pets/{id}:
    get:
      operationId: getPet
      parameters: [{ name: id, in: path, required: true, schema: { type: integer } }]
…

입력 — 새 OpenAPI (YAML/JSON)

openapi: 3.0.3
info: { title: Pets, version: 1.1.0 }
paths:
  /pets:
    get:
      operationId: listPets
      parameters:
        - { name: limit, in: query, required: true, schema: { type: integer } }
        - { name: status, in: query, schema: { type: string, enum: [open, sold] } }
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema: { type: array, items: { $ref: "#/components/schemas/Pet" } }
    post:
      operationId: addPet
      requestBody:
        required: true
        content: { application/json: { schema: { $ref: "#/components/schemas/NewPet" } } }
      responses: { "201": { description: Created } }
  /pets/{id}:
    get:
      operationId: getPet
      parameters: [{ name: id, in: path, required: true, schema: { type: string } }]
…

결과 — 변경 사항

판정 | 위치 | 변경
⛔ 깨짐 | GET /pets query:limit | 필수로 변경
⛔ 깨짐 | GET /pets query:status | enum 값 제거: pending
⛔ 깨짐 | GET /pets 200[].name | 선택으로 변경
⛔ 깨짐 | GET /pets 200[].tag | 응답 필드 제거
⛔ 깨짐 | GET /pets 200[].kind | enum 값 추가: bird (클라이언트가 모르는 값을 받을 수 있음)
⛔ 깨짐 | POST /pets requestBody | 요청 본문이 필수로 변경
⛔ 깨짐 | POST /pets requestBody.name | maxLength 50 → 20
⛔ 깨짐 | POST /pets requestBody.kind | 요청 필드 추가 (필수)
⛔ 깨짐 | GET /pets/{id} path:id | 타입 integer → string
⛔ 깨짐 | GET /pets/{id} 200.name | 선택으로 변경
⛔ 깨짐 | GET /pets/{id} 200.tag | 응답 필드 제거
⛔ 깨짐 | GET /pets/{id} 200.kind | enum 값 추가: bird (클라이언트가 모르는 값을 받을 수 있음)
⛔ 깨짐 | DELETE /pets/{id} | 메서드 제거
⚠️ 주의 | GET /pets/{id} 404 | 응답 제거
ℹ️ 참고 | info.version | 1.0.0 → 1.1.0
✅ 호환 | GET /pets 200[].owner | 응답 필드 추가
✅ 호환 | GET /pets/{id} 200.owner | 응답 필드 추가
✅ 호환 | GET /owners | 엔드포인트 추가

결과 — 요약

⛔ 호환성을 깨는 변경 13건 · 주의 1건 · 호환 변경 3건
권장 버전 증가: major (MAJOR — 기존 클라이언트가 깨질 수 있음)
판정 기준: 요청(클라이언트→서버)은 제약이 강해지면 깨짐, 응답(서버→클라이언트)은 보장이 약해지면 깨집니다. 문서에 쓰인 계약만 비교하며 실제 서버 동작은 알 수 없습니다

이 도구로 할 수 있는 일

API 변경이 기존 클라이언트를 깨뜨리는지 배포 전에 확인합니다. 문서는 서버로 전송되지 않습니다.

  • 깨짐: 엔드포인트·응답 필드 제거, 필수 요청 파라미터 추가, 요청 타입 강화, 응답 타입 변경, enum 값 제거(요청)
  • 주의: 응답 코드 추가, enum 값 추가(응답), 파라미터 위치 변경
  • 호환: 엔드포인트 추가, 선택 파라미터 추가, 응답 필드 추가, 설명 변경
  • 요청(클라이언트→서버)과 응답(서버→클라이언트)을 방향에 맞춰 판정하고 $ref 를 풀어 비교
  • major·minor·patch 권장 버전 증가와 '깨짐·주의만' 보기

💡 Tips

  • 요청은 제약이 강해지면(필수 추가) 깨지고, 응답은 보장이 약해지면(필드 제거) 깨집니다. 방향이 반대입니다.
  • 응답에 enum 값을 추가하면 클라이언트 switch 가 처리하지 못할 수 있어 '주의'로 분류합니다.
  • CI 에서 이 비교 결과가 깨짐이면 major 버전을 올리거나 /v2 경로를 만드는 기준으로 쓰세요.

자주 묻는 질문

실제 서버 동작도 비교하나요?

아니요. 문서에 적힌 계약만 비교합니다. 문서와 다르게 동작하는 서버의 변화는 알 수 없습니다.

oasdiff 와 같은 결과인가요?

비슷한 분류 원칙을 쓰지만 모든 규칙을 구현하지는 않았습니다. 핵심 호환성 문제를 빠르게 확인하는 용도입니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
