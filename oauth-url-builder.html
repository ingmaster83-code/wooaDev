OAuth 인가 URL 생성기 · 점검기

response_type, scope, state, nonce, PKCE 파라미터가 들어간 OAuth 2.0 / OpenID Connect 인가 요청 URL을 만들고, 이미 가진 URL의 보안 문제를 점검합니다.

사용 예시

🔍 점검할 항목 4개

입력 — 분석할 인가 요청 URL

https://accounts.example.com/oauth2/authorize?response_type=token&client_id=abc123&redirect_uri=http%3A%2F%2Fapp.example.com%2Fcb&scope=openid%20email

입력 — 인가 엔드포인트

https://accounts.example.com/oauth2/authorize

입력 — client_id

my-client

입력 — redirect_uri

https://app.example.com/callback

결과 — 인가 URL

https://accounts.example.com/oauth2/authorize?response_type=token&client_id=abc123&redirect_uri=http%3A%2F%2Fapp.example.com%2Fcb&scope=openid%20email

결과 — 파라미터 설명

파라미터 | 값 | 설명
response_type | token | 응답 유형: code=인가 코드, token/id_token=암시적 흐름
client_id | abc123 | 앱을 식별하는 ID
redirect_uri | http://app.example.com/cb | 인가 후 돌아올 주소 (사전 등록값과 정확히 일치해야 함)
scope | openid email | 요청하는 권한 목록

이 도구로 할 수 있는 일

로그인 연동에서 가장 자주 틀리는 부분이 인가 요청 URL입니다. 파라미터를 인코딩해 URL을 만들고, 붙여 넣은 URL은 항목별로 설명하고 위험 요소를 알려 줍니다.

  • 만들기: 엔드포인트, client_id, redirect_uri, scope, response_type(code/id_token/hybrid), prompt, 추가 파라미터
  • state와 nonce는 비워 두면 안전한 난수로 자동 생성, PKCE code_challenge(S256) 추가
  • 점검: state 누락, 암시적 흐름(token), PKCE 없음, nonce 없는 id_token, http redirect_uri, 와일드카드
  • 각 파라미터의 의미를 표로 설명
  • URL 인코딩(%20 등)을 올바르게 처리

💡 Tips

  • redirect_uri는 제공자에 등록한 값과 글자 하나까지 같아야 합니다 (끝의 슬래시 포함).
  • state는 로그인 시작 때 만든 값을 세션에 저장해 두었다가 콜백에서 반드시 비교하세요 (CSRF 방지).
  • scope에 openid가 있으면 OIDC 요청입니다. id_token을 받는다면 nonce도 검증해야 합니다.

자주 묻는 질문

response_type=token 은 왜 위험한가요?

암시적 흐름은 액세스 토큰이 URL 조각으로 브라우저 기록·리퍼러에 노출될 수 있어 OAuth 2.1에서 제거되었습니다. 인가 코드 + PKCE를 쓰세요.

state와 nonce는 무엇이 다른가요?

state는 요청과 콜백을 짝지어 CSRF를 막고, nonce는 발급된 ID 토큰이 이 요청에 대한 것인지 확인해 재전송 공격을 막습니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
