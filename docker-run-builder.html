docker run 명령어 생성기 + docker-compose 변환

이미지, 포트, 볼륨, 환경 변수, 자원 제한, 보안 옵션을 입력해 docker run 명령어를 만들고 같은 설정의 docker-compose.yml을 함께 만들어 줍니다. 위험한 설정은 바로 경고합니다.

사용 예시

✅ docker run 명령어를 만들었습니다

입력 — 포트 (한 줄에 하나: 호스트:컨테이너)

8080:80
127.0.0.1:5432:5432
53:53/udp

입력 — 볼륨 (한 줄에 하나: 원본:대상[:ro])

./html:/usr/share/nginx/html:ro
pgdata:/var/lib/postgresql/data

입력 — 환경 변수 (KEY=값, 한 줄에 하나)

TZ=Asia/Seoul
POSTGRES_PASSWORD=changeme

결과 — docker run 명령어

docker run \
  -d \
  --name web \
  --restart unless-stopped \
  -p 8080:80 \
  -p 127.0.0.1:5432:5432 \
  -p 53:53/udp \
  -v "$(pwd)/html:/usr/share/nginx/html:ro" \
  -v pgdata:/var/lib/postgresql/data \
  -e TZ=Asia/Seoul \
  -e POSTGRES_PASSWORD=changeme \
  nginx:1.27-alpine

결과 — docker-compose.yml 변환

services:
  web:
    image: nginx:1.27-alpine
    container_name: web
    restart: unless-stopped
    ports:
      - "8080:80"
      - "127.0.0.1:5432:5432"
      - "53:53/udp"
    volumes:
      - ./html:/usr/share/nginx/html:ro
      - pgdata:/var/lib/postgresql/data
    environment:
      TZ: "Asia/Seoul"
      POSTGRES_PASSWORD: "changeme"

volumes:
  pgdata:

이 도구로 할 수 있는 일

옵션이 많은 docker run 을 폼으로 채우면 한 줄 명령(줄바꿈된 형식)과 docker-compose.yml 이 함께 나옵니다. 처음 컨테이너를 띄우거나 compose 로 옮길 때 편합니다.

  • 입력: 이미지, 이름, -d/-it/--rm, 재시작 정책, 네트워크, 포트(호스트:컨테이너[/udp]), 볼륨, 환경 변수, 사용자, 작업 디렉터리, 메모리·CPU, 읽기 전용, cap-drop, no-new-privileges, privileged
  • 출력: 줄바꿈된 docker run 명령어, 동일한 docker-compose.yml(포트·볼륨·네트워크·named volume 포함)
  • 포트 검증(1~65535, 바인딩 IP), 상대 경로 볼륨을 $(pwd)/… 로 변환
  • 🚨 MySQL·PostgreSQL·Redis 같은 DB 포트의 0.0.0.0 공개, docker.sock 마운트, --privileged, 호스트 네트워크 경고
  • 비밀번호 환경 변수, root 실행, 메모리 제한 없음, latest 태그, -d 와 --rm 충돌 점검

💡 Tips

  • 외부 접근이 필요 없는 포트는 127.0.0.1:5432:5432 처럼 로컬로만 바인딩하세요. Linux에서 -p 로 연 포트는 ufw 규칙을 우회할 수 있습니다.
  • 비밀번호는 -e 로 직접 쓰지 말고 --env-file 이나 Docker secrets 를 사용하세요. docker inspect 로 노출됩니다.
  • 운영 컨테이너에는 --user, --memory, --read-only, --cap-drop ALL 을 기본으로 고려하세요.

자주 묻는 질문

docker run 에서 ./ 상대 경로 볼륨이 안 돼요.

docker run -v 는 절대 경로만 받습니다. $(pwd)/경로 로 쓰면 됩니다 (PowerShell 은 ${PWD}). compose 에서는 ./ 를 그대로 쓸 수 있습니다.

--restart 와 --rm 을 같이 쓸 수 없나요?

Docker가 거부합니다. --rm 은 종료 시 컨테이너를 지우는 옵션이라 재시작 정책과 의미가 충돌합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
