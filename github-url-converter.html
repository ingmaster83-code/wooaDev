GitHub URL 변환기 — blob · raw · clone · CDN

GitHub 파일·폴더·저장소 주소를 붙여 넣으면 Blob, Raw, jsDelivr CDN, API, github.dev, Blame, History, ZIP, HTTPS/SSH clone 주소를 한꺼번에 만들어 줍니다.

사용 예시

✅ 4개 주소를 변환했습니다

입력 — GitHub 주소 (한 줄에 하나)

https://github.com/vercel/next.js/blob/canary/packages/next/src/server/next.ts#L10-L20
https://raw.githubusercontent.com/facebook/react/main/README.md
git@github.com:torvalds/linux.git
https://github.com/microsoft/vscode/tree/main/src/vs

이 도구로 할 수 있는 일

README의 이미지 링크, 스크립트 다운로드, CDN 사용 등 상황마다 필요한 주소 형태가 다릅니다. 하나만 붙여 넣으면 모두 만들어 줍니다.

  • 입력: github.com blob/tree/raw 주소, raw.githubusercontent.com 주소, git@github.com:… ssh 주소, 저장소 주소, github.io
  • 출력: 저장소·HTTPS/SSH clone·GitHub CLI, Blob, Raw(두 가지 형태), jsDelivr CDN, GitHub API contents, github.dev, Blame, History, ZIP
  • 줄 번호 앵커(#L10-L20) 유지, 경로의 특수문자 인코딩
  • 슬래시가 들어간 브랜치명(feature/x)은 구성 개수 옵션으로 경계 지정, 참조(브랜치·태그·SHA)를 다른 값으로 교체
  • 브랜치 이름 링크는 내용이 바뀌므로 커밋 SHA 퍼마링크를 권장

💡 Tips

  • 문서나 이슈에 코드를 인용할 때는 브랜치 대신 커밋 SHA 퍼마링크(GitHub에서 y 키)를 쓰세요.
  • jsDelivr CDN은 캐시되어 최신 커밋이 늦게 반영될 수 있습니다. 태그나 SHA로 고정해 쓰세요.
  • 비공개 저장소의 Raw 주소는 토큰이 필요합니다. 주소를 그대로 공유하지 마세요.

자주 묻는 질문

blob 과 raw 의 차이는 무엇인가요?

blob 은 GitHub 웹 화면(구문 강조, 버튼 포함)이고, raw 는 파일 내용만 그대로 내려받는 주소입니다. 스크립트 실행이나 이미지 삽입에는 raw 를 씁니다.

feature/x 같은 브랜치 주소가 이상하게 나눠져요.

URL만으로는 브랜치와 경로의 경계를 알 수 없어서입니다. '브랜치 이름의 / 개수 + 1' 옵션을 2 로 바꾸세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
