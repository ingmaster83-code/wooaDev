MongoDB Extended JSON (EJSON) 변환기

mongoexport·Compass 가 내보내는 확장 JSON 의 $oid, $date, $numberLong 같은 타입 표기를 Canonical(타입 보존), Relaxed(읽기 쉬움), 단순 JSON 으로 서로 바꿉니다.

사용 예시

✅ Relaxed 로 변환했습니다

입력 — MongoDB 확장 JSON (EJSON)

{
  "_id": {"$oid": "507f1f77bcf86cd799439011"},
  "createdAt": {"$date": {"$numberLong": "1760000000000"}},
  "count": {"$numberInt": "42"},
  "big": {"$numberLong": "9007199254740993"},
  "price": {"$numberDouble": "19.99"},
  "amount": {"$numberDecimal": "12345.6789"},
  "uid": {"$uuid": "123e4567-e89b-12d3-a456-426614174000"},
  "file": {"$binary": {"base64": "aGVsbG8=", "subType": "00"}},
  "re": {"$regularExpression": {"pattern": "^a", "options": "i"}},
  "name": "Kim"
}

결과 — 변환 결과

결과 — 참고

64비트 정수 9007199254740993 는 JSON 숫자로 정밀도를 잃을 수 있어 $numberLong 으로 유지했습니다
Relaxed 에서는 int32/int64/double 이 보통 JSON 숫자로 표시되어 원래 타입을 구분할 수 없습니다. 타입 보존이 필요하면 Canonical 을 쓰세요

이 도구로 할 수 있는 일

MongoDB 데이터를 JSON 으로 주고받을 때 ObjectId·날짜·64비트 정수가 어떻게 표현되는지 헷갈리는 일을 줄여 줍니다.

  • Relaxed: 정수·실수는 JSON 숫자로, 날짜는 ISO 문자열로 표시(읽기 쉬움)
  • Canonical: 모든 숫자 타입을 $numberInt/$numberLong/$numberDouble 로 명시해 타입을 보존
  • 단순 JSON: $oid 를 문자열로, 날짜를 ISO 로 바꿔 타입 정보를 제거
  • 지원: $oid, $date, $numberInt/Long/Double/Decimal, $uuid, $binary, $regularExpression, $timestamp, $minKey/$maxKey
  • JavaScript 안전 정수를 넘는 64비트 정수는 정밀도를 지키기 위해 $numberLong 유지

💡 Tips

  • 타입이 중요한 이관·백업에는 Canonical, 사람이 읽는 로그에는 Relaxed 를 쓰세요.
  • 단순 JSON 으로 바꿔 다시 넣으면 ObjectId·날짜가 문자열이 되니 가져오기에는 쓰지 마세요.
  • mongoimport 는 Canonical 과 Relaxed 를 모두 읽을 수 있습니다.

자주 묻는 질문

Relaxed 와 Canonical 중 무엇을 써야 하나요?

다른 시스템과 정확한 타입을 주고받아야 하면 Canonical, 사람이 읽거나 API 응답이면 Relaxed 가 좋습니다.

왜 $numberLong 이 문자열인가요?

64비트 정수는 JSON 숫자(IEEE 754 double)로 표현하면 9,007,199,254,740,992 이상에서 정밀도를 잃기 때문입니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
