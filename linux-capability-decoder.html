Linux capability 디코더 · 인코더

/proc/PID/status 의 CapEff 같은 16진수 값을 CAP_ 이름과 설명, 위험도로 풀고, 반대로 capability 이름 목록을 마스크와 docker --cap-add, Kubernetes securityContext 로 바꿉니다.

사용 예시

✅ capability 14개 · 최고 위험도: 높음

입력 — capability 값 (16진수 마스크 또는 CAP_ 이름 목록)

00000000a80425fb

결과 — capability 목록

비트 | 이름 | 권한 | 위험도
0 | CAP_CHOWN | 파일 소유자(uid/gid)를 임의로 변경 | 낮음 · Docker 기본
1 | CAP_DAC_OVERRIDE | 파일 읽기·쓰기·실행 권한 검사를 무시 | 중간 · Docker 기본
3 | CAP_FOWNER | 파일 소유자만 가능한 작업(chmod 등)을 수행 | 낮음 · Docker 기본
4 | CAP_FSETID | setuid/setgid 비트 유지 | 낮음 · Docker 기본
5 | CAP_KILL | 다른 사용자 프로세스에 시그널 전송 | 낮음 · Docker 기본
6 | CAP_SETGID | GID 를 임의로 변경 | 중간 · Docker 기본
7 | CAP_SETUID | UID 를 임의로 변경 (root 로 전환 가능) | 높음 · Docker 기본
8 | CAP_SETPCAP | 다른 프로세스의 capability 변경 | 중간 · Docker 기본
10 | CAP_NET_BIND_SERVICE | 1024 미만 포트에 바인딩 | 낮음 · Docker 기본
13 | CAP_NET_RAW | RAW·PACKET 소켓 (ping, 패킷 스니핑·위조) | 중간 · Docker 기본
18 | CAP_SYS_CHROOT | chroot 실행 | 중간 · Docker 기본
27 | CAP_MKNOD | 특수 파일(장치 노드) 생성 | 중간 · Docker 기본
29 | CAP_AUDIT_WRITE | 커널 감사 로그에 기록 | 낮음 · Docker 기본
31 | CAP_SETFCAP | 파일에 capability 설정 | 중간 · Docker 기본

결과 — 변환 결과

CapEff/CapPrm  : 00000000a80425fb
0x             : 0xa80425fb
개수           : 14

getpcaps / capsh : cap_chown,cap_dac_override,cap_fowner,cap_fsetid,cap_kill,cap_setgid,cap_setuid,cap_setpcap,cap_net_bind_service,cap_net_raw,cap_sys_chroot,cap_mknod,cap_audit_write,cap_setfcap

# Docker/Podman
docker run --cap-drop ALL --cap-add CHOWN --cap-add DAC_OVERRIDE --cap-add FOWNER --cap-add FSETID --cap-add KILL --cap-add SETGID --cap-add SETUID --cap-add SETPCAP --cap-add NET_BIND_SERVICE --cap-add NET_RAW --cap-add SYS_CHROOT --cap-add MKNOD --cap-add AUDIT_WRITE --cap-add SETFCAP …
# Docker 기본 capability 14개와 동일합니다

# Kubernetes securityContext
securityContext:
  capabilities:
    drop: ["ALL"]
    add: ["CHOWN", "DAC_OVERRIDE", "FOWNER", "FSETID", "KILL", "SETGID", "SETUID", "SETPCAP", "NET_BIND_SERVICE", "NET_RAW", "SYS_CHROOT", "MKNOD", "AUDIT_WRITE", "SETFCAP"]

이 도구로 할 수 있는 일

컨테이너가 가진 권한을 점검할 때 grep Cap /proc/self/status 로 나온 16진수는 사람이 읽을 수 없습니다. 이 도구가 이름과 의미로 풀어 줍니다.

  • 입력: 16진수 마스크(0x 접두사 가능) 또는 CAP_ 이름 목록(접두사 생략·소문자·쉼표 가능, ALL 지원)
  • 출력: 비트 번호, 이름, 권한 설명, 위험도, Docker 기본 capability 여부
  • 변환 결과: CapEff 마스크, getpcaps/capsh 이름, docker run --cap-drop ALL --cap-add …, Kubernetes securityContext
  • Docker 기본 14개와의 차이(추가/제외) 표시
  • 🚨 CAP_SYS_ADMIN, SYS_MODULE, SYS_PTRACE, SYS_RAWIO, DAC_READ_SEARCH, MAC_OVERRIDE 같은 위험한 권한 경고

함께 쓰면 좋은 도구

💡 Tips

  • 필요한 capability 만 남기려면 --cap-drop ALL 로 모두 버린 뒤 필요한 것만 --cap-add 하세요.
  • 1024 미만 포트만 열면 되는 서비스라면 NET_BIND_SERVICE 하나로 충분합니다.
  • CAP_SYS_ADMIN 은 사실상 root 에 가까워 컨테이너 탈출에 자주 쓰입니다. --privileged 못지않게 위험합니다.

자주 묻는 질문

CapInh, CapPrm, CapEff, CapBnd, CapAmb 는 무엇이 다른가요?

Eff(유효)가 지금 실제로 쓸 수 있는 권한이고, Prm(허용)은 가질 수 있는 상한, Bnd(경계)는 자식이 얻을 수 있는 최대치입니다. 보통 CapEff 를 보면 됩니다.

0000003fffffffff 는 어떤 의미인가요?

비트 0~37(38개)이 켜진 값으로, 5.8 이전 커널에서 root 프로세스가 가지는 전체 권한 마스크입니다. 최신 커널은 비트 40까지 있어 전체가 000001ffffffffff 입니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
