LLM 구조화 출력 스키마 검사기

JSON Schema 를 붙여 넣으면 OpenAI Structured Outputs(strict)나 Gemini responseSchema 가 지원하지 않는 부분을 찾고, 필요하면 additionalProperties: false, 모든 속성 required, 선택 값의 null 허용 같은 변환을 적용한 요청용 JSON 을 만들어 줍니다.

사용 예시

⛔ 호환되지 않는 부분 11건 · 경고 1건

입력 — JSON Schema (또는 response_format / 도구 정의 전체)

결과 — 점검 결과

⛔ 모든 object 에 additionalProperties: false 가 필요합니다
⛔ strict 모드는 모든 속성을 required 에 넣어야 합니다. 빠진 속성: email, role, address, tags, payment (선택 값은 ["타입","null"] 로 표현)
⛔ #.properties.name.minLength: OpenAI strict 모드는 "minLength" 키워드를 지원하지 않습니다
⛔ #.properties.address: 모든 object 에 additionalProperties: false 가 필요합니다
⛔ #.properties.address: strict 모드는 모든 속성을 required 에 넣어야 합니다. 빠진 속성: zip (선택 값은 ["타입","null"] 로 표현)
⛔ #.properties.tags.uniqueItems: OpenAI strict 모드는 "uniqueItems" 키워드를 지원하지 않습니다
⛔ #.properties.payment.oneOf: OpenAI strict 모드는 "oneOf" 키워드를 지원하지 않습니다
⛔ #.properties.payment.oneOf[0]: 모든 object 에 additionalProperties: false 가 필요합니다
⛔ #.properties.payment.oneOf[0]: strict 모드는 모든 속성을 required 에 넣어야 합니다. 빠진 속성: card (선택 값은 ["타입","null"] 로 표현)
⛔ #.properties.payment.oneOf[1]: 모든 object 에 additionalProperties: false 가 필요합니다
⛔ #.properties.payment.oneOf[1]: strict 모드는 모든 속성을 required 에 넣어야 합니다. 빠진 속성: iban (선택 값은 ["타입","null"] 로 표현)
⚠️ #.properties.payment: type 이 없습니다. 모든 스키마에 type(또는 anyOf/enum)을 명시하세요
ℹ️ description 이 없는 속성이 8개 있습니다. 모델은 설명을 보고 값을 채우므로 속성마다 description 을 쓰면 정확도가 올라갑니다
ℹ️ 변환에서 지원하지 않는 키워드를 제거했습니다: minLength, uniqueItems, oneOf — 제약은 프롬프트의 description 이나 후처리 검증으로 옮기세요
ℹ️ 선택 속성은 필수로 바꾸고 ["타입","null"] 로 null 을 허용했습니다. 모델이 값을 모르면 null 을 채웁니다
ℹ️ 규칙은 공개 문서를 기준으로 하며 모델·시기에 따라 지원 범위가 넓어질 수 있습니다. 최종 확인은 실제 API 호출로 하세요

이 도구로 할 수 있는 일

모델 API 에 보내기 전에 스키마가 거부되지 않는지 확인합니다. 스키마는 서버로 전송되지 않습니다.

  • 대상: OpenAI Structured Outputs(strict), Google Gemini responseSchema, 일반 점검
  • OpenAI strict: 모든 object 의 additionalProperties: false, 모든 속성 required, 지원되지 않는 키워드, 중첩 깊이와 속성 수 한도
  • Gemini: 지원 키워드 외의 항목, additionalProperties, $ref 처리 차이
  • 자동 변환: 선택 속성을 필수 + [타입, null] 로 바꾸고 요청에 바로 쓰는 response_format 형태로 출력
  • 변환 결과를 다시 검사해 호환 여부 확인, 객체·속성·깊이 통계

💡 Tips

  • strict 모드에서는 선택 속성이 없습니다. 값이 없을 수 있으면 type: ["string", "null"] 로 표현합니다.
  • 스키마가 깊거나 속성이 많으면 응답이 느려지고 한도에 걸릴 수 있으니 필요한 필드만 남기세요.
  • enum 과 description 을 명확히 적으면 모델이 값을 정확히 채울 가능성이 높아집니다.

자주 묻는 질문

규칙이 최신인가요?

공개 문서를 기준으로 하며 모델과 시기에 따라 지원 범위가 넓어질 수 있습니다. 최종 확인은 실제 API 호출로 하세요.

minimum·pattern 같은 제약은요?

공급자와 모델에 따라 무시되거나 거부될 수 있습니다. 경고가 나오면 값 검증은 응답을 받은 뒤 애플리케이션에서 하는 것이 안전합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
