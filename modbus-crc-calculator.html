Modbus RTU CRC-16 계산기

01 03 00 00 00 0A 같은 Modbus RTU 프레임 바이트를 넣으면 CRC-16/MODBUS 를 계산해 붙이거나, CRC 가 포함된 프레임이 올바른지 검증합니다. 슬레이브 주소·기능 코드·레지스터 주소를 풀어서 보여 줍니다.

사용 예시

✅ CRC-16/MODBUS 처리 완료

입력 — Modbus RTU 프레임 (16진수 바이트)

01 03 00 00 00 0A

결과 — 결과

항목 | 값
CRC-16/MODBUS 값 | 0xCDC5
전송 순서 (낮은 바이트 먼저) | C5 CD
전체 프레임 | 01 03 00 00 00 0A C5 CD
슬레이브 주소 | 1
기능 코드 | 3 (0x03) — Read Holding Registers
요청 해석 | 시작 주소 0, 개수 10 (프로토콜 주소, 레지스터 번호 40001)

결과 — 완성된 프레임

01 03 00 00 00 0A C5 CD

이 도구로 할 수 있는 일

PLC·인버터·센서와 시리얼 통신 중 프레임을 직접 만들거나 로그의 CRC 가 맞는지 확인할 때 씁니다. 모든 계산은 브라우저에서 이루어집니다.

  • 계산: 초기값 0xFFFF, 반사 다항식 0xA001, 결과를 낮은 바이트 → 높은 바이트 순으로 붙임
  • 검증: 마지막 두 바이트를 CRC 로 보고 재계산해 일치 여부 표시 (전체 프레임의 CRC 는 0x0000)
  • 해석: 슬레이브 주소(0은 브로드캐스트), 기능 코드 01·02·03·04·05·06·0F·10, 시작 주소와 수량, 바이트 수
  • 예외 응답(기능 코드 + 0x80)과 예외 코드 설명
  • 16진수 입력은 공백·0x·콤마가 섞여도 허용

💡 Tips

  • CRC 는 낮은 바이트(CRC Lo)가 먼저 전송됩니다. 순서를 바꾸면 장치가 응답하지 않습니다.
  • Modbus TCP 는 CRC 를 사용하지 않습니다. RTU 시리얼 전용입니다.
  • 레지스터 주소는 문서에 따라 0부터 또는 1부터(40001) 표기하니 장치 매뉴얼을 확인하세요.

자주 묻는 질문

CRC 결과가 장비와 다르면요?

CRC 계산 대상에는 슬레이브 주소부터 데이터 끝까지가 포함되고 CRC 자신은 제외됩니다. 입력에 CRC 가 이미 들어 있지 않은지 확인하세요.

0xA001 은 무슨 값인가요?

다항식 0x8005 를 비트 반전한 값으로, 오른쪽 시프트 방식 구현에서 쓰이는 표현입니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
