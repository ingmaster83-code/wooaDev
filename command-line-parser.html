명령줄 · PATH · 환경 변수 분석기

복잡한 셸 명령줄을 프로그램, 인수, 앞에 붙은 환경 변수, 파이프, 리디렉션으로 나눠 보여 주고, PATH 변수의 중복·위험 항목과 환경 변수 목록의 오류를 점검합니다.

사용 예시

✅ 명령 3개로 분해했습니다

입력 — 명령줄

API_KEY=abc123 NODE_ENV=production curl -sS -H "Authorization: Bearer $TOKEN" 'https://api.example.com/v1/items?limit=10' | jq '.items[] | .name' > names.txt 2>&1 && echo "done: $(date +%F)"

입력 — PATH 값

/usr/local/bin:/usr/bin:/bin:/usr/local/bin:./node_modules/.bin::~/bin:/opt/tools/

입력 — 환경 변수 (KEY=VALUE, export 가능)

export NODE_ENV=production
DATABASE_URL="postgres://user:pa ss@db:5432/app"
API_TOKEN='abc.def'
PORT=3000
PORT=8080
# comment
1BAD=nope
empty=

결과 — 분석 결과

# | 프로그램 | 인수 (⏐ 로 구분) | 앞에 붙은 환경 변수 | 리디렉션 | 다음 연결
1 | curl | -sS ⏐ -H ⏐ Authorization: Bearer $TOKEN ⏐ https://api.example.com/v1/items?limit=10 | API_KEY=abc123, NODE_ENV=production | — | 파이프 (출력 → 다음 입력)
2 | jq | .items[] | .name | — | > names.txt (덮어쓰기), 2>&1  (stderr → stdout) | 앞이 성공하면 다음 실행
3 | echo | done: $(date +%F) | — | — | —

이 도구로 할 수 있는 일

길고 따옴표가 섞인 명령을 읽거나 스크립트에 옮기기 전에 구조를 확인하세요. 입력은 브라우저에서만 처리되며 실행되지 않습니다.

  • 명령줄: POSIX 따옴표('…', "…", $'…', \), 환경 변수 접두사, 파이프(|, |&), 연결(&&, ||, ;, &), 리디렉션(>, >>, <, 2>, 2>&1, &>), 하위 셸
  • 경고: 따옴표 없는 $변수(단어 분리·글로빙), 명령 치환, rm -rf, chmod 777, curl | sh, eval, 2>&1 순서 오류
  • Windows 규칙(CommandLineToArgvW)으로 인수 분리도 지원
  • PATH: 중복, 빈 항목(현재 디렉터리), 상대 경로, ~ 사용, 끝 슬래시 점검과 정리된 export 문 생성
  • 환경 변수: KEY=VALUE/export/.env 정리, 중복·잘못된 이름·비밀 값 표시, export·.env·docker -e·JSON 출력

💡 Tips

  • PATH 의 빈 항목(::)이나 . 은 현재 폴더를 뜻해 악성 실행 파일 실행 위험이 있습니다.
  • 스크립트에서는 "$변수" 처럼 항상 따옴표로 감싸세요. 공백이 있는 값이 여러 인수로 쪼개지는 것을 막습니다.
  • 2>&1 은 > 파일 뒤에 써야 합니다: command > out.log 2>&1.

자주 묻는 질문

이 도구가 명령을 실행하나요?

아니요. 문자열을 분석만 하고 실행하지 않습니다. 변수 확장이나 명령 치환도 계산하지 않고 그대로 표시합니다.

PATH 앞쪽과 뒤쪽 중 어느 쪽이 우선인가요?

앞쪽 항목이 먼저 검색됩니다. 같은 이름의 프로그램이 여러 곳에 있으면 첫 번째가 실행되므로 which -a 로 확인하세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
