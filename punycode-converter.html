퓨니코드(Punycode) 변환기 — 한글 도메인 ↔ xn--

한글도메인.한국 같은 국제화 도메인 이름을 xn-- 로 시작하는 ASCII Punycode로, 반대로 Punycode를 원래 글자로 바꿉니다.

사용 예시

✅ 6개 변환

입력 — 도메인 (한 줄에 하나)

한글도메인.한국
bücher.example
例え.jp
xn--bcher-kva.example
xn--e1afmkfd.xn--p1ai
😀.fm

이 도구로 할 수 있는 일

도메인 이름 시스템(DNS)은 ASCII만 허용하기 때문에 한글·한자·키릴 문자가 든 도메인은 xn-- 로 시작하는 Punycode로 바꿔 등록·조회합니다. DNS 설정이나 인증서(SAN)에는 이 형태를 써야 합니다.

  • 유니코드 → Punycode: 각 레이블을 정규화(NFKC)·소문자화한 뒤 RFC 3492로 인코딩 (한국 → xn--3e0b707e)
  • Punycode → 유니코드: xn-- 레이블을 원래 글자로 복원, 자동 모드는 xn--이 있으면 디코딩
  • 전각 마침표(。)도 구분자로 인식, URL을 넣으면 호스트 부분만 변환
  • 레이블 63자, 전체 253자 제한을 검사해 알려 줌

💡 Tips

  • TLS 인증서의 SAN과 DNS 레코드에는 xn-- 형태를 사용하세요. 브라우저 주소창만 유니코드로 보여 줍니다.
  • 한글 도메인은 한 글자가 여러 문자로 인코딩되어 레이블이 63자를 넘기 쉽지 않은지 확인하세요.
  • 비슷하게 생긴 문자를 쓴 피싱 도메인(호모그래프)은 Punycode로 바꾸면 쉽게 드러납니다.

자주 묻는 질문

Punycode는 암호화인가요?

아니요. 유니코드 문자열을 ASCII로 가역 변환하는 인코딩일 뿐이며 누구나 되돌릴 수 있습니다.

모든 IDNA 규칙을 지원하나요?

NFKC 정규화와 소문자화까지만 하고, 전체 IDNA(UTS #46) 매핑·금지 문자 검사는 하지 않습니다. 등록 가능 여부는 레지스트리 규칙을 따릅니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
