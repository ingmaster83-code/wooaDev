쿼리 문자열 파서 · 빌더

URL의 쿼리 문자열을 키-값 표와 JSON으로 풀어 보고(배열·중첩 포함), 반대로 JSON 객체를 올바르게 인코딩된 쿼리 문자열로 만듭니다.

사용 예시

✅ 파라미터 9개 · 경로 https://example.com/search · 프래그먼트 #results · 중복 키: tag

입력 — 입력

https://example.com/search?q=hello+world&tag=a&tag=b&filter[status]=open&filter[owner]=kim&ids[]=1&ids[]=2&empty=&page=2#results

결과 — 파라미터 목록

# | 키 | 값 (디코딩) | 원문
1 | q | hello world | q=hello+world
2 | tag | a | tag=a
3 | tag | b | tag=b
4 | filter[status] | open | filter[status]=open
5 | filter[owner] | kim | filter[owner]=kim
6 | ids[] | 1 | ids[]=1
7 | ids[] | 2 | ids[]=2
8 | empty | (빈 문자열) | empty=
9 | page | 2 | page=2

결과 — 결과

{
  "q": "hello world",
  "tag": [
    "a",
    "b"
  ],
  "filter": {
    "status": "open",
    "owner": "kim"
  },
  "ids": [
    "1",
    "2"
  ],
  "empty": "",
  "page": "2"
}

이 도구로 할 수 있는 일

API 호출이 안 될 때 가장 먼저 의심하는 것이 쿼리 문자열입니다. 인코딩이 풀린 값과 배열·중첩 구조를 보면서 확인하세요.

  • 분석: 전체 URL 또는 ?a=1&b=2 입력 → 파라미터 표(디코딩 값, 원문), 중복 키 표시, 경로·#프래그먼트 분리
  • JSON 변환: 같은 키 반복(tag=a&tag=b)과 a[]=1, a[0]=1은 배열로, filter[status]=open은 중첩 객체로 (끌 수 있음)
  • 만들기: JSON 객체 → 쿼리 문자열. 배열은 반복(a=1&a=2), 대괄호(a[]=), 인덱스(a[0]=), 쉼표(a=1,2) 중 선택
  • 옵션: 공백을 %20 또는 +로, 키 정렬, null·빈 값 제외, 객체는 a[b]=1 형태로 평탄화
  • '+'를 공백으로, %XX를 UTF-8 문자로 디코딩

💡 Tips

  • 배열 표기는 서버 프레임워크마다 다릅니다: Express(qs)·PHP·Rails는 a[]=, Spring은 반복 키를 기대합니다.
  • 한글이 깨져 보이면 %ED%95%9C 같은 UTF-8 퍼센트 인코딩인지 확인하세요. 이 도구는 자동으로 디코딩합니다.
  • 공백은 쿼리에서 + 로도 쓰이지만 경로에서는 %20만 유효합니다.

자주 묻는 질문

'+'와 '%20'은 같은가요?

쿼리 문자열(application/x-www-form-urlencoded)에서는 둘 다 공백입니다. 하지만 URL 경로에서 +는 그냥 더하기 문자입니다.

같은 키가 여러 번 나오면 어떻게 되나요?

서버마다 첫 값·마지막 값·배열로 다르게 처리합니다. 이 도구는 배열로 모아서 보여 주고 중복 키를 표시합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
