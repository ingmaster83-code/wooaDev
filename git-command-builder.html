Git 명령어 생성기 — 실행 전에 뜻 확인

작업을 고르고 옵션을 체크하면 git 명령어를 만들어 주고, 각 부분이 무슨 뜻인지, 어떤 위험이 있는지, 실수했을 때 되돌리는 방법을 함께 알려 줍니다.

사용 예시

✅ 명령어를 만들었습니다

결과 — Git 명령어

git push -u origin feature/login

결과 — 각 부분의 뜻

부분 | 뜻
git | Git 실행
push | 로컬 커밋을 원격에 올림
-u | 이후 git push/pull 에 이 원격 브랜치를 기본값으로 연결
origin | 원격 이름
feature/login | 올릴 브랜치

이 도구로 할 수 있는 일

외우기 어려운 옵션 조합을 체크박스로 고르면 한 줄 명령어와 설명 표, 주의사항이 함께 나옵니다. 위험한 명령은 실행 전에 한 번 더 확인하게 됩니다.

  • 지원 작업: commit, branch/switch, merge, rebase, reset, revert, cherry-pick, stash, log, diff, push, pull, fetch, clone, tag, restore, clean, remote
  • 각 부분의 뜻을 표로 설명 (예: --force-with-lease 는 안전한 강제 푸시)
  • 🚨 reset --hard, push --force, clean -f, stash clear 등 되돌릴 수 없는 작업 경고
  • 되돌리는 방법 안내 (reflog, ORIG_HEAD, reset --soft HEAD~1 등)
  • 메시지·경로는 셸에서 안전하게 인용되어 그대로 복사 가능

함께 쓰면 좋은 도구

💡 Tips

  • 강제 푸시가 필요하면 --force 대신 --force-with-lease 를 쓰세요. 다른 사람이 올린 커밋을 지우지 않습니다.
  • rebase·amend·reset 은 커밋 해시를 바꿉니다. 이미 공유한 브랜치에서는 revert 를 쓰세요.
  • clean 은 기본이 미리보기(-n)입니다. 목록을 확인한 뒤에만 -f 로 실제 삭제하세요.

자주 묻는 질문

실수로 reset --hard 를 했어요.

커밋된 내용이었다면 git reflog 로 이전 커밋 해시를 찾아 git reset --hard 해시 로 되돌릴 수 있습니다. 커밋하지 않은 변경은 복구할 수 없습니다.

git switch 와 git checkout 은 다른가요?

switch 는 브랜치 전환, restore 는 파일 복원으로 checkout 의 두 역할을 나눈 최신 명령입니다. 동작은 같지만 의도가 분명합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
