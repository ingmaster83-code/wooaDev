Docker Compose 작업대 · 검사기

docker-compose.yml 을 붙여 넣으면 서비스 표와 함께 호스트 포트 충돌, depends_on 의 없는 서비스·순환, 정의되지 않은 네트워크·볼륨, 중복 container_name, 오타 난 키, latest 이미지, privileged, 평문 비밀 값을 줄 번호로 알려 주고 시작 순서를 계산합니다.

사용 예시

⛔ 오류 5건 · 경고 2건 — 서비스 3개

입력 — docker-compose.yml

version: "3.8"
services:
  web:
    image: nginx:latest
    ports:
      - "8080:80"
      - "127.0.0.1:9000:9000"
    depends_on:
      - api
      - cache
    networks: [front]
  api:
    build: ./api
    container_name: api
    ports:
      - "8080:3000"
    environment:
      DB_URL: postgres://${DB_USER}:${DB_PASS:-secret}@db/app
    depends_on:
      db:
        condition: service_healthy
    volumes:
      - data:/var/lib/app
      - ./conf:/etc/app:ro
    networks: [front, back]
  db:
    image: postgres:16
    privileged: true
    networks: [back]
    volumes:
      - pgdata:/var/lib/postgresql/data
networks:
  front: {}
volumes:
  pgdata:
  unused:

결과 — 서비스

서비스 | 이미지/빌드 | 포트 | depends_on | 네트워크 | 줄
web | nginx:latest | 8080:80, 127.0.0.1:9000:9000 | api, cache | front | 3
api | build: ./api | 8080:3000 | db | front, back | 12
db | postgres:16 | — | — | back | 26

결과 — 점검 결과

ℹ️ 줄 1: version 필드는 Compose v2+ 에서 폐기(obsolete)되었으며 무시됩니다
ℹ️ 줄 1: 기본값 없는 환경 변수 DB_USER 는 .env 파일이나 셸에 정의돼 있어야 합니다 (없으면 빈 문자열 경고)
⚠️ 줄 4: 이미지 "nginx:latest" 는 latest 태그입니다. 버전을 고정하세요
⛔ 줄 8: depends_on 의 "cache" 서비스가 없습니다
⛔ 줄 16: 호스트 포트 tcp 8080 가 서비스 "web"(줄 6)와 "api" 에서 충돌합니다
ℹ️ 줄 19: "db" 의 이미지에 healthcheck 가 내장되어 있지 않다면 service_healthy 가 영원히 대기합니다. compose 에 healthcheck 를 정의하세요
⛔ 줄 22: 서비스 "api" 가 정의되지 않은 볼륨 "data" 를 씁니다 (최상위 volumes 에 선언 필요)
⛔ 줄 25: 서비스 "api" 가 정의되지 않은 네트워크 "back" 를 씁니다
⚠️ 줄 28: 서비스 "db" 가 privileged: true 입니다. 호스트 전체 권한을 가지므로 꼭 필요한 경우만 쓰세요
⛔ 줄 29: 서비스 "db" 가 정의되지 않은 네트워크 "back" 를 씁니다
ℹ️ 줄 36: 볼륨 "unused" 를 쓰는 서비스가 없습니다

이 도구로 할 수 있는 일

compose 파일을 올리기 전에 실행 단계에서야 드러나는 오류를 미리 찾습니다. 파일은 서버로 전송되지 않습니다.

  • 서비스 표: 이미지/빌드, 포트, depends_on, 네트워크, 줄 번호
  • 포트: 짧은·긴 문법 해석, 호스트 IP 가 다르면 충돌 아님, 범위 확인, 따옴표 없는 NN:NN 경고
  • 참조: depends_on 대상과 조건(service_healthy 에 healthcheck 필요), 네트워크·볼륨 정의, 사용하지 않는 네트워크·볼륨, 순환 감지와 위상 정렬한 시작 순서
  • 서비스 키 오타, version 폐기 안내, container_name 중복·scale 불가, restart 값, 환경 변수 보간(${VAR:-기본}) 목록
  • 보안: latest·태그 없는 이미지, privileged, network_mode: host, 환경 변수의 평문 비밀

💡 Tips

  • 포트는 "8080:80" 처럼 따옴표로 감싸세요. YAML 1.1 파서는 NN:NN 을 60진수로 읽을 수 있습니다.
  • depends_on 만으로는 서비스가 준비될 때까지 기다리지 않습니다. condition: service_healthy 와 healthcheck 를 함께 쓰세요.
  • 비밀 값은 .env 파일이나 secrets 로 분리하고 .gitignore 에 추가하세요.

자주 묻는 질문

version 필드를 지워도 되나요?

Compose v2 이상에서는 version 이 폐기되어 무시됩니다. 지워도 동작은 같습니다.

같은 호스트 포트를 두 서비스가 쓰면 항상 오류인가요?

같은 호스트 IP(또는 IP 미지정)에서 같은 프로토콜의 같은 포트를 쓰면 충돌입니다. 서로 다른 호스트 IP 에 바인딩하면 가능합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
