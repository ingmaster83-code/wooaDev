Kubernetes 매니페스트 생성기

앱 이름, 이미지, 포트, replicas, 리소스, 헬스 체크 경로, Ingress 호스트를 입력하면 Deployment, Service, Ingress, HPA, PodDisruptionBudget YAML 을 만들어 줍니다. non-root, 읽기 전용 루트 FS 같은 보안 기본값과 프로브가 포함됩니다.

사용 예시

✅ 리소스 4개를 만들었습니다

입력 — 환경 변수 (한 줄에 KEY=값)

LOG_LEVEL=info
APP_MODE=production

결과 — YAML

apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
  namespace: production
  labels:
    app.kubernetes.io/name: myapp
    app.kubernetes.io/managed-by: manifest
spec:
  replicas: 2
  selector:
    matchLabels:
      app.kubernetes.io/name: myapp
  template:
    metadata:
      labels:
        app.kubernetes.io/name: myapp
    spec:
      securityContext:
        runAsNonRoot: true
        seccompProfile:
          type: RuntimeDefault
      containers:
        - name: myapp
          image: ghcr.io/example/myapp:1.0.0
          ports:
            - name: http
              containerPort: 8080
          env:
            - name: LOG_LEVEL
              value: "info"
            - name: APP_MODE
              value: "production"
          resources:
            requests:
              cpu: 100m
              memory: 128Mi
            limits:
              memory: 256Mi
          readinessProbe:
            httpGet:
              path: /healthz
              port: http
            periodSeconds: 5
          livenessProbe:
            httpGet:
              path: /healthz
              port: http
            initialDelaySeconds: 10
            periodSeconds: 10
          securityContext:
            allowPrivilegeEscalation: false
            readOnlyRootFilesystem: true
            capabilities:
              drop: ["ALL"]
---
apiVersion: v1
kind: Service
metadata:
…

결과 — 만들어진 리소스

종류 | 이름 | 요약
Deployment | myapp | 2 replicas
Service | myapp | ClusterIP :80 → http(8080)
Ingress | myapp | myapp.example.com (TLS)
PodDisruptionBudget | myapp | minAvailable 1

이 도구로 할 수 있는 일

새 앱의 첫 매니페스트를 빠르게 만들고 필수 설정을 빠뜨리지 않도록 돕습니다. 입력은 브라우저 밖으로 나가지 않습니다.

  • 리소스: Deployment(필수), Service(ClusterIP·NodePort·LoadBalancer), Ingress(호스트·TLS·ingressClassName), HorizontalPodAutoscaler(v2), PodDisruptionBudget
  • 설정: 레이블(app.kubernetes.io/*), 네임스페이스, 환경 변수 목록, cpu/memory requests·limits, readiness·liveness 프로브
  • 보안 강화 옵션: runAsNonRoot, seccomp RuntimeDefault, allowPrivilegeEscalation: false, 읽기 전용 루트 FS, capabilities drop ALL
  • 입력 검증: DNS 이름, 호스트 형식, limit ≥ request, HPA 최대 ≥ replicas, 비밀 값 환경 변수 경고, latest 이미지 경고
  • 결과를 검증기 도구로 바로 점검 가능한 표준 YAML(--- 구분)

💡 Tips

  • 비밀 값은 환경 변수에 직접 넣지 말고 Secret 을 만든 뒤 valueFrom.secretKeyRef 로 참조하세요.
  • HPA 를 쓰면 replicas 는 HPA 가 관리하므로 Deployment 매니페스트에서 빼는 것이 좋습니다.
  • 읽기 전용 루트 FS 를 켜면 앱이 /tmp 에 쓸 수 없습니다. emptyDir 볼륨을 마운트하세요.

자주 묻는 질문

생성된 YAML 을 바로 운영에 써도 되나요?

출발점입니다. 이미지 태그, 리소스 값, 프로브 경로, 네트워크 정책 등은 앱에 맞게 조정하고 kubectl apply --dry-run=server 로 확인하세요.

Helm 차트도 만들어 주나요?

아니요. 순수 매니페스트만 만듭니다. Helm 이나 Kustomize 로 옮길 때 출력 YAML 을 템플릿의 기반으로 쓰세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
