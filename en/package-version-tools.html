Package Version Constraint Explainer — Composer, Cargo, NuGet & Go

Turns constraints such as ^1.2.3 || ~2.0 (Composer), ^0.2.3 (Cargo), [1.0,2.0) (NuGet) and Go module versions into readable ranges and tells you which candidate versions match.

Example

Input — Version constraint / module version

^1.2.3 || ~2.0

1.2.3

2.0.0

3.0.0

What this tool does

Interpret each ecosystem's version syntax in one place. Input is processed only in your browser.

  • Composer: ^, ~, *, hyphen ranges, >=1.0 <2.0, ||, comma / space AND, stability (-dev, @beta)
  • Cargo: ^ (default), ~, *, =, comparators, comma AND and the special caret behaviour of 0.x
  • NuGet: 1.0 (minimum), [1.0], [1.0,2.0), (,1.0] and pre-release labels
  • Go: /v2 module path suffix, unstable v0, pseudo-versions and +incompatible
  • A range explanation table and a verdict for each candidate

💡 Tips

  • In Cargo ^0.2.3 allows only up to <0.3.0; for 0.x the minor is the compatibility boundary.
  • NuGet's 1.0 means 1.0 or higher, not exactly 1.0.
  • In Go, v2 and above require the module path to end in /v2.

Frequently Asked Questions

Composer ~1.2 versus ^1.2?

~1.2 is >=1.2,<2.0 and ~1.2.3 is >=1.2.3,<1.3.0, while ^1.2.3 is >=1.2.3,<2.0.0.

Do pre-releases match?

Each ecosystem's rules apply: unnamed pre-releases are usually excluded and the table shows why.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
