What this tool does

A ULID is 26 Crockford Base32 characters: 10 for the millisecond timestamp and 16 random. Sorting lexicographically sorts by time, which suits database indexes better than UUID v4, and it's short and URL-safe.

  • Generate: choose a count, monotonic mode that increments the random part within the same millisecond, lowercase, or a fixed time
  • Decode: creation time (UTC ISO, Unix ms) and the 80-bit random value (hex)
  • Paste several ULIDs to check that their order matches ULID (chronological) order
  • Look-alike letters I, L, O are corrected to 1, 1, 0; a first character above 7 (48-bit overflow) is rejected
  • Randomness comes from crypto.getRandomValues and is unpredictable

💡 Tips

  • When generating test fixtures, fix the time so the sort order is predictable.
  • ULIDs are case-insensitive but conventionally written in uppercase.
  • Only use them where exposing the creation time is acceptable — a ULID doesn't hide it.

Frequently Asked Questions

How are ULIDs different from UUID v7?

Both start with a millisecond timestamp and sort by time. A ULID is a 26-character Base32 string; UUID v7 follows the UUID format (36-character hex), so existing UUID column types work as-is.

Why a monotonic mode?

Several IDs generated in the same millisecond could otherwise come out in random order. Incrementing the previous random value keeps creation order even within one millisecond.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
