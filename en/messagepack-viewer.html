MessagePack Decoder & Encoder

Decodes MessagePack bytes from hex, Base64 or a file into a structure table with format names and byte offsets, plus JSON. It can also encode JSON into the shortest MessagePack form.

Example

✅ Decoded — 42 bytes, 12 elements

Input — MessagePack (hex / Base64) or JSON to encode

84 a4 6e 61 6d 65 a5 57 6f 6f 61 21 a3 61 67 65 1e a6 73 63 6f 72 65 73 93 01 cb 40 09 1e b8 51 eb 85 1f d4 02 0a a2 6f 6b c3

16 | 0x1e |   $.age | positive fixint | 30
24 | 0x93 |   $.scores | fixarray | array(3)

What this tool does

Open msgpack data from service-to-service traffic or caches. Data never leaves your browser.

  • Input: hex (spaces and 0x allowed), Base64 or a file, detected automatically
  • Structure table: byte offset, format byte, path ($.a.b[0]), format name (positive fixint, fixstr, map 16 …) and value
  • Formats: 8–64-bit integers, float32 / 64, str, bin, array, map, ext, fixext and the timestamp extension (-1)
  • 64-bit integers keep full precision; non-string map keys, duplicate keys, invalid UTF-8 and trailing bytes are reported
  • Encode: JSON to the shortest integer forms, output as hex and Base64

💡 Tips

  • Unlike JSON, msgpack distinguishes binary data and integers from floats; 1.0 and 1 are different bytes.
  • A msgpack map with non-string keys turns its keys into strings in JSON, which can collide.
  • If values are concatenated like a stream, use the trailing-bytes note to split and decode each value.

Frequently Asked Questions

How does MessagePack differ from JSON?

It is a binary format with a JSON-like data model: smaller and faster, with a binary type and extension types.

Why is byte c1 an error?

0xc1 is reserved and never used in the spec, so valid data cannot contain it; the data may be corrupted or another format.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
