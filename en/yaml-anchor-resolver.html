YAML Anchor, Alias & Merge Key Resolver

Shows YAML containing anchors (&), aliases (*) and merge keys (<<) fully expanded. It lists where anchors are defined and used, unused anchors, undefined aliases and which value wins in a merge.

Example

✅ Resolved 3 anchor(s), 3 alias(es), 2 merge(s)

Input — YAML with anchors, aliases and merge keys (<<)

defaults: &defaults
  adapter: postgres
  host: localhost
  pool: 5

development:
  <<: *defaults
  database: dev_db

production:
  <<: *defaults
  host: db.example.com
  database: prod_db
  pool: 20

replicas: &replicas [web1, web2]
cluster:
  nodes: *replicas

unused: &old
  legacy: true

Result — Fully expanded result

defaults:
  adapter: postgres
  host: localhost
  pool: 5
development:
  database: dev_db
  adapter: postgres
  host: localhost
  pool: 5
production:
  host: db.example.com
  database: prod_db
  pool: 20
  adapter: postgres
replicas:
  - web1
  - web2
cluster:
  nodes:
    - web1
    - web2
unused:
  legacy: true

Result — Anchors and aliases

Anchor | Defined at | Kind | Uses | Used at
&defaults | 1 | mapping | 2 | 7, 11
&replicas | 16 | list | 1 | 18
&old | 20 | mapping | 0 | —

What this tool does

See what a file that reduces duplication with anchors, such as CI config or database.yml, really contains. Your file is not uploaded.

  • Resolve: &anchors, *aliases and <<: *anchor or <<: [*a, *b] merges replaced by real values, output as YAML or JSON
  • Table: anchor name, defined line, kind (mapping, list, value), number of uses and their lines
  • Checks: unused anchors, undefined aliases, an alias before its anchor and duplicate keys
  • Merge rules explained: a value written in the mapping beats a merged one, and with several merged mappings the earlier wins
  • Options: leave out shared definitions (top-level keys carrying an anchor) and multiple documents (---)

💡 Tips

  • If a tool does not support anchors, feed it the expanded output; comments are dropped.
  • The merge key <<: is a YAML 1.1 convention that some parsers do not support.
  • An alias may appear only after its anchor; reordering causes an error.

Frequently Asked Questions

Is the merge key standard?

It is a YAML 1.1 type and absent from the 1.2 core schema, though many parsers support it; this tool resolves it as if supported.

Is the merge deep?

No. <<: merges top-level keys only and replaces nested mappings wholesale; merge nested values again at each key.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
