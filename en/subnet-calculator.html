Subnet Calculator — IPv4 & IPv6 CIDR

Calculates network address, broadcast, usable host range and count from an IP with CIDR or subnet mask. /31, /32 and IPv6 are handled too.

What this tool does

The calculation you do most often in network design and firewall or security-group rules. Enter several lines to compare them in a table.

  • Input: 192.168.1.10/24, 10.0.0.0 255.255.0.0 (IP + mask), 2001:db8::/32 (IPv6)
  • Result: network address, subnet mask, wildcard, broadcast, first/last host, total addresses and usable hosts
  • /31 (point-to-point, RFC 3021) and /32 (single host) are computed differently from the usual −2 rule
  • Detects class A–E and private (RFC 1918), CGNAT (100.64/10), link-local, loopback and documentation (TEST-NET) ranges
  • Non-contiguous masks such as 255.0.255.0 are rejected

💡 Tips

  • Cloud subnets (e.g. AWS VPC) reserve the first four and the last address, so five fewer are really usable.
  • A Cisco ACL wildcard mask is the inverse of the subnet mask.
  • To merge many CIDRs into fewer blocks, use the CIDR Set Calculator.

Frequently Asked Questions

Why subtract 2 for hosts?

The first address is the network address and the last is the broadcast address; neither can be assigned to a device. A /31 is for point-to-point links and uses both addresses.

Doesn't IPv6 have a broadcast address?

No — IPv6 uses multicast instead, so every address in the subnet (including the first) can be a host. A /64 is normally assigned per link.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
