OpenAPI Mock Data Generator

Pick an endpoint from an OpenAPI document and generate a response or request body mock. Examples are used when present; otherwise values are derived deterministically from the schema (type, format, enum, min/max), so the same input always gives the same output. A curl command is included.

Example

✅ Generated mock data for GET /pets → 200

Input — OpenAPI document (YAML or JSON)

openapi: 3.0.3
info: { title: Pets, version: 1.0.0 }
servers: [{ url: https://api.example.com/v1 }]
paths:
  /pets:
    get:
      summary: List pets
      parameters: [{ name: limit, in: query, schema: { type: integer } }]
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema: { type: array, items: { $ref: "#/components/schemas/Pet" } }
    post:
      summary: Add a pet
      requestBody:
        content: { application/json: { schema: { $ref: "#/components/schemas/NewPet" } } }
      responses:
        "201":
          description: Created
          content: { application/json: { schema: { $ref: "#/components/schemas/Pet" } } }
        "400": { description: Bad request, content: { application/json: { schema: { $ref: "#/components/schemas/Error" } } } }
components:
  schemas:
    Pet:
      type: object
…

What this tool does

Get realistic response data for front-end work and tests without a running API. The document is not uploaded.

  • Target: write 'GET /pets/{id}' style method + path, or select by operationId
  • Values: example, default and enum first; string formats (date-time, email, uuid, uri ...) and numeric ranges are respected
  • Schemas: $ref, merged allOf, oneOf / anyOf (first branch) and additionalProperties maps
  • readOnly fields only in responses, writeOnly fields only in requests
  • Choose status code and array length; curl output has path variables filled in

💡 Tips

  • The same document always yields the same values, so the output works for snapshot tests and documentation.
  • Add an example to a schema to pin the mock value to it.
  • Use request mocks as POST / PUT test data and response mocks as front-end mock-server responses.

Frequently Asked Questions

Are the values random?

No. They are calculated deterministically from the schema name and position, so identical input gives identical output.

How is oneOf handled?

The first branch is used. Add an example to the schema if you need a different one.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
