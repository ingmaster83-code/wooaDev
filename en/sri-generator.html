SRI Hash Generator — The integrity Attribute

Generate the Subresource Integrity value (sha256 / sha384 / sha512) for JS and CSS files loaded from a CDN and get a ready-made script or link tag.

Example

✅ SRI hash computed for 22 bytes

Input — Paste the file content

console.log("hello");

Input — Resource URL (for the tag example)

https://cdn.example.com/lib/app.min.js

What this tool does

SRI makes the browser refuse a script whose hash differs, even if the CDN was compromised or the file changed. All you need is the file content.

  • Pick a file or paste its content to get sha384 (recommended), sha256 or sha512 integrity values
  • Optionally output all three algorithms separated by spaces
  • A .css URL gives a link tag, anything else a script tag, both with crossorigin=anonymous
  • Paste an integrity value you already have to check it against the current file
  • Files are processed locally and never uploaded

💡 Tips

  • SRI only works when the resource is served with CORS (Access-Control-Allow-Origin); keep crossorigin=anonymous.
  • Pin the CDN URL to a version (lib@3.7.1) and hash that exact file so the value stays stable.
  • If even one byte changes the browser blocks the load, so update the hash in your deploy pipeline.

Frequently Asked Questions

Why is sha384 recommended?

The W3C spec recommends it and all major browsers support sha256, sha384 and sha512. It balances strength and length.

What happens when SRI fails?

The browser refuses to run the script or apply the stylesheet and logs a console error. The page may break, so plan a fallback.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
