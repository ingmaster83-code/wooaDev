Text Chunker — RAG & Embedding Preprocessing

Splits long documents into chunks suited for embeddings and retrieval. Supports character, estimated-token, paragraph, Markdown-heading and sentence splitting with overlap, word / sentence boundary cutting, a chunk table, JSON output and warnings for tiny chunks.

Example

✅ 2 chunk(s) · avg 210 chars · total ≈165 tokens

Input — Document to split

# RAG 소개

RAG(Retrieval-Augmented Generation)는 외부 문서를 검색해 LLM 의 답변을 보강하는 방식입니다. 문서를 적당한 크기로 나누는 청킹이 검색 품질을 좌우합니다.

## 청킹 전략

고정 길이 청킹은 단순하지만 문장이 중간에서 잘릴 수 있습니다. 문단·제목 기준 청킹은 의미 단위를 유지합니다. 겹침(overlap)을 두면 경계에서 문맥이 끊기는 문제를 줄일 수 있습니다.

## 주의사항

청크가 너무 작으면 문맥이 부족하고, 너무 크면 관련 없는 내용이 섞여 검색 정밀도가 떨어집니다. Chunks that are too large also cost more tokens when they are placed in the prompt.

What this tool does

Vary chunk size and overlap and see the result immediately when preparing documents for vector search. Documents never leave your browser.

  • Split by: characters, tokens (estimated), paragraphs (blank lines), Markdown headings (#) and sentences
  • Character and token modes support overlap and cutting on word or sentence boundaries
  • Paragraph and sentence modes merge small units up to the size limit; heading mode starts a new chunk at every heading (no overlap applied)
  • Token estimate: about 4 chars / token for English, 1.5 for Korean and auto for mixed (use your model's tokenizer for exact values)
  • A chunk table (range, length, tokens, overlap, preview), JSON (id, start, end, text) and short-chunk warnings

💡 Tips

  • Start with 200–500 tokens and 10–20% overlap and tune by looking at retrieval results.
  • Use paragraph or heading splitting so tables and code blocks are not cut in half.
  • Korean uses far more tokens than English for the same number of characters.

Frequently Asked Questions

What happens if chunks are too small or too large?

Too small lacks context; too large mixes unrelated content, lowers retrieval precision and raises prompt cost.

Why does the token count differ from my model?

It is estimated from characters; compute exact values with the model's tokenizer such as tiktoken.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
