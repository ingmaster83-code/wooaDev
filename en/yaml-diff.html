YAML Diff — Compare Content, Ignore Indentation & Comments

Parses both YAML documents and compares the data, so differences in indentation, comments or key order don't show up — only real changes, with their paths.

Example

🔍 Added 1 · Removed 0 · Changed 3

Input — Original YAML (A)

name: api
replicas: 2
image: app:1.0
env:
  - name: MODE
    value: dev
labels:
  tier: backend

Input — Changed YAML (B)

name: api
replicas: 3
image: app:1.1
env:
  - name: MODE
    value: prod
labels:
  tier: backend
  team: core

Result — Changes

Type | Path | Before (A) | After (B)
Changed | $.replicas | 2 | 3
Changed | $.image | "app:1.0" | "app:1.1"
Changed | $.env[0].value | "dev" | "prod"
Added | $.labels.team |  | "core"

What this tool does

A text diff makes dozens of lines look different when only indentation changed. This tool reads both files as data first, so only meaningful changes remain.

  • Ignores indentation, comments and key order (but "1" vs 1 is reported as a type change)
  • Added/removed/changed values with paths such as $.spec.template.spec.containers[0].image
  • Multi-document files (---) are compared as arrays
  • Anchors (&) and aliases (*) are expanded before comparison

Turn on "Ignore array order" if the order of list items doesn't matter.

💡 Tips

  • Handy for comparing Helm values.yaml across environments or checking Kubernetes manifests before and after a change.
  • A bare number and a quoted string are treated as different types.
  • If one side has a syntax error you're told which side and the line/column.

Frequently Asked Questions

Are two files that only differ in comments the same?

Yes. Comments, indentation and key order aren't data, so they're ignored and only values are compared.

How are anchors and merge keys (<<) compared?

They are expanded while parsing, so the comparison uses the final effective values.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
