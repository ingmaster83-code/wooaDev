Git Merge & Rebase Simulator — Commit Graph Preview

Set the shared commits and the commits on each branch, pick an operation and the tool draws the before and after commit graph in ASCII, with the commands to run and which hashes change.

What this tool does

The difference between merge and rebase is quicker to grasp in a picture than in words. Change a few numbers to compare scenarios.

  • Input: shared commits up to the fork, commits after the fork on feature and main, and branch names
  • Operations: merge (fast-forwards when possible), --no-ff, --squash, rebase, rebase then --ff-only, cherry-pick
  • Before and after graphs with branch pointers and HEAD in ASCII
  • Per-commit table: unchanged / ♻️ recreated with a new hash / 🆕 new
  • Commands to run, whether a force push is needed, conflict risk and recovery tips

💡 Tips

  • Rule of thumb: merge for shared branches, rebase to tidy a private branch that is not pushed yet.
  • GitHub's Squash and merge equals --squash. Delete the work branch afterwards.
  • If a rebase goes wrong use git rebase --abort, or git reflog to find the old position afterwards.

Frequently Asked Questions

Why does a rebase need a force push?

Rebase copies commits and gives them new hashes, so history diverges from the old commits on the remote. You need git push --force-with-lease, and should not do it on branches others use.

When should I use merge --no-ff?

When you want a merge commit even though fast-forward is possible, to keep feature-level history.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
