MQTT Topic Filter Tester

See in a matrix whether subscription filters like sensors/+/temperature and sensors/# match topics like sensors/room1/temperature. $SYS rules, empty levels and misplaced wildcards are reported too.

Example

✅ Tested 6 filters × 7 topics

Input — Subscription filters (one per line)

sensors/+/temperature
sensors/#
+/+/temperature
#
$SYS/#
home/livingroom/+

Input — Published topics (one per line)

sensors/room1/temperature
sensors/room1/humidity
sensors/room1/floor2/temperature
home/livingroom/light
home/livingroom
$SYS/broker/uptime
/sensors/room1/temperature

Result — Findings

A leading slash ("/a") gives an empty first level, so it is a different topic from "a"
A filter starting with # or + never matches topics that begin with $ ($SYS …); subscribe to $SYS/# explicitly
A # subscription receives everything — heavy and risky; restrict it with ACLs
Topics are case-sensitive; sensors/# also matches the parent topic "sensors" itself

What this tool does

Preview which topics are received before deploying broker ACLs or subscriptions. Input is processed in your browser.

  • Matching: + is exactly one level, # is zero or more levels at the end (sensors/# also matches sensors)
  • Topics starting with $ are not matched by # or +/… filters (name them, e.g. $SYS/#)
  • Filter errors: # not last, + or # inside a level, empty filter
  • Topic errors: + or # in a published topic, empty topic, NUL character and length limit
  • A filter × topic matrix and a findings list

💡 Tips

  • Leading or trailing slashes create empty levels, so /a and a are different topics.
  • Subscribing to # alone still does not receive $SYS topics.
  • Topics are case sensitive and may contain spaces, which are best avoided.

Frequently Asked Questions

sensors/+ versus sensors/#?

+ matches one level such as sensors/room1; # matches all deeper levels such as sensors/room1/temperature.

Can I publish to a wildcard?

No. + and # are valid only in subscription filters; using them in a published topic violates the spec.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
