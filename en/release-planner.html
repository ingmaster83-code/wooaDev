Paste a list of Conventional Commits to get the next version (major / minor / patch), a CHANGELOG draft grouped by features and fixes, and the tag and push commands.

What this tool does

Automates reading git log, deciding the version and writing release notes every time you ship. Just paste the commits.

  • Version: BREAKING CHANGE / ! → major, feat → minor, fix / perf → patch, docs and chores alone → no release
  • Option to treat breaking changes as minor in 0.x, and prerelease (rc, beta) counters
  • CHANGELOG grouped as Features / Bug Fixes / Performance / Reverts, or Keep a Changelog (Added / Changed / Fixed)
  • With a repository URL it adds issue (#123), commit and version compare links
  • Lines that do not follow the format are skipped and reported; git tag and push commands included

💡 Tips

  • You can paste git log --oneline output (hash + message) as it is.
  • Generated notes are a draft; polish them into wording users understand before releasing.
  • If you squash-merge feature branches, have PR titles follow the Conventional Commits form.

Frequently Asked Questions

What if commits do not follow the convention?

Lines in another form are left out of the version calculation and notes, and listed so you can see them. A team commit convention gives the best results.

What about versions before 1.0.0?

SemVer treats 0.x as unstable, and it is common to bump minor for breaking changes there. Choose it with the option.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
