Cache-Control Header Builder & Parser

Build a Cache-Control header from presets for static files, HTML and APIs — or paste an existing one to have each directive explained and contradictions flagged.

Example

✅ Browser: 1 yr / Shared cache: 1 yr

Input — Cache-Control value to parse

public, max-age=31536000, immutable, stale-while-revalidate=600

Result — Cache-Control header

Cache-Control: public, max-age=31536000, immutable, stale-while-revalidate=600

Result — Directive explanations

Directive | Value | Meaning
public |  | Any cache (CDN, proxies) may store it
max-age | 31536000 | Seconds the response is considered fresh → 1 yr
immutable |  | Will not change while fresh — skip revalidation
stale-while-revalidate | 600 | Serve stale for N seconds while revalidating in the background → 10 min

What this tool does

Wrong cache settings mean users don't see a deployment, or the CDN hits your server on every request. Build the right value for each case and verify what you already use.

  • Build: choose public/private, max-age, s-maxage, no-cache, no-store, must-revalidate, immutable, stale-while-revalidate, stale-if-error…
  • Presets: fingerprinted static assets (1 year + immutable), HTML (always revalidate), private API (no-store), CDN-centric, SWR
  • Parse: each directive explained with its time (31536000 → 1 yr) and a summary of browser vs shared-cache freshness
  • Checks: public with private, no-store with max-age, lone immutable, max-age=0 alone, over a year, stale-* without max-age

💡 Tips

  • Cache hashed JS/CSS for a year with immutable and keep only the HTML short — the standard recipe.
  • no-cache doesn't mean "don't cache" but "revalidate before use". Use no-store to prevent storage.
  • Use s-maxage to give the CDN a different lifetime than browsers.

Frequently Asked Questions

What is the difference between no-cache and no-store?

no-cache stores the response but revalidates it every time (a 304 is possible); no-store never stores it. Use no-store for sensitive personal data.

What is stale-while-revalidate?

It lets a cache serve an expired response for a set time while fetching a fresh one in the background, which feels faster.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
