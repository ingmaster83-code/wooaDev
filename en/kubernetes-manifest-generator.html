What this tool does

Produce the first manifests for a new app without forgetting essentials. Input never leaves your browser.

  • Resources: Deployment, Service (ClusterIP, NodePort, LoadBalancer), Ingress (host, TLS, ingressClassName), HorizontalPodAutoscaler (v2) and PodDisruptionBudget
  • Settings: app.kubernetes.io/* labels, namespace, environment variables, cpu / memory requests and limits and readiness / liveness probes
  • Hardening option: runAsNonRoot, seccomp RuntimeDefault, allowPrivilegeEscalation: false, read-only root file system and capabilities drop ALL
  • Input checks: DNS names, host format, limit ≥ request, HPA max ≥ replicas, warnings for secret-looking env vars and latest images
  • Standard YAML (separated by ---) that you can run through the validator right away

💡 Tips

  • Do not put secrets in env values; create a Secret and reference it with valueFrom.secretKeyRef.
  • With an HPA the replica count is managed by the HPA, so consider removing replicas from the Deployment.
  • A read-only root file system stops the app writing to /tmp; mount an emptyDir volume.

Frequently Asked Questions

Can I use the YAML in production as is?

It is a starting point; adjust image tags, resources, probe paths and network policies and confirm with kubectl apply --dry-run=server.

Does it produce a Helm chart?

No, only plain manifests; use the output as the base of a Helm or Kustomize template.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
