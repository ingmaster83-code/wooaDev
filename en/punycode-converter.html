What this tool does

DNS only allows ASCII, so domains with Korean, Chinese or Cyrillic characters are registered and resolved as Punycode labels starting with xn--. DNS records and certificates (SAN) need this form.

  • Unicode → Punycode: each label is NFKC-normalised, lowercased and encoded with RFC 3492 (例え → xn--r8jz45g)
  • Punycode → Unicode: restores xn-- labels; auto mode decodes whenever xn-- is present
  • Ideographic full stops (。) count as dots; a URL converts only its host
  • Checks the 63-character label and 253-character name limits

💡 Tips

  • Use the xn-- form in TLS certificate SANs and DNS records; only the address bar displays Unicode.
  • Check that long non-Latin labels don't exceed 63 characters once encoded.
  • Homograph phishing domains (look-alike characters) are exposed when converted to Punycode.

Frequently Asked Questions

Is Punycode encryption?

No — it's a reversible encoding of Unicode into ASCII that anyone can decode.

Does it implement the full IDNA rules?

Only NFKC normalisation and lowercasing; full IDNA (UTS #46) mapping and prohibited-character checks aren't done. Registrability depends on the registry's rules.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
