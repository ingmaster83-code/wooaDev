AWS ARN Parser & Builder

Breaks an ARN such as arn:aws:iam::123456789012:role/MyRole into partition, service, region, account and resource and finds format mistakes. You can also assemble a new ARN from its fields.

What this tool does

ARNs appear constantly in IAM policies, resource policies and CLI commands, yet the resource part is structured differently per service.

  • Split: partition (aws, aws-cn, aws-us-gov), service, region, account-id and resource (type / name / version-or-alias guessed)
  • Paste several ARNs, one per line, to compare them in a table
  • Validate: 12-digit account ID, region format, partition, empty resource, and services such as S3 and IAM that leave region / account empty
  • Flags wildcards (*) used in policy resources
  • Build mode assembles an ARN from partition, service, region, account and resource

💡 Tips

  • An S3 bucket ARN is arn:aws:s3:::bucket and an object is arn:aws:s3:::bucket/key; policies often need both.
  • IAM, Route 53 and CloudFront are global, so the region field is empty.
  • Lambda aliases and versions put a colon inside the resource: function:name:alias.

Frequently Asked Questions

Why does the resource part differ per service?

Each service defines its own layout, mixing slash and colon separators. The tool guesses the first token as the type.

Where do I find my account ID?

In the console's top-right menu, or with aws sts get-caller-identity.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
