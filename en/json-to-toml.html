JSON to TOML Converter

Converts JSON into readable TOML configuration, building [table] sections and [[array of tables]] automatically.

Example

✅ Converted

Input — JSON input

{
  "title": "Example",
  "owner": { "name": "Kim", "active": true },
  "database": { "ports": [8000, 8001], "connection_max": 5000 },
  "servers": [
    { "name": "alpha", "ip": "10.0.0.1" },

  ]
}

title = "Example"

name = "Kim"

[database]
ports = [ 8000, 8001 ]
connection_max = 5000

[[servers]]
name = "alpha"
ip = "10.0.0.1"

[[servers]]
name = "beta"
ip = "10.0.0.2"

What this tool does

TOML is the config format of Rust's Cargo.toml, Python's pyproject.toml and many static-site tools. Use this when you already have settings as JSON.

  • Nested objects become [section] tables and arrays of objects become [[servers]] table arrays
  • Strings, numbers, booleans and arrays are written according to TOML 1.0
  • TOML has no null, so choose to drop the key, use an empty string, or report an error
  • Explains that a TOML document must be an object at the top level

To go the other way, use the TOML to JSON converter.

💡 Tips

  • If your JSON contains many nulls, "Drop the key" is the usual choice — treat them as optional values.
  • Feed the result into the TOML Formatter for extra tidying such as sorting keys.
  • Dates in JSON are strings, so they stay strings in TOML.

Frequently Asked Questions

How is TOML different from JSON?

TOML allows comments and has simpler quoting/comma rules, making it nicer for hand-edited config. It has no null, and the top level must be a table (object).

Can arrays hold mixed types?

Yes, since TOML 1.0, and this tool writes TOML 1.0.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
