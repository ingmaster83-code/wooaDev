URLPattern Tester — Check Routing Pattern Matches

Enter a URLPattern such as https://shop.example.com/products/:id(\d+)/:section? and check which URLs match and what :id and :section capture. It also shows how the pattern splits into protocol, hostname, pathname and other components.

Example

✅ 2 of 6 match

Input — URLPattern (full URL or pathname)

https://shop.example.com/products/:id(\d+)/:section?

Input — URLs to test (one per line)

https://shop.example.com/products/42
https://shop.example.com/products/42/reviews
https://shop.example.com/products/abc
https://shop.example.com/products/42/reviews/extra
http://shop.example.com/products/7
https://other.example.com/products/7

Result — Match results

URL | Result | Groups / reason
https://shop.example.com/products/42 | ✅ | id=42
https://shop.example.com/products/42/reviews | ✅ | id=42, section=reviews
https://shop.example.com/products/abc | ❌ | pathname: "/products/abc" ≠ /products/:id(\d+)/:section?
https://shop.example.com/products/42/reviews/extra | ❌ | pathname: "/products/42/reviews/extra" ≠ /products/:id(\d+)/:section?
http://shop.example.com/products/7 | ❌ | protocol: "http" ≠ https
https://other.example.com/products/7 | ❌ | hostname: "other.example.com" ≠ shop.example.com

Result — Pattern components

Component | Pattern | Group names
protocol | https | —
hostname | shop.example.com | —
port | * (any) | —
pathname | /products/:id(\d+)/:section? | id, section
search | * (any) | —
hash | * (any) | —

What this tool does

Check that a pattern catches only the intended URLs before using the URLPattern API. This tool has its own implementation, so it works regardless of browser support.

  • Syntax: /users/:id, :id(\d+), wildcard *, optional :section?, repeats :path+ / :path*, {…}? groups and escapes
  • Both full-URL patterns and pathname-only patterns, with per-component (protocol, hostname, port, pathname, search, hash) patterns
  • Results: capture names and values, and why a URL did not match
  • Checks: unsupported or invalid syntax, duplicate names, slash handling of optional segments
  • Several URLs, one per line

💡 Tips

  • With a pathname-only pattern the other components are wildcards.
  • :id matches one segment without slashes by default; use :id(\d+) to accept digits only.
  • The same pattern syntax works in service workers and the Navigation API.

Frequently Asked Questions

How does it differ from a regex?

URLPattern matches per URL component, gives named captures and applies encoding rules. Its syntax is based on path-to-regexp.

Can it match query strings?

You can give a search pattern, but it depends on parameter order, so check parameters in code instead.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
