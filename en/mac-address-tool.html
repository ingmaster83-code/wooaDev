MAC Address Validator & Converter

Converts MAC addresses between colon, hyphen and Cisco dotted notation, validates them, and reports unicast/multicast, locally administered bits and the EUI-64 link-local IPv6 address.

What this tool does

Devices write MAC addresses differently — Linux and Windows use colons or hyphens, Cisco uses dots — so every copy-paste needs reformatting.

  • Input: 00:1A:2B:3C:4D:5E, 00-1a-2b-3c-4d-5e, 001a.2b3c.4d5e, 001A2B3C4D5E, 0x1a2b3c4d5e
  • Choose the output style (colon / hyphen / Cisco / plain) and case; many lines at once
  • The first-byte bits tell unicast vs multicast and universal (UAA) vs local (LAA) administration — VMs, containers and randomised MACs are LAA
  • Shows the 3-byte OUI and the EUI-64 based link-local IPv6 (fe80::) address
  • Distinguishes broadcast (FF:FF:FF:FF:FF:FF) and all-zero addresses

💡 Tips

  • Phones' "private Wi-Fi address" uses a random LAA MAC. If the second hex digit is 2, 6, A or E, it's LAA.
  • Vendor-name lookup needs the current IEEE OUI list, so only the OUI value is shown here.
  • Docker's default MACs start with 02:42:.

Frequently Asked Questions

What are LAA and UAA?

If the second bit of the first byte is 0 the address is universally administered (assigned by the vendor, UAA); if 1 it's locally administered (set by software or an admin, LAA).

How is the EUI-64 link-local address built?

Insert FF:FE in the middle of the MAC, flip the U/L bit of the first byte, and append the resulting 64 bits to fe80::/64.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
