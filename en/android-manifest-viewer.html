AndroidManifest.xml Viewer & Security Audit

Provide AndroidManifest.xml text or the binary manifest (AXML) extracted from an APK as hex, Base64 or a file to restore the XML and tabulate the package, SDK versions, permissions, activities, services, receivers, providers and intent filters. Missing exported, debuggable builds and cleartext HTTP are flagged.

Example

⛔ 2 error(s), 6 warning(s) — com.wooahouse.demo

Input — AndroidManifest.xml (text) or the binary manifest from an APK (hex / Base64)

<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    package="com.wooahouse.demo"
    android:versionCode="12"
    android:versionName="1.2.0">

    <uses-sdk android:minSdkVersion="24" android:targetSdkVersion="34" />

    <uses-permission android:name="android.permission.INTERNET" />
    <uses-permission android:name="android.permission.CAMERA" />
    <uses-permission android:name="android.permission.ACCESS_BACKGROUND_LOCATION" />
    <uses-permission android:name="android.permission.READ_SMS" />
    <uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE" />

    <application
        android:name=".App"
        android:label="Wooa Demo"
        android:debuggable="true"
        android:usesCleartextTraffic="true">

        <activity android:name=".MainActivity">
            <intent-filter>

What this tool does

Read the manifest and audit its security settings without decompiling the APK. Your file is not uploaded.

  • Input: text XML, the binary AXML from an APK (UTF-8 / UTF-16 string pools), hex, Base64 or a file
  • Info: package, versionName / Code, minSdk, targetSdk and compileSdk, app label, Application class
  • Permissions: normal / dangerous (runtime) / sensitive classification, duplicates, protection level of custom permissions
  • Components: type, name, exported, protecting permission, intent filters (action, category, data) and deep-link autoVerify
  • Checks: missing exported with targetSdk 31+ (install failure), debuggable, allowBackup, cleartext, exported providers and services, low targetSdk

💡 Tips

  • With targetSdk 31 or higher, every component with an intent-filter must declare android:exported or the install fails.
  • If a release APK has debuggable true, anyone can access the app's data; check your build variant.
  • The final merged manifest is under app/build/intermediates, or open the APK in Android Studio's APK Analyzer.

Frequently Asked Questions

Are resource references (@0x7f…) resolved to names?

resources.arsc is not read, so they stay as @0x7f… numbers and string resource values such as labels are unknown.

Can I upload a whole APK or AAB?

No. An APK is a zip: extract AndroidManifest.xml first. This tool does not unzip archives.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
