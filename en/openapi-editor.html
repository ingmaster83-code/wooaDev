OpenAPI & Swagger Validator

Paste an OpenAPI 3.0 / 3.1 or Swagger 2.0 document (YAML or JSON) to get an endpoint table and line-numbered checks for $ref targets, path variables vs path parameters, duplicate operationIds, response codes, schema mistakes and security definitions.

Example

⛔ 9 error(s), 1 warning(s) — OpenAPI 3.0.3, 3 endpoint(s)

Input — OpenAPI / Swagger document (YAML or JSON)

openapi: 3.0.3
info:
  title: Pet Store
paths:
  /pets/{petId}:
    get:
      operationId: getPet
      parameters:
        - name: limit
          in: query
          schema: { type: integer, minimum: 1 }
      responses:
        "200":
          description: OK
          content:
            application/json:
              schema: { $ref: "#/components/schemas/Pet" }
        "404": { $ref: "#/components/responses/Missing" }
    delete:
      operationId: getPet
      requestBody: { content: { application/json: { schema: { type: object } } } }
      responses: {}
  /pets:
    post:
      security: [{ apiKey: [] }]
      responses:
        "201": { description: Created }
        "2xx": { description: Any }
components:
  schemas:
    Pet:
      type: object
      required: [id, name]
      properties:
        id: { type: integer, format: int64 }
        tags: { type: array }
…

What this tool does

Find structure and reference errors in the browser before publishing your API docs. The document is not uploaded.

  • Formats: OpenAPI 3.0, 3.1 and Swagger 2.0 in YAML or JSON
  • Errors: missing required fields, unresolved $ref, path variables without an in: path parameter, duplicate operationId, invalid response codes
  • Schemas: array without items, required names missing from properties, non-standard format, references to undefined security schemes
  • Hints (can be hidden): missing summary or operationId, unused components, no security scheme defined
  • Endpoint table with method, path, operationId, responses, tags and line numbers

💡 Tips

  • Every {id} in a path needs an in: path, required: true parameter with the same name. This is the most common error.
  • operationId becomes the SDK method name, so keep it unique across the whole document.
  • Move shared responses and schemas into components and reference them with $ref to keep the document short and easy to check.

Frequently Asked Questions

Is this the same as Spectral or the official validator?

It is a fast checker for common structure, reference and rule mistakes. It does not perform full JSON Schema validation (unevaluatedProperties and so on), so run Spectral or similar before releasing.

Does it follow external file $refs?

No. Only internal references starting with #/ inside the same document are checked; references to other files are skipped.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
