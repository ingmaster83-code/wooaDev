GitHub Actions Workflow Validator

Paste a workflow YAML to get line-numbered findings on event names, job keys, needs references and cycles, uses formats, outdated action versions, retired runners, script-injection risks, dangerous pull_request_target checkouts and missing permissions.

Example

⛔ 6 error(s), 2 warning(s) — 2 job(s), 5 step(s)

Input — Workflow (.github/workflows/*.yml)

name: CI
on:
  push:
    branches: [main]
  pull_request_target:
    types: [opened]
jobs:
  build:
    runs-on: ubuntu-20.04
    steps:
      - uses: actions/checkout@v3
        with:
          ref: ${{ github.event.pull_request.head.sha }}
      - name: Greet
        run: echo "${{ github.event.pull_request.title }}"
      - id: build
        run: npm ci && npm test
      - uses: actions/upload-artifact@main
        with:
          name: out
          path: dist
  deploy:
    needs: [build, test]
    runs-on: ubuntu-latest
    steps:
      - run: echo ${{ steps.deploy.outputs.url }}
        uses: ./scripts/deploy

Result — Findings

ℹ️ Line 1: No permissions block, so GITHUB_TOKEN gets the repository default; reduce it with permissions: contents: read
ℹ️ Line 8: Job "build" has no timeout-minutes, so a hung job can run up to 6 hours
⛔ Line 9: Runner "ubuntu-20.04" is retired and jobs will not start; use ubuntu-latest or a current version
⚠️ Line 11: actions/checkout@v3 is outdated (deprecated Node runtime or shut down); upgrade to v4 or later
⛔ Line 11: pull_request_target runs with secrets and write access; checking out the PR head runs outside code with those privileges
⛔ Line 15: Untrusted input (github.event.pull_request.title) is interpolated into the run script, a script-injection risk; pass it through env and use "$VAR"
⚠️ Line 18: actions/upload-artifact@main points to a branch whose content can change; pin a tag or commit SHA
ℹ️ Line 22: Job "deploy" has no timeout-minutes, so a hung job can run up to 6 hours
⛔ Line 23: needs refers to missing job "test"
⛔ Line 26: A step cannot have both uses and run
⛔ Line 26: No step in this job has the id used in steps.deploy

What this tool does

Find structure and security problems before pushing and watching the Actions tab fail. Your file is not uploaded.

  • Structure: top-level keys, on event names, 5-field cron, workflow_dispatch choice inputs, job ids and keys, runs-on, uses / run exclusivity and duplicate step ids
  • References: missing, self and cyclic needs, whether steps.<id> and needs.<job> exist, matrix keys
  • uses: owner/repo@ref format, outdated major actions (checkout, setup-*, cache, upload-artifact …), branch refs (@main) and SHA pinning advice for third-party actions
  • Security: untrusted input such as github.event.*.title / body / head_ref in run, pull_request_target with a PR head checkout, hard-coded tokens and write-all permissions
  • Hints: retired runners (ubuntu-20.04 …), missing timeout-minutes and permissions

💡 Tips

  • Do not put ${{ github.event.issue.title }} directly in run; pass it through env and use "$TITLE" to stop quote-breaking command injection.
  • Pin third-party actions to a commit SHA rather than a tag to avoid supply-chain attacks through moved tags.
  • Start from least privilege such as permissions: contents: read and grant write only to the jobs that need it.

Frequently Asked Questions

Does it replace actionlint?

It does not type-check every expression like actionlint, but it checks the structure, reference and security problems you meet most often with no install.

What about the on key reading as true?

This tool reads YAML 1.2 and keeps on as a string key; some old YAML 1.1 parsers turn on into true.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
