Kubernetes ConfigMap & Secret ↔ .env Converter

Splits the KEY=VALUE pairs of a .env file into ConfigMap and Secret YAML (with Base64 encoding) and turns Secret / ConfigMap YAML back into .env. It also writes the envFrom snippet for your Deployment.

Example

✅ ConfigMap 3 key(s) · Secret 2 key(s)

Input — .env content (KEY=VALUE)

# 앱 설정
LOG_LEVEL=info
API_URL=https://api.example.com
DB_HOST=db.internal
DB_PASSWORD=s3cr3t!
JWT_SECRET="a long secret value"

Input — ConfigMap / Secret YAML

apiVersion: v1
kind: Secret
metadata:
  name: app-secret
data:
  DB_PASSWORD: czNjcjN0IQ==
  JWT_SECRET: YSBsb25nIHNlY3JldCB2YWx1ZQ==
stringData:
  EXTRA: plain value

Result — Result

apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  LOG_LEVEL: info
  API_URL: "https://api.example.com"
  DB_HOST: db.internal
---
apiVersion: v1
kind: Secret
metadata:
  name: app-config-secret
type: Opaque
data:
  DB_PASSWORD: czNjcjN0IQ==
  JWT_SECRET: YSBsb25nIHNlY3JldCB2YWx1ZQ==

Result — Using it in a Deployment

# Deployment > spec.template.spec.containers[]
        envFrom:
          - configMapRef:
              name: app-config
          - secretRef:
              name: app-config-secret

# or one key at a time
        env:
          - name: LOG_LEVEL
            valueFrom:
              configMapKeyRef:
                name: app-config
                key: LOG_LEVEL

What this tool does

Moving settings from .env to Kubernetes means computing Base64 per value and splitting ConfigMap from Secret; this automates it. Everything runs in your browser.

  • .env → YAML: keys containing PASSWORD, SECRET, TOKEN, KEY … go to a Secret, the rest to a ConfigMap (override manually if you like)
  • Secrets as data (Base64) or stringData (plain), with an optional namespace
  • Checks the name (DNS subdomain), key characters and duplicates, and quotes numbers and booleans as strings
  • Generates envFrom / valueFrom snippets for the Deployment
  • Reverse direction: decode data / stringData of ConfigMap and Secret YAML into .env

💡 Tips

  • Base64 is not encryption. Do not commit Secret YAML to Git; use Sealed Secrets, External Secrets or SOPS.
  • ConfigMap values must be strings, so numbers such as ports are emitted as "8080".
  • A single ConfigMap or Secret is limited to 1 MiB; consider volumes or another store for big files.

Frequently Asked Questions

data versus stringData?

data holds Base64 values; with stringData you write plain text and the API server encodes it on save. stringData reads better in manifests.

Does changing a Secret update running Pods?

Environment variables only change after a restart. Values mounted as volumes refresh after a short delay.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
