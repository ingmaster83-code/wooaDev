AWS IAM Policy Viewer & Analyzer

Paste an IAM policy JSON to see each statement's Effect, Action, Resource and Condition in a table, and get warnings for wildcard admin access, privilege escalation paths and S3 ARN mistakes. Enter an action and resource to simulate allow or deny for this policy.

Example

⛔ 2 error(s), 5 warning(s) — 5 statement(s)

Input — IAM policy (JSON)

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ReadBucket",
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": "arn:aws:s3:::my-bucket"
    },
    {
      "Sid": "Wide",
      "Effect": "Allow",
      "Action": [
        "ec2:*",
        "iam:PassRole"
      ],
      "Resource": "*"
    },
    {
      "Sid": "Wide",
      "Effect": "Allow",
      "NotAction": "iam:*",
      "Resource": "*"
    },
    {
      "Sid": "Deny",
      "Effect": "Deny",
      "Action": "s3:DeleteObject",
      "Resource": "arn:aws:s3:::my-bucket/*",
      "Condition": {
        "Bool": {
          "aws:SecureTransport": "false"
        }
      }
    },
    {
      "Effect": "Allow",
      "Action": "sts:AssumeRole",
      "Resource": "*",
      "Principal": "*"
    }
  ]
}

Input — Access simulation (optional): action [resource] e.g. s3:GetObject arn:aws:s3:::my-bucket/a.txt

s3:GetObject arn:aws:s3:::my-bucket/a.txt

Result — Statements

# | Sid | Effect | Actions | Resources / principal | Conditions
1 | ReadBucket | Allow | s3:GetObject, s3:ListBucket | arn:aws:s3:::my-bucket | —
2 | Wide | Allow | ec2:*, iam:PassRole | * | —
3 | Wide | Allow | not: iam:* | * | —
4 | Deny | Deny | s3:DeleteObject | arn:aws:s3:::my-bucket/* | Bool {"aws:SecureTransport":"false"}
5 | — | Allow | sts:AssumeRole | P:"*" * | —

Result — Simulation

Action | Resource | Result | Matching statements
s3:GetObject | arn:aws:s3:::my-bucket/a.txt | ✅ Allowed | #3 (Wide) Allow

What this tool does

Review intent and risk in the browser before applying a policy. The policy is not uploaded.

  • Table: Sid, Effect, Action, Resource / Principal and Condition per statement (a single Statement object is accepted)
  • Risks: Action:* with Resource:*, service-wide wildcards, privilege escalation paths such as iam:PassRole or iam:*, public Principal:*
  • Format: Effect values, NotAction / NotResource, Version, bucket vs object ARN confusion for S3
  • Simulation: enter 'action [resource]' for an explicit allow / explicit deny / implicit deny verdict with the matching statements
  • Hints that can be turned off

💡 Tips

  • An explicit Deny always beats any Allow. Check the matching statements shown in the simulation.
  • s3:GetObject applies to object ARNs such as arn:aws:s3:::bucket/*, not the bucket ARN.
  • Before using wildcards, narrow the Action list using the calls CloudTrail actually recorded.

Frequently Asked Questions

Is it the same as the IAM Policy Simulator?

No. It evaluates this one policy in a simple way; SCPs, permission boundaries, session policies, resource policies and condition keys are not included. Use AWS's Policy Simulator for an exact verdict.

Are conditions evaluated?

Conditions are shown in the table but their values are not evaluated; statements with conditions are marked as conditional in the simulation.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
