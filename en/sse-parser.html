Server-Sent Events (SSE) Stream Parser

Splits raw text/event-stream copied from curl or browser dev tools into events, showing event, id, retry, data and comment lines, parsing JSON data and building the concatenated streaming result.

What this tool does

Unpack raw streams when debugging LLM streaming responses or notification feeds. Data never leaves your browser.

  • Spec parsing: a blank line ends an event, one space after the first colon is stripped, lines starting with a colon are comments
  • Fields: event (default message), data (multiple lines joined with \n), id and retry (digits only)
  • JSON data is parsed and delta / content fields are concatenated
  • Flags terminators like [DONE], unknown fields and an incomplete last event without its blank line
  • Handles CRLF and CR line endings

💡 Tips

  • An event is dispatched only after its terminating blank line; without it browsers discard the event.
  • On reconnect EventSource sends the last id in the Last-Event-ID header.
  • Comment lines (: keep-alive) are sent periodically so proxies do not drop the connection.

Frequently Asked Questions

SSE versus WebSocket?

SSE is a one-way server-to-client HTTP stream with built-in reconnection; WebSocket is bidirectional.

How are multi-line data fields merged?

The data lines of one event are joined with newlines into a single string.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
