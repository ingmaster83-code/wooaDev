Git Branch & Tag Name Validator

Enter branch or tag names to find those that break the git check-ref-format rules, see why, and get a corrected suggestion. Optional team-convention checks cover lowercase and prefixes.

Example

❌ 9 of 12 name(s) violate Git rules

Input — Branch / tag names (one per line)

release/v1.2.0
hotfix..urgent
.hidden
feature/new.lock
my-branch.
@
feat/add-@{x}
-bad

What this tool does

Use it when you get a 'not a valid branch name' error, or when documenting branch naming rules for your team.

  • Rules checked: consecutive dots, spaces and control characters, ~ ^ : ? * [ \, the @{ sequence, a lone @, leading or trailing slash, //, trailing dot, components starting with a dot, .lock endings and a leading -
  • Choose branch, tag or full ref (refs/…)
  • Table of violation reasons and corrected names, for many names at once
  • Team conventions: uppercase (case-insensitive filesystem clashes), mixed _ and -, no prefix, over 60 characters and non-ASCII
  • Explains the path clash between a branch named feature and feature/x

💡 Tips

  • A / makes the ref a folder. While a branch feature exists you cannot create feature/x.
  • Windows and macOS are case-insensitive, so Feature and feature can collide. Stay lowercase.
  • Including an issue number, as in feature/123-add-login, helps traceability.

Frequently Asked Questions

It passes but Git still errors.

A branch with the same name or parent path (feature vs feature/x) may already exist, or a remote branch overlaps. Check git branch -a.

Are non-English branch names allowed?

Git allows them, but encoding problems can appear in some environments, so ASCII is recommended.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
