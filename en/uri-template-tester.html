URI Template (RFC 6570) Tester

Expand a template such as /users/{id}{?page,limit} with variables and inspect the result of every expression.

Example

✅ Expanded 3 expression(s)

Input — URI template (RFC 6570)

https://api.example.com/users/{id}/posts{?page,limit,tags*}{#section}

Input — Variables (JSON)

{
  "id": "42",
  "page": 2,
  "limit": 20,
  "tags": ["a b", "c&d"],
  "section": "top 10"
}

Result — Expanded URI

https://api.example.com/users/42/posts?page=2&limit=20&tags=a%20b&tags=c%26d#top%2010

Result — Expressions

Expression | Operator | Variables | Expansion
{id} | (none) | id | 42
{?page,limit,tags*} | ? | page,limit,tags* | ?page=2&limit=20&tags=a%20b&tags=c%26d
{#section} | # | section | #top%2010

What this tool does

REST API links (HAL, OpenAPI Links, the url fields of the GitHub API) are given as URI templates like "https://api.github.com/repos/{owner}/{repo}/issues{/number}". See what URL results when you supply variables.

  • Operators: {var} simple, {+var} reserved, {#var} fragment, {.var} dot, {/var} path, {;var} semicolon, {?var} query, {&var} query continuation
  • Modifiers: {var:3} prefix (first 3 characters), {list*} explode arrays and objects
  • Variables come as a JSON object (strings, numbers, arrays, objects); undefined ones are omitted
  • A table shows each expression's expansion, with percent-encoding rules (reserved characters allowed or not) applied automatically

💡 Tips

  • Write queries as {?q,page}: the first gets ?, the rest get &.
  • Use {+path} to keep slashes literal and {path} to encode them.
  • An array with {?tags*} gives tags=a&tags=b; with {?tags} it gives tags=a,b.

Frequently Asked Questions

Is a URI template the same as a regex route pattern?

No — a URI template builds URLs by filling in variables (expansion); URLPattern or regexes match incoming URLs. They work in opposite directions.

What happens to undefined variables?

Per RFC 6570 that variable is dropped from the expression. The tool also lists which ones were missing.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
