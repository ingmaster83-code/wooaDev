Give an XML sample to get an XSD with the element hierarchy, child order (sequence / choice / all), minOccurs and maxOccurs, attribute required-ness, types inferred from values (integer, decimal, date, boolean, URI) and enumerations. Choose nested or named-type style.

What this tool does

When an integration has no schema, draft one from sample XML and check it with the validator. Data never leaves your browser.

  • Structure: elements on the same path are merged; xs:sequence when the child order is consistent, xs:all when order varies, an unbounded xs:choice when children interleave
  • Occurrences: required if present under every parent, minOccurs=0 otherwise and maxOccurs=unbounded when repeated
  • Types: boolean, int / long / integer, decimal, date, dateTime, time, anyURI, otherwise string; elements with text and attributes use a simpleContent extension
  • Attributes: use=required when present in every instance and an enumeration when values repeat among few options
  • Style: nested (Russian Doll) or named types (Venetian Blind), xs / xsd prefix and indentation

💡 Tips

  • The more repeats of an element the sample has, the better minOccurs and maxOccurs come out.
  • Validate the original XML with the XSD validator to round-trip check the generated schema.
  • Inference reflects only the sample's values, so review date and number types and enumerations.

Frequently Asked Questions

Does it produce a perfect schema?

No, it is a draft inferred from a sample; variations that are not present (optional elements, other values) are not reflected, so review it.

Can I merge several XML samples?

It merges repeated elements within one document; put several files under a common root to make one sample.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
