CBOR Decoder & Encoder (RFC 8949)

Decodes CBOR bytes from hex, Base64 or a file into a tree with major types, byte offsets and tags, and produces JSON and RFC 8949 diagnostic notation. JSON can be encoded into CBOR too.

What this tool does

Make CBOR from IoT, WebAuthn and COSE readable. Data never leaves your browser.

  • All major types 0–7: integers, byte and text strings, arrays, maps, tags, simple values and floats
  • Half, single and double floats with Infinity and NaN, plus 64-bit integers
  • Tags: date string, epoch time (also shown as ISO), bignums 2 and 3, self-described 55799 and more by name
  • Indefinite-length strings, arrays and maps with break, and notes on deterministic-encoding violations
  • Output: JSON, diagnostic notation (e.g. {"a": 1, "b": [2, 3]}) and a byte-offset table; encode JSON to CBOR

💡 Tips

  • WebAuthn attestationObject and COSE keys are CBOR maps; their integer keys (1, 3, -1 …) become strings in JSON.
  • Tag 24 (embedded CBOR) means a byte string holds another CBOR item; copy the inner bytes and decode them again.
  • Signed data that needs deterministic encoding must avoid indefinite lengths and sort its keys.

Frequently Asked Questions

How does CBOR differ from MessagePack?

Both are binary JSON-like formats, but CBOR is an IETF standard (RFC 8949) with tags, half floats and indefinite lengths.

What is diagnostic notation?

A standard human-readable notation for CBOR: h'0102' is a byte string and 1(1699684224) is a value wrapped in tag 1.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
