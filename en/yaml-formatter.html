YAML Formatter — Fix Indentation, Keep Comments

Unifies messy YAML indentation to 2, 3 or 4 spaces while leaving comments and key order alone, then verifies the data is unchanged.

Example

✅ Formatted — comments and key order kept; semantic equality verified.

Input — YAML input

# service config
service:
    name: api      # keep this comment
    ports:
        - 80
        - 443
    env:
        - name: MODE
          value: prod
    script: |
        echo "start"
        run --fast
  
limits: {cpu: 2, mem: 512}

Result — Formatted YAML

# service config
service:
  name: api      # keep this comment
  ports:
    - 80
    - 443
  env:
    - name: MODE
      value: prod
  script: |
    echo "start"
    run --fast

limits: {cpu: 2, mem: 512}

What this tool does

Many YAML formatters parse and re-emit the file, which erases every comment. The default mode here only recalculates indentation in the text, leaving comments, key order and quoting untouched.

  • Re-indent only: unify to 2/3/4 spaces, trim trailing spaces, keep block scalar (| and >) content
  • The result is parsed again and compared with the original; if the data differs, no output is produced
  • Rewrite structure: full js-yaml re-emit (comments dropped; sort keys, line wrapping and anchors options)
  • Handles multi-document files (---) and mappings inside sequences (- name: x)

Syntax errors are reported with line and column.

💡 Tips

  • Use the default mode for files where comments matter: docker-compose.yml, GitHub Actions, Kubernetes manifests.
  • Tab-indented YAML is invalid; you'll be told to use spaces.
  • Need sorted keys? Switch to "Rewrite structure" (comments will be lost).

Frequently Asked Questions

Can formatting change the meaning of my YAML?

In the default mode the output is parsed again and compared with the input; if anything differs, nothing is output. So a result that changes the meaning is never shown.

Are block scalars with an indentation indicator (|2) supported?

Not in the automatic re-indent mode — you'll get a message. Use "Rewrite structure" for those.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
