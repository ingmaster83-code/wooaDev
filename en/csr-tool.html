What this tool does

Check a CSR before applying for a certificate or create one quickly. The private key is generated only in your browser and never sent.

  • Decode: subject (CN, O, OU, C, ST, L, email), requested SAN and key usage, public key (RSA bits, EC curve), signature algorithm, SHA-256 fingerprint
  • Verify: checks the signature with the CSR's own public key to catch tampering or damage
  • Generate: key type (ECDSA P-256 / P-384, RSA 2048 / 3072 / 4096), CN, organisation, country and SAN (domain, wildcard, IPv4, IPv6, email)
  • Output: CSR (PEM) and private key (PKCS#8 PEM); standard PKCS#10 that passes openssl req -verify
  • Checks: missing SAN, short RSA keys, weak signatures, CN absent from SAN

💡 Tips

  • Submit only the CSR to the CA; keep the private key on your server and send it nowhere.
  • SAN is mandatory today; list the wildcard and the bare domain (example.com) separately to cover both.
  • Extensions in a CSR are only requests that the CA may ignore or change.

Frequently Asked Questions

Can I use a key generated here in production?

It is generated only in the browser, but production keys should be created on the server or an HSM; use this for tests and internal use.

My CSR has a CN but no SAN.

Some public CAs copy the CN into the SAN but it is not guaranteed; recreate the CSR with the domains listed in SAN.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
