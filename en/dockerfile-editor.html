Dockerfile Linter & Formatter

Paste a Dockerfile to get an instruction table (continuations and here-docs handled) plus line-numbered errors such as FROM order, stage names, COPY --from references and EXPOSE ranges, and best-practice problems like latest tags, apt-get usage, running as root and secrets.

Example

⛔ 3 error(s), 5 warning(s) — 2 stage(s), 12 instruction(s)

Input — Dockerfile

# syntax=docker/dockerfile:1
FROM node:latest AS build
WORKDIR /app
COPY . .
RUN npm install && npm run build
RUN apt-get update
RUN apt-get install curl

FROM nginx
COPY --from=build /app/dist /usr/share/nginx/html
COPY --from=builder /app/conf /etc/nginx
ENV API_TOKEN=abc123
EXPOSE 80 99999
CMD nginx -g "daemon off;"

Result — Instructions

Line | Instruction | Arguments
2 | FROM | node:latest AS build
3 | WORKDIR | /app
4 | COPY | . .
5 | RUN | npm install && npm run build
6 | RUN | apt-get update
7 | RUN | apt-get install curl
9 | FROM | nginx
10 | COPY | --from=build /app/dist /usr/share/nginx/html
11 | COPY | --from=builder /app/conf /etc/nginx
12 | ENV | API_TOKEN=abc123
13 | EXPOSE | 80 99999
14 | CMD | nginx -g "daemon off;"

Result — Findings

⚠️ Line 2: Image "node:latest" uses latest, so builds are not reproducible; pin a version
ℹ️ Line 4: COPY . . before installing dependencies busts the cache on every source change; copy only dependency manifests (package.json …) and install first
ℹ️ Line 5: Use npm ci instead of npm install for reproducible builds
⚠️ Line 6: A separate RUN apt-get update can leave a stale cached list; chain it with && apt-get install in the same RUN
⛔ Line 7: apt-get install without -y waits for input and fails the build
ℹ️ Line 7: Use --no-install-recommends to avoid extra packages
ℹ️ Line 7: End the same RUN with rm -rf /var/lib/apt/lists/* to shrink the image
⚠️ Line 9: Image "nginx" has no tag, so latest is used; pin a version
⚠️ Line 9: The final stage runs as root; set a non-root USER
ℹ️ Line 9: No HEALTHCHECK; consider adding one so orchestrators can see health
⛔ Line 11: --from=builder matches no earlier stage (needs FROM … AS builder)
⚠️ Line 12: A secret in ENV API_TOKEN stays in image layers and history; use build secrets (--mount=type=secret) or runtime env
⛔ Line 13: EXPOSE port 99999 is outside 1–65535
ℹ️ Line 14: CMD shell form makes sh PID 1 and SIGTERM is not forwarded; use exec form ["bin", "arg"]

What this tool does

Catch common mistakes in the browser before building the image. Your Dockerfile is not uploaded.

  • Parsing: line continuations (\ or `), comments, parser directives (# escape=), here-docs and mixed-case instructions
  • Errors: instructions before FROM, unknown instructions, duplicate stage names, undefined --from stages, EXPOSE range, missing COPY arguments, invalid exec-form JSON, apt-get install without -y
  • Warnings: latest or untagged images, a separate RUN apt-get update, curl | sh, sudo, chmod 777, secrets in ENV / ARG, relative WORKDIR, final stage running as root
  • Hints (can be hidden): COPY instead of ADD, npm ci, --no-install-recommends, cache cleanup, HEALTHCHECK, COPY . . before dependency install, exec-form CMD
  • Output of a normalised Dockerfile with continuations joined and upper-case instructions

💡 Tips

  • Copy only dependency manifests (package.json …) first and install, then copy the source, to keep the build cache effective.
  • Pass secrets with RUN --mount=type=secret instead of ENV / ARG so they stay out of the image history.
  • Use exec-form CMD (a JSON array) so the termination signal (SIGTERM) reaches your app directly.

Frequently Asked Questions

Is it the same as hadolint?

It covers similar rules but not all of them; it is a quick browser check for core errors and common best practices.

How are multi-stage builds checked?

Each FROM starts a stage; AS names, COPY --from references, unused stages and the final stage's USER and HEALTHCHECK are checked.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
