S3 URL Converter — s3://, https:// & ARN

Converts an S3 object address between the s3:// URI, virtual-hosted HTTPS, path-style HTTPS, legacy endpoints and ARN, and points out bucket-name rule violations.

What this tool does

S3 has several address forms for the same object, and CLI, SDKs, browsers and IAM policies each want a different one.

  • Input: s3:// URI, virtual-hosted (bucket.s3.region.amazonaws.com), path-style (s3.region.amazonaws.com/bucket), legacy s3-region, website and accelerate endpoints, ARN
  • Output: s3 URI, ARN, virtual-hosted, path-style, global legacy, dual-stack (IPv6) and an aws s3 ls command
  • Special and non-ASCII characters in keys are percent-encoded or decoded
  • Bucket name checks: 3–63 characters, lowercase letters, digits, . and -, no consecutive dots, IP-like names or reserved affixes
  • Inputs without a region assume the default region and tell you so

💡 Tips

  • A dot in the bucket name breaks the wildcard certificate of virtual-hosted HTTPS and triggers browser warnings.
  • Use virtual-hosted style in new code; path-style is being phased out.
  • A wrong region gives a 301 redirect; check the real one with aws s3api get-bucket-location.

Frequently Asked Questions

Can I open an s3:// address in a browser?

No. s3:// is a URI for the CLI and SDKs. A browser needs the HTTPS form plus public access or a presigned URL.

Are presigned URLs converted?

The signature query is not converted. Use the tool to read the bucket and key, and create the signature separately.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
