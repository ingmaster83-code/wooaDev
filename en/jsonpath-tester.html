JSONPath Tester — Matches with Their Paths

Run expressions like $.store.book[?(@.price < 10)].title against your JSON and see every matched value with its path.

Example

✅ 2 match(es)

Input — JSON data

{
  "store": {
    "book": [
      { "category": "reference", "author": "Nigel Rees", "title": "Sayings of the Century", "price": 8.95 },
      { "category": "fiction", "author": "Evelyn Waugh", "title": "Sword of Honour", "price": 12.99 },
      { "category": "fiction", "author": "Herman Melville", "title": "Moby Dick", "isbn": "0-553-21311-3", "price": 8.99 },
      { "category": "fiction", "author": "J. R. R. Tolkien", "title": "The Lord of the Rings", "isbn": "0-395-19395-8", "price": 22.99 }
    ],
    "bicycle": { "color": "red", "price": 399 }
  }
}

Input — JSONPath expression

$.store.book[?(@.price < 10)].title

Result — Matches (path + value)

# | Path | Value
1 | $['store']['book'][0]['title'] | "Sayings of the Century"
2 | $['store']['book'][2]['title'] | "Moby Dick"

Result — Values as JSON

[
  "Sayings of the Century",
  "Moby Dick"
]

What this tool does

JSONPath (RFC 9535) is a query language for JSON used by config tools, API gateways and test frameworks. Try your expression on real data before putting it in code.

  • Basics: $.a.b, $['a'], $[0], $[-1], $.*, unions $['a','b']
  • Recursive descent $..price, slices $[1:5:2], reverse $[::-1]
  • Filters [?(@.price < 10 && @.category == 'fiction')], existence [?(@.isbn)], regex [?(@.name =~ /^a/)]
  • Functions length(), count(), match(), search()
  • Each match is shown with its normalized path, e.g. $['store']['book'][0]

Expressions are parsed by the tool itself, never passed to eval, so nothing you type is executed as code.

💡 Tips

  • In filters, quote strings with single or double quotes; write numbers as-is.
  • Copy a result path for use with the JSON Pointer tool or in your code.
  • An expression without a leading $ such as a.b is treated as relative to the root.

Frequently Asked Questions

Why do JSONPath implementations give different results?

Implementations predating the RFC differ in filter syntax and extras like .length. This tool supports RFC 9535 together with the widely used Goessner syntax.

Is my expression sent to a server or evaluated as JavaScript?

No. The expression is parsed by the tool in your browser; it is neither uploaded nor run through eval.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
