Ingress & Service Routing Tester

Paste Ingress and Service manifests and enter request URLs, one per line, to see how each is routed: host (exact and wildcard), path (Exact, Prefix, regex), the longest matching rule, the target Service port and the pod targetPort.

Example

⛔ 1 routing failure(s) — 8 request(s)

Input — Ingress / Service / Deployment manifests (YAML)

apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: main
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /$2
spec:
  ingressClassName: nginx
  tls:
    - hosts: [app.example.com]
      secretName: app-tls
  rules:
    - host: app.example.com
      http:
        paths:
          - path: /api(/|$)(.*)
            pathType: ImplementationSpecific
            backend: { service: { name: api, port: { number: 8080 } } }
          - path: /static
            pathType: Prefix
            backend: { service: { name: static, port: { name: http } } }
          - path: /static/private
            pathType: Exact
            backend: { service: { name: admin, port: { number: 80 } } }
          - path: /
            pathType: Prefix
            backend: { service: { name: web, port: { number: 80 } } }
    - host: "*.example.com"
      http:
        paths:
…

Input — Requests to test (one URL per line)

https://app.example.com/
https://app.example.com/api/users
https://app.example.com/static/logo.png
https://app.example.com/static/private
https://app.example.com/static/private/x

Result — Routing result

Request | Matched rule | Backend | Notes | Class
https://app.example.com/ | main · app.example.com / (Prefix) | web:80 → pod:http | rewrite → / | nginx
https://app.example.com/api/users | main · app.example.com /api(/|$)(.*) (ImplementationSpecific) | api:8080 → pod:3000 | rewrite → /users | nginx
https://app.example.com/static/logo.png | main · app.example.com /static (Prefix) | static:http → pod:80 | rewrite → / | nginx
https://app.example.com/static/private | main · app.example.com /static/private (Exact) | admin:80 | Service "admin" is not in this file · rewrite → / | nginx
https://app.example.com/static/private/x | main · app.example.com /static (Prefix) | static:http → pod:80 | rewrite → / | nginx
http://app.example.com/staticfile | main · app.example.com / (Prefix) | web:80 → pod:http | rewrite → / · a TLS host, so a redirect (308) to https is likely | nginx
https://other.example.com/anything | main · *.example.com / (Prefix) | wildcard:80 | Service "wildcard" is not in this file · rewrite → / | nginx
https://unknown.org/ | — | — | ⛔ No rule matches → 404 (or the default backend) |

Result — Findings

ℹ️ The meaning of the ImplementationSpecific path "/api(/|$)(.*)" depends on the controller (nginx: prefix, or regex with use-regex); this tool follows nginx
Precedence: exact host > wildcard host > no host; within a host Exact beats the longest Prefix. Prefix matches by path element, so /static does not match /staticfile

What this tool does

See before applying an Ingress which requests go to which service. Your manifests are not uploaded.

  • Host: exact > wildcard (*.example.com covers one label) > rules without a host, case-insensitive
  • Path: Exact is a full match, Prefix matches by path element (/foo matches /foo/bar but not /foobar), / matches everything and the longest rule wins
  • ImplementationSpecific: interpreted as nginx does (prefix, or regex with use-regex) with a note that controllers differ
  • Backend: Service name and port (name or number), Service port → targetPort, pods matching the selector and defaultBackend
  • Extras: the nginx rewrite-target result, http → https redirect for TLS hosts, duplicate rules and a missing ingressClassName

💡 Tips

  • When Exact and Prefix share a path, Exact wins.
  • ImplementationSpecific is left to the controller; check its annotations if you need regex.
  • A wildcard host *.example.com matches a.example.com but neither example.com nor a.b.example.com.

Frequently Asked Questions

Is it identical to every Ingress controller?

Standard rules (host and pathType precedence) match, but ImplementationSpecific and annotations vary by controller; this tool follows ingress-nginx.

What if the Service is not in the file?

Only the backend name and port are shown, with a note that the Service is not in the file.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
