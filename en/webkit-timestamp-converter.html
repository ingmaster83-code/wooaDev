WebKit (Chrome) · PRTime · Cocoa Timestamp Converter

Turns Chrome cookie/history database values (microseconds since 1601), Firefox PRTime and Apple Core Data seconds into dates, and converts between them.

What this tool does

Browser and app SQLite databases (Chrome Cookies and History, Safari, iOS apps) store times as huge integers like 13300000000000000 or fractions like 772459815.5. Each uses a different epoch, so reading them as Unix time gives nonsense.

  • Chrome/WebKit: microseconds since 1601-01-01 (cookie expires_utc, visit times)
  • Firefox PRTime: microseconds since 1970-01-01 / Unix microseconds
  • Apple Cocoa (Core Data, NSDate): seconds (with fraction) since 2001-01-01
  • Whichever you enter, UTC ISO (microseconds) and the other epochs' values are shown
  • Enter a date to convert back to the selected epoch's integer

💡 Tips

  • A Chrome cookie with expires_utc = 0 is a session cookie.
  • Digit counts hint at the epoch: ~17 digits = WebKit, 16 = PRTime, 9 digits with fraction = Cocoa.
  • A result in 1601 or 1970 means the wrong epoch was selected.

Frequently Asked Questions

Why does Chrome use 1601?

Chrome uses the same 1601-01-01 epoch as Windows FILETIME but stores microseconds instead of 100 ns. Hence WebKit time = Unix microseconds + 11644473600000000.

Can Cocoa timestamps be negative?

Yes, for times before 2001-01-01. Negative and fractional values are handled.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
