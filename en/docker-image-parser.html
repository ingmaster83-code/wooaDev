Docker Image Name Parser — Registry, Tag & Digest

Splits image references such as nginx, ubuntu:22.04 or ghcr.io/owner/app:v1@sha256:… into registry, repository, tag and digest and normalises them to the full name Docker really pulls.

localhost:5000/my/app@sha256:3d6d3a1c5f0b9c4d5b3c1e2f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b

What this tool does

Image names have many implicit parts (registry docker.io, official images under library/, tag latest), so it is easy to lose track of what is actually pulled. Analyse many lines at once.

  • Split: registry (with port), repository path, tag and @digest
  • Normalise: nginx → docker.io/library/nginx:latest, index.docker.io aliases unified, default registry configurable
  • Identify registries: Docker Hub, GHCR, Quay, Amazon ECR, Google GCR / Artifact Registry, MCR, Azure ACR, GitLab, localhost
  • Validate: lowercase digits and separators in repositories, tags up to 128 allowed characters, digests as sha256:64 hex
  • Findings: latest or missing tag, digest pinning advice, and how the first component is judged to be a registry or a user name

💡 Tips

  • Pin a version tag in production, or best of all an @sha256:… digest, instead of latest.
  • A first component with . or : or equal to localhost is a registry; otherwise it is a Docker Hub user name.
  • Tags may contain uppercase but repository names must be lowercase.

Frequently Asked Questions

What if I give both a tag and a digest?

The digest wins and the tag only remains as a human hint. Even if the tag later points elsewhere, the image pulled by digest does not change.

What is library/?

The Docker Hub namespace of official images (nginx, ubuntu …). nginx is really docker.io/library/nginx.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
