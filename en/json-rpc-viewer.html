JSON-RPC 2.0 Message Viewer & Validator

Classifies requests, notifications, success and error responses and batches, and pairs requests with responses by id. Spec violations such as a missing jsonrpc version, unanswered requests or result with error are flagged and standard codes like -32700 and -32601 explained.

Input — JSON-RPC messages (object, array (batch), or one per line)

[

What this tool does

Make traffic logs of Ethereum nodes, LSP, MCP and other RPC APIs readable. Input is processed only in your browser.

  • Input: a single object, a batch array or one message per line (log style)
  • Classification: request (has id), notification (no id), result response and error response
  • Pairing: request ↔ response by id, unanswered requests, orphan responses and duplicate ids
  • Validation: jsonrpc "2.0", method string, params array or object, exactly one of result and error
  • Standard error codes: -32700 parse error, -32600 invalid request, -32601 method not found, -32602 invalid params, -32603 internal error, -32000 to -32099 server errors

💡 Tips

  • A notification has no id and gets no reply; add an id if you expect one.
  • Batch responses may be in a different order, so pair by id.
  • id may be a string, number or null, but null is discouraged.

Frequently Asked Questions

Is an id of 0 still a request?

Yes, 0 is a valid id. Only a missing id key makes it a notification.

How does it differ from HTTP status codes?

JSON-RPC is transport independent and carries errors in the body's error member; over HTTP the status is usually 200.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
