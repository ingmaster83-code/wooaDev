GitLab CI Pipeline Validator

Paste .gitlab-ci.yml to see a job table and stage order, with line-numbered findings on undefined stages, missing script, needs to later stages or cycles, extends targets, rules mixed with only, boolean variables and retry / when errors.

Example

⛔ 6 error(s), 1 warning(s) — 3 job(s)

Input — .gitlab-ci.yml

stages: [build, test, deploy]

variables:
  NODE_ENV: production
  DEBUG: true

.node:
  image: node:latest
  before_script:
    - npm ci

build:
  extends: .node
  stage: build
  script:
    - npm run build
  artifacts:
    paths: [dist/]

test:
  extends: .nodejs
  stage: test
  script: npm test
  needs: [build, deploy]
  only: [main]
  rules:
    - if: $CI_COMMIT_BRANCH == "main"

deploy:
  stage: deploy
  retry: 5
  when: delayed
  script:
    - ./deploy.sh
  environment: production

Result — Jobs (stage order)

Job | Stage | Image | Script lines | needs | When | Line
build | build | node:latest | 1 | — | on_success | 12
test | test | — | 1 | build, deploy | rules | 20
deploy | deploy | — | 1 | — | delayed | 29

Result — Findings

⛔ Line 5: Variable DEBUG is a boolean; GitLab variable values must be strings, so quote it ("true")
⚠️ Line 13: Image "node:latest" has no tag or uses latest; pin a version
ℹ️ Line 17: Without expire_in, artifacts use the instance default expiry (30 days) of storage
⛔ Line 21: extends refers to missing job (template) ".nodejs"
⛔ Line 24: needs "deploy" (deploy) is in a later stage than "test" (test) and cannot be waited for
⛔ Line 26: Job "test" cannot combine rules with only / except
⛔ Line 31: retry must be 0–2 (got 5)
⛔ Line 32: when: delayed needs start_in (e.g. 30 minutes)

What this tool does

Check the structure before pushing and finding that no pipeline is created. Your file is not uploaded.

  • Job table: stage (default .pre, build, test, deploy, .post), image, script lines, needs, when and line number
  • Inheritance: resolves extends chains so a template's script and image apply; detects cycles and missing targets
  • References: stage definitions, needs targets (existence, later stage, cycles) and dependencies on earlier stages
  • Rules: rules keys and when values, no mixing rules with only / except, quotes and regex (/pattern/) in rules:if, start_in for when: delayed, retry 0–2
  • Variables and security: names, boolean values (must be strings), plain-text secrets, latest images, artifacts paths and expire_in

💡 Tips

  • Variable values must be strings: write DEBUG: "true" instead of DEBUG: true.
  • needs runs jobs as a DAG without waiting for stages, which speeds up pipelines, but only jobs from earlier stages can be listed.
  • Templates pulled in with include are invisible to this tool, so references to them are only warnings.

Frequently Asked Questions

Are anchors and !reference supported?

Anchors and merge keys (<<) are resolved. !reference passes through without resolving its target.

Is it the same as GitLab's CI Lint?

It is not a full server-side validation but a quick way to find common structural errors; confirm with your project's CI Lint.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
