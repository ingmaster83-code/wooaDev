ISO 8601 · RFC 2822 · HTTP Date Converter

Reads ISO 8601, e-mail (RFC 2822) and HTTP header dates and converts them to UTC, Unix time and other notations — fractional seconds are never truncated.

What this tool does

Logs say 2026-10-16T09:30:15.123456789+09:00, mail headers say Thu, 16 Oct 2026 12:00:00 -0500, HTTP responses say Fri, 16 Oct 2026 03:00:00 GMT — the same moment in different notations. Interpret them all in one place.

  • Formats: ISO 8601 (date only, time, fractions, Z / offsets), RFC 2822 and HTTP-date (IMF-fixdate)
  • JavaScript Date stops at milliseconds; this tool uses BigInt to keep up to nanoseconds (9 digits)
  • Output: UTC ISO, original-offset ISO, Unix seconds/milliseconds, RFC 2822, HTTP date, weekday
  • Values without a zone are treated as UTC and labelled as such

💡 Tips

  • A date-time without an offset is read as UTC. For local wall-clock times use the Time Zone Converter.
  • Leave fraction digits on "As input" to keep the precision you typed.
  • When debugging HTTP caching, paste Last-Modified / Expires values here to see them as ISO.

Frequently Asked Questions

Are ISO 8601 and RFC 3339 the same?

RFC 3339 is a profile (subset) of ISO 8601. Common forms such as 2026-10-16T09:30:00Z or 2026-10-16T18:30:00+09:00 satisfy both.

How are leap seconds (23:59:60) handled?

A second value of 60 is accepted and converted to the next minute's :00, because Unix time doesn't count leap seconds separately.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
