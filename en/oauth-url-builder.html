What this tool does

The authorization request URL is where login integrations most often go wrong. Build one with properly encoded parameters, or paste a URL to get each parameter explained and risks flagged.

  • Build: endpoint, client_id, redirect_uri, scope, response_type (code / id_token / hybrid), prompt and extra parameters
  • Empty state and nonce are filled with secure random values; optionally add a PKCE S256 code_challenge
  • Audit: missing state, implicit flow (token), no PKCE, id_token without nonce, http redirect_uri, wildcards
  • A table explains what every parameter means
  • URL encoding (%20 and friends) is handled correctly

💡 Tips

  • redirect_uri must match the registered value character for character, including a trailing slash.
  • Store the state you generate in the session and compare it in the callback (CSRF protection).
  • openid in scope makes it an OIDC request; if you receive an id_token, also validate the nonce.

Frequently Asked Questions

Why is response_type=token dangerous?

The implicit flow puts the access token in the URL fragment where history and referrers can leak it, so OAuth 2.1 removed it. Use authorization code with PKCE.

How do state and nonce differ?

state ties a request to its callback to stop CSRF; nonce ties the issued ID token to this request to stop replay.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
