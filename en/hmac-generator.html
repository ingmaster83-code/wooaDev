What this tool does

An HMAC is a signature only the holder of the secret key can produce, which is why it is used for webhook verification and API authentication. Everything is computed in your browser.

  • Algorithms: HMAC-SHA256 (default), SHA-1, SHA-384, SHA-512
  • Enter key and message as text, hex or Base64
  • Output in hex, Base64 and Base64URL at the same time
  • Paste a received signature (a sha256= prefix is fine) to check for a match
  • Long keys are hashed first exactly as the HMAC standard requires

💡 Tips

  • Compute webhook signatures over the exact raw request bytes, not re-serialised JSON; whitespace and newlines count.
  • On the server compare signatures with a constant-time function (timingSafeEqual) rather than ==.
  • If your key is a hex string, switch the key format to hex; as text it produces a completely different value.

Frequently Asked Questions

How is HMAC different from a plain hash?

Anyone can compute a hash, but an HMAC needs the secret key, so it proves the message is unchanged and was sent by someone holding the key.

Is HMAC-SHA1 still safe?

HMAC is less sensitive to collisions so HMAC-SHA1 is not broken today, but new systems should use SHA-256 or better.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
