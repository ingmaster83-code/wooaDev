JSON to Rust · C# · Dart · Kotlin Model Converter

Turn one JSON sample into Rust (serde), C# (System.Text.Json), Dart (fromJson/toJson) or Kotlin (data class) model code.

Result — Generated code

use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Root {
    pub id: i64,
    pub name: String,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub email: Option<String>,
    pub is_active: bool,
    pub score: f64,
    pub tags: Vec<String>,
    pub address: Address,
    pub created_at: String,
    #[serde(default)]
    pub nickname: serde_json::Value,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Address {
    pub city: String,
    pub zip: Option<String>,
}

What this tool does

Mobile (Flutter, Kotlin) and backend (Rust, C#) teams keep re-typing the same JSON schema as models. Paste once and switch the language.

  • Rust: #[derive(Serialize, Deserialize)], optional fields as Option<T>, #[serde(rename)] where names differ, r#type for keywords
  • C#: System.Text.Json [JsonPropertyName], class or record, nullable reference types (?) option
  • Dart: final fields, required/nullable constructors, fromJson/toJson with casts and double handling
  • Kotlin: kotlinx.serialization @Serializable/@SerialName, optional fields as = null
  • All languages: nested objects split out, arrays → List/Vec, identical shapes reused

Go, Java, Python and Swift have their own dedicated converters.

💡 Tips

  • For Flutter models choose Dart — fromJson/toJson are generated along with the class.
  • For C# projects with nullable reference types, keep the nullable option on (it adds = default!; to cut warnings).
  • For camelCase APIs in Rust, the rename_all option avoids per-field renames.

Frequently Asked Questions

What if a field's type is uncertain?

If samples don't settle on one type (only null, or mixed types), the language's dynamic type is used (serde_json::Value, object, dynamic, JsonElement).

Does the Dart code need json_serializable?

No. The classes implement fromJson/toJson themselves, so no build_runner step is needed.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
