ASN.1 / DER / BER Decoder

Decodes ASN.1 data such as certificates, keys, CSRs and PKCS files from PEM, hex, Base64 or a file into a tree of tag, length and value. OID names, times and strings are shown readably and structures inside OCTET STRINGs are expanded.

Example

✅ Parsed — 52 bytes, 8 nodes, depth 3

Input — ASN.1 data (PEM / hex / Base64)

What this tool does

Check the real structure of PEM certificates, public keys, CSRs and PKCS#7 / 8 data. Data never leaves your browser.

  • Input: PEM (first block), hex, Base64 or a file (.der .cer .pem …)
  • Tree: offset, tag name (SEQUENCE, INTEGER, [0] context …), header and value length, value
  • Values: OBJECT IDENTIFIER names (sha256WithRSAEncryption …), UTCTime and GeneralizedTime, UTF8String and IA5String, bit length of large integers
  • ASN.1 inside OCTET STRING and BIT STRING is expanded automatically (can be turned off)
  • openssl asn1parse style text tree; notes on indefinite-length BER, truncated data and trailing bytes

💡 Tips

  • Use the certificate decoder for certificate fields and this tool for the raw structure.
  • Bracketed tags such as [0] and [1] are context-specific tags from explicit or implicit tagging.
  • The INTEGERs of an RSA private key are long, so only their bit length is shown.

Frequently Asked Questions

DER versus BER?

DER is a strict subset of BER with a single encoding; certificates are DER while some PKCS files are BER with indefinite lengths.

What if the PEM has several blocks?

Only the first is decoded and the rest are noted; use the certificate decoder for bundles.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
