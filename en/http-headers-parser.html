HTTP Headers Parser — Understand and Audit Headers

Paste headers from the browser dev tools or curl -I and get a line of explanation per header plus warnings about missing cookie, cache and security settings.

What this tool does

Makes the Network tab or curl -i output easier to read: requests and responses are told apart automatically and every header gets a one-line explanation.

  • Extracts method, target, protocol and status code from the request/status line; handles folded header lines
  • Interprets Content-Type (media type, charset), Cache-Control directives, Set-Cookie attributes, Strict-Transport-Security duration, Accept q-values, date headers (as ISO) and Content-Length
  • Checks for missing HSTS / X-Content-Type-Options, cookie Secure / HttpOnly / SameSite, missing charset, version disclosure in Server, duplicated single-value headers and no-store vs max-age conflicts
  • Authorization and Cookie values are shown only partially, which is safe when screen-sharing

💡 Tips

  • You can paste the output of curl -sI https://example.com as is.
  • Lowercase header names are normal in HTTP/2 and HTTP/3.
  • Remove secrets before sharing requests with auth headers — this tool only shows a partial value.

Frequently Asked Questions

How are request and response told apart?

A first line like "GET /path HTTP/1.1" is a request and "HTTP/2 200" a response. Without a start line a Host header suggests a request.

Are my headers sent anywhere?

No. Headers may contain cookies or tokens, but all analysis happens inside your browser.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
