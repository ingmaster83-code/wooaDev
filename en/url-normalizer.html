URL Normalizer & Path Joiner

Brings URLs to a canonical form: lowercases scheme and host, drops default ports, resolves ../, sorts the query, removes tracking parameters such as utm_* and resolves relative references.

What this tool does

When the same page appears as HTTP://Example.com:80/a/./b/../c?b=2&a=1 and in other shapes, log aggregation, deduplication, cache keys and canonical tags drift apart. This puts them in one standard form.

  • Always applied: lowercase scheme and host, drop default ports (80/443), resolve ./ and ../, convert the host to Punycode
  • Options: remove fragment, tracking params (utm_*, fbclid, gclid, msclkid …), sort query, strip www., http→https, drop index.html, remove/add trailing slash
  • Percent-encoding tidy-up: %7E → ~ and uppercase hex for the rest
  • With a base URL, relative references such as ../images/a.png, //cdn.example.com/x.js or ?page=2 are resolved to absolute URLs (path joining)
  • Shows what changed per line and the unique count after normalising

💡 Tips

  • For SEO canonicals combine tracking-parameter removal, query sorting and a consistent trailing slash.
  • If the order of query parameters matters for your API, turn off "Sort query".
  • Only the host is case-insensitive; paths are case-sensitive and are left alone.

Frequently Asked Questions

Can normalising turn a URL into a different page?

Only changes the standards treat as equivalent (host case, default ports, dot-segments) and the options you select are applied. Optional steps like removing tracking parameters may mean different things on different sites.

Why isn't path case changed?

Per RFC 3986 paths are case-sensitive and on some servers /A and /a are different resources.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
