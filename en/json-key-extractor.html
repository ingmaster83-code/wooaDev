JSON Key Extractor — Find, Keep or Remove Keys

Collects the values of the keys you name wherever they appear in a JSON document — or keeps only those keys, removes them, or lists every key in use.

Example

✅ Found in 7 place(s)

Input — JSON input

{
  "id": 1,
  "name": "Kim",
  "email": "kim@example.com",
  "orders": [
    { "id": 10, "total": 3200, "items": [{ "id": 1, "name": "pen" }] },
    { "id": 11, "total": 900, "items": [] }
  ],
  "profile": { "id": "p-1", "email": "k@work.com" }
}

Input — Key names (comma or space separated)

id, email

Result — Results

Path | Key | Value
$.id | id | 1
$.email | email | "kim@example.com"
$.orders[0].id | id | 10
$.orders[0].items[0].id | id | 1
$.orders[1].id | id | 11
$.profile.id | id | "p-1"
$.profile.email | email | "k@work.com"

Result — JSON result

[
  1,
  "kim@example.com",
  10,
  1,
  11,
  "p-1",
  "k@work.com"
]

What this tool does

Sometimes you only need every id from a large API response, or you want to strip sensitive keys (password, token) before sharing. Just type the key names — no need to write paths.

  • Find (recursive): every occurrence of the key at any depth, shown with path and value
  • Keep: only the listed keys remain (structure preserved)
  • Remove: delete the listed keys everywhere
  • Key list: every key in use with its count and value types

For exact path-based queries, use the JSONPath Tester or JMESPath Tester.

💡 Tips

  • Before sharing data, use "Remove" with password, token, secret.
  • "Key list" is a quick way to learn all fields of an unfamiliar API response.
  • Ignore-case matches variants such as userId and userid at once.

Frequently Asked Questions

Are same-named keys at different depths all returned?

Yes. Objects and arrays are traversed fully and every match is listed with its path.

What happens to parent objects in "Keep"?

Paths leading to a kept key are preserved; branches without any selected key are dropped.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
