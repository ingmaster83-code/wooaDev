What this tool does

A UUID looks like a random string, but its version digit and variant bits are fixed, and some versions embed a timestamp. Use this when you find a UUID in a log or database and want to know when it was created.

  • Detects the version (v1–v8) and variant (RFC 9562 / Microsoft / NCS), plus Nil and Max UUIDs
  • v1 / v6: decodes the 100 ns timestamp since 1582-10-15, clock_seq and node (MAC or random)
  • v7: extracts the 48-bit Unix millisecond timestamp — the reason v7 keys sort by creation order
  • v3 / v5 are hashes of a namespace and name, so the original name cannot be recovered
  • Accepts 32 hex digits without hyphens, {braces} and urn:uuid: prefixes

💡 Tips

  • A v4 (random) UUID carries no time. If you need a creation time, use v7 or a ULID.
  • v1 / v6 times are in 100-nanosecond units — switch the precision option to see the native value.
  • Paste several lines and compare the time column to see which UUID came first.

Frequently Asked Questions

How is UUID v7 different from v4?

All 122 bits of v4 are random, while v7 starts with a 48-bit Unix millisecond timestamp, so values sort by creation order. That reduces index fragmentation, which makes v7 better for database keys.

Is the node of a v1 UUID really a MAC address?

It was originally, but many implementations use random bytes for privacy. When the multicast bit of the first node byte is 1, the node is flagged as random.
