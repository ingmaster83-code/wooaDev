docker run Command Builder + docker-compose Converter

Fill in image, ports, volumes, environment variables, resource limits and security options to get a docker run command and the equivalent docker-compose.yml. Risky settings are flagged immediately.

Example

✅ docker run command built

Input — Ports (one per line: host:container)

8080:80
127.0.0.1:5432:5432
53:53/udp

Input — Volumes (one per line: source:target[:ro])

./html:/usr/share/nginx/html:ro
pgdata:/var/lib/postgresql/data

Input — Environment variables (KEY=value, one per line)

TZ=Asia/Seoul
POSTGRES_PASSWORD=changeme

Result — docker run command

docker run \
  -d \
  --name web \
  --restart unless-stopped \
  -p 8080:80 \
  -p 127.0.0.1:5432:5432 \
  -p 53:53/udp \
  -v "$(pwd)/html:/usr/share/nginx/html:ro" \
  -v pgdata:/var/lib/postgresql/data \
  -e TZ=Asia/Seoul \
  -e POSTGRES_PASSWORD=changeme \
  nginx:1.27-alpine

Result — docker-compose.yml equivalent

services:
  web:
    image: nginx:1.27-alpine
    container_name: web
    restart: unless-stopped
    ports:
      - "8080:80"
      - "127.0.0.1:5432:5432"
      - "53:53/udp"
    volumes:
      - ./html:/usr/share/nginx/html:ro
      - pgdata:/var/lib/postgresql/data
    environment:
      TZ: "Asia/Seoul"
      POSTGRES_PASSWORD: "changeme"

volumes:
  pgdata:

What this tool does

Fill a form instead of remembering docker run's many options and get a multi-line command plus a docker-compose.yml. Handy for the first container or when moving to compose.

  • Input: image, name, -d / -it / --rm, restart policy, network, ports (host:container[/udp]), volumes, environment, user, working directory, memory and CPU, read-only, cap-drop, no-new-privileges, privileged
  • Output: a multi-line docker run command and the same docker-compose.yml (ports, volumes, networks and named volumes)
  • Port validation (1–65535, bind IP) and relative-path volumes converted to $(pwd)/…
  • 🚨 warnings for database ports (MySQL, PostgreSQL, Redis …) on 0.0.0.0, docker.sock mounts, --privileged and host networking
  • Checks plain-text password variables, running as root, missing memory limit, latest tag and -d with --rm

💡 Tips

  • Bind ports that need no outside access to localhost, such as 127.0.0.1:5432:5432. On Linux ports opened with -p can bypass ufw rules.
  • Do not pass passwords with -e; use --env-file or Docker secrets. They are visible via docker inspect.
  • For production consider --user, --memory, --read-only and --cap-drop ALL by default.

Frequently Asked Questions

Relative ./ volumes fail in docker run.

docker run -v accepts absolute paths only, so use $(pwd)/path (PowerShell: ${PWD}). docker-compose accepts ./ as is.

Can I combine --restart and --rm?

Docker rejects it. --rm deletes the container on exit, which contradicts a restart policy.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
