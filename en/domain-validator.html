What this tool does

When a form accepts a domain or you audit a host list in a config file, one regex misses many rules. Each label is checked on its own and failures are explained.

  • Domain mode: at least two labels including a TLD; hostname mode (single labels allowed); DNS-name mode (underscores allowed: _dmarc, _domainkey)
  • Rules: labels 1–63 characters, 253 total, letters/digits/hyphens only, no leading/trailing hyphen, no empty labels (..), no all-digit TLD
  • Distinguishes IP addresses mistaken for domains and URLs (spaces, / : @) pasted by mistake
  • Options for wildcards (*.example.com) and IDN; allowed IDNs are shown normalised as Punycode
  • Valid entries can be copied separately

💡 Tips

  • Use hostname mode for sign-up forms and domain mode for e-mail domains.
  • TXT record names such as _dmarc.example.com only pass in DNS-name mode.
  • The tool checks format only — it doesn't verify that the TLD exists.

Frequently Asked Questions

Is a name with an underscore invalid?

It isn't allowed in hostnames (web server addresses) but is fine in DNS record names (_dmarc, _sip._tcp…). Pick the mode that matches your use.

Why 253 characters at most?

The wire format limits a whole name to 255 bytes; after the length bytes and the root label, that leaves 253 characters of text.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
