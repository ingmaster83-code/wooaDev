What this tool does

Oddities like 0.1 + 0.2 ≠ 0.3 all come from floating-point representation. See exactly which bits get stored and how large the error is.

  • Number → bits: split into 1 sign bit | exponent (5/8/11 bits) | fraction (10/23/52 bits) and show hex
  • Bits → number: interpret a pattern like 0x40490FDB as a float (or treat 0x values as plain integers)
  • Shows the actually stored value and the absolute error (e.g. float32 0.1 = 0.10000000149011612)
  • Classifies normal, subnormal, zero, infinity and NaN (quiet/signaling) and shows the exponent
  • The 16-bit (half) conversion helps inspect formats used in machine learning and graphics

💡 Tips

  • float32 holds about 7 decimal digits exactly, float64 about 15–16.
  • Dyadic fractions (0.5, 0.25, 0.125) are stored exactly; values like 0.1 that repeat in binary cause the error.
  • Subnormals trade precision for a smooth gradual underflow near zero.

Frequently Asked Questions

Why isn't 0.1 exact as a float?

In binary 0.1 is 0.0001100110011… repeating forever, so a finite fraction can only hold an approximation.

What's the difference between quiet and signaling NaN?

If the top fraction bit is 1 it's a quiet NaN (propagates silently); if 0 it's a signaling NaN (may raise an exception).
