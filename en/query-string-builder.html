Query String Parser & Builder

Decode a URL's query string into a table and JSON (arrays and nesting included), or build a correctly encoded query string from a JSON object.

Example

✅ 9 parameter(s) · path https://example.com/search · fragment #results · repeated keys: tag

Input — Input

https://example.com/search?q=hello+world&tag=a&tag=b&filter[status]=open&filter[owner]=kim&ids[]=1&ids[]=2&empty=&page=2#results

What this tool does

When an API call fails, the query string is the first suspect. Inspect decoded values and the array/nesting structure.

  • Parse: a full URL or ?a=1&b=2 → parameter table (decoded value, raw), repeated keys flagged, path and #fragment split off
  • To JSON: repeated keys (tag=a&tag=b) and a[]=1 / a[0]=1 become arrays, filter[status]=open becomes a nested object (switchable)
  • Build: JSON object → query string. Arrays as repeats (a=1&a=2), brackets (a[]=), indexes (a[0]=) or commas (a=1,2)
  • Options: spaces as %20 or +, sort keys, skip null/empty values, flatten objects as a[b]=1
  • '+' is decoded as a space and %XX as UTF-8 characters

💡 Tips

  • Array syntax varies by framework: Express (qs), PHP and Rails use a[]=, while Spring expects repeated keys.
  • If non-ASCII text looks garbled, check for UTF-8 percent-encoding like %ED%95%9C — this tool decodes it automatically.
  • A space may be + in a query but only %20 is valid in a path.

Frequently Asked Questions

Are '+' and '%20' the same?

In a query string (application/x-www-form-urlencoded) both mean a space. In a URL path, + is just a plus sign.

What happens when a key repeats?

Servers differ: first value, last value or an array. This tool collects them into an array and flags the repeated key.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
