AES Encrypt & Decrypt (GCM, CBC, CTR)

Encrypts and decrypts text with AES-128/192/256 in GCM, CBC or CTR mode. Key, IV, auth tag and AAD are handled separately, which helps when matching a server implementation; empty key and IV fields are filled randomly.

What this tool does

Decode AES ciphertext from another language or server, or check that two implementations agree. Keys and data never leave your browser.

  • Modes: AES-GCM (16-byte tag, AAD), AES-CBC (PKCS#7 padding) and AES-CTR (64-bit counter)
  • Key: 16 / 24 / 32 bytes as hex, Base64 or UTF-8; empty key and IV are generated randomly when encrypting
  • Result: ciphertext, detached auth tag, IV‖ciphertext‖tag in one piece, as hex or Base64
  • Decrypt: GCM with an appended or separate tag, an option to take the IV from the front, and diagnosis of a tag mismatch (tampering, wrong key, IV or AAD)
  • Matches NIST test vectors; mode-specific security notes (nonce reuse, CBC integrity)

💡 Tips

  • Reusing a nonce with the same key in GCM completely breaks its security; use a new one per message.
  • Most decryption failures come from a different key, IV or AAD, or a different hex / Base64 reading.
  • CBC and CTR do not detect tampering; use GCM when integrity matters.

Frequently Asked Questions

Is the tag appended or separate?

Web Crypto and Java append the tag to the ciphertext, while OpenSSL and some libraries return it separately; the tool supports both.

May I enter real secrets?

Input is not sent to any server, but this is a tool for testing and learning; handle production secrets in servers or a KMS.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
