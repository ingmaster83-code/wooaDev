💡 Tips

  • sub: subject (user ID), iss: issuer, exp: expiry (Unix timestamp)
  • JWT payload is Base64URL encoded — it is NOT encrypted, just signed
  • Never put sensitive data (passwords, credit cards) in the payload
  • HS256 uses a shared secret; RS256 uses a public/private key pair

FAQ

How does JWT work?
A JWT consists of three parts: Header.Payload.Signature. The server signs the token with a secret key. Clients send the JWT with each request, and the server verifies the signature to confirm authenticity without a database lookup.
Can anyone read the JWT payload?
Yes — the payload is Base64URL encoded, not encrypted, so anyone can decode it. JWT security relies on signature verification, not secrecy. Never put sensitive information in the payload.
