Stack Trace Formatter — Auto-Detects the Language

Detects the language of a long error stack trace, splits it into frames (function, file, line) and highlights frames belonging to your own packages so you know where to look first.

What this tool does

Strip library frames out of dozens of lines and find your own code. Logs are processed only in your browser.

  • Language detection: Java / Kotlin, Python, JavaScript (V8 and Firefox styles), .NET, Go, Ruby, PHP
  • Table: frame number, cause level (top / Caused by), function, file:line(:column) and kind (your code / library / other)
  • Give your code prefixes (com.shop, /app/src …) to mark those frames with ⭐ and name the first one to inspect
  • Handles Caused by chains (the root cause is usually the last) and "... 12 more" omitted frames
  • Notes that minified bundles (.min.js) need a source map

💡 Tips

  • The last Caused by is usually the root cause; read your frames above it first.
  • Stack traces can contain file paths, internal class names and values; review before sharing.
  • Production JS needs a source map to recover original positions (this tool does not read source maps).

Frequently Asked Questions

Why is the language not detected?

Check that lines look like frames such as 'at … (file:line)' or 'File "…", line N'. Removing log prefixes such as timestamps helps.

How are async frames shown?

Async frames without a file and line are left out; only frames with file information appear.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
