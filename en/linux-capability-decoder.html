Linux Capability Decoder & Encoder

Decodes hex values such as CapEff from /proc/PID/status into CAP_ names with descriptions and risk levels, and turns a list of capability names into a mask, docker --cap-add flags and a Kubernetes securityContext.

Example

✅ 14 capabilities · highest risk: high

Input — Capability value (hex mask or list of CAP_ names)

00000000a80425fb

Result — Capabilities

Bit | Name | What it allows | Risk
0 | CAP_CHOWN | Change file owner (uid/gid) arbitrarily | low · Docker default
1 | CAP_DAC_OVERRIDE | Bypass file read / write / execute permission checks | medium · Docker default
3 | CAP_FOWNER | Perform owner-only operations (chmod …) on any file | low · Docker default
4 | CAP_FSETID | Keep set-user-ID / set-group-ID bits | low · Docker default
5 | CAP_KILL | Send signals to other users' processes | low · Docker default
6 | CAP_SETGID | Change GID arbitrarily | medium · Docker default
7 | CAP_SETUID | Change UID arbitrarily (can become root) | high · Docker default
8 | CAP_SETPCAP | Modify capabilities of other processes | medium · Docker default
10 | CAP_NET_BIND_SERVICE | Bind to ports below 1024 | low · Docker default
13 | CAP_NET_RAW | RAW and PACKET sockets (ping, sniffing, spoofing) | medium · Docker default
18 | CAP_SYS_CHROOT | Use chroot | medium · Docker default
27 | CAP_MKNOD | Create special files (device nodes) | medium · Docker default
29 | CAP_AUDIT_WRITE | Write to the kernel audit log | low · Docker default
31 | CAP_SETFCAP | Set file capabilities | medium · Docker default

# Docker/Podman
docker run --cap-drop ALL --cap-add CHOWN --cap-add DAC_OVERRIDE --cap-add FOWNER --cap-add FSETID --cap-add KILL --cap-add SETGID --cap-add SETUID --cap-add SETPCAP --cap-add NET_BIND_SERVICE --cap-add NET_RAW --cap-add SYS_CHROOT --cap-add MKNOD --cap-add AUDIT_WRITE --cap-add SETFCAP …
# Identical to the 14 capabilities of Docker's default set

securityContext:

What this tool does

When auditing a container's privileges, the hex from grep Cap /proc/self/status is unreadable. This tool turns it into names and meanings.

  • Input: a hex mask (0x prefix allowed) or a list of CAP_ names (prefix optional, lowercase and commas fine, ALL supported)
  • Output: bit number, name, description, risk level and whether it is in Docker's default set
  • Conversions: CapEff mask, getpcaps / capsh names, docker run --cap-drop ALL --cap-add …, Kubernetes securityContext
  • Shows differences from Docker's default 14 (added / dropped)
  • 🚨 warnings for powerful capabilities such as CAP_SYS_ADMIN, SYS_MODULE, SYS_PTRACE, SYS_RAWIO, DAC_READ_SEARCH and MAC_OVERRIDE

💡 Tips

  • To keep only what you need, --cap-drop ALL and then --cap-add the minimum.
  • A service that only binds ports below 1024 needs just NET_BIND_SERVICE.
  • CAP_SYS_ADMIN is nearly root and a common container-escape route, about as dangerous as --privileged.

Frequently Asked Questions

What are CapInh, CapPrm, CapEff, CapBnd and CapAmb?

Eff (effective) is what the process can use right now, Prm (permitted) the upper bound it may hold, Bnd (bounding) the maximum children can gain. CapEff is usually the one to read.

What does 0000003fffffffff mean?

Bits 0–37 (38 capabilities) are set, the full set of a root process on kernels before 5.8. Newer kernels go up to bit 40, so the full set is 000001ffffffffff.
