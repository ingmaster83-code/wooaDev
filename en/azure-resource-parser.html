Azure Resource ID, SAS & Connection String Parser

Splits resource IDs such as /subscriptions/…/providers/Microsoft.Compute/virtualMachines/vm1, blob URLs with SAS tokens and storage connection strings into parts, and flags expiry, excessive permissions and exposed keys.

What this tool does

Turns the long resource IDs, SAS URLs and connection strings from the Azure portal, ARM templates and CLI into something readable. Secret values are masked on screen.

  • Resource ID: subscriptionId (GUID check), resourceGroup, provider, resource type and the name hierarchy (parent / child)
  • Blob URL: storage account, container, path and SAS fields (sv, sp, se, st, spr, sr)
  • SAS checks: expired, no expiry, write / delete permission, HTTP allowed
  • Connection string: shows AccountName and EndpointSuffix, masks AccountKey and SharedAccessSignature
  • Resource IDs are case-insensitive, so compare them in lowercase

💡 Tips

  • Create SAS tokens with short expiry and minimum permissions (read only); use managed identities for long-lived access.
  • Do not keep connection strings with AccountKey in code or logs; store them in Key Vault.
  • When comparing resources across ARM templates, lowercase the whole ID first.

Frequently Asked Questions

What is the sig in a SAS token?

An HMAC signature over the token contents. Anyone holding it has the same permissions until expiry, so share it carefully.

Managed identity or SAS?

A managed identity is safer because no secret lives in code. SAS is handy for temporary access by outsiders.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
