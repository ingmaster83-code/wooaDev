What this tool does

For when the device token you register with your iOS push server differs in format between logs, databases and libraries.

  • Input: <spaced hex>, contiguous hex (any case), Base64 / Base64URL, one per line
  • Output: lowercase hex for your server, an 8-char grouped readable form and Base64
  • Validation: normally 32 bytes (64 digits); warns when shorter than 32 or longer than 100
  • App code samples: Swift Data → hex, Node Base64 → hex and Python
  • Reminds you to size the storage column generously because length can change

💡 Tips

  • Sandbox and production tokens are not interchangeable; match the APNs endpoint.
  • Reinstalling or restoring an app can change the token, so register it at every launch.
  • An Android FCM registration token is a different value from an APNs token.

Frequently Asked Questions

May I store the token in uppercase?

APNs ignores case, but storing lowercase consistently makes duplicate comparison easy.

My token is not 64 characters; is that fine?

Apple says token length may grow, with up to 100 bytes allowed, so do not hard-code 64.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
