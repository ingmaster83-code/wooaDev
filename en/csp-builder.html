CSP Builder & Analyzer — Content-Security-Policy

Build a Content-Security-Policy from presets, find weaknesses in an existing policy (unsafe-inline, wildcards) and test whether a given script or image request would be allowed.

Example

🔍 4 finding(s)

Input — CSP to analyse / test

default-src 'self'; script-src 'self' https://cdn.example.com 'unsafe-inline'; img-src 'self' data: https:; object-src *; frame-ancestors 'self'

Input — Requests to test (one per line: type URL)

script https://cdn.example.com/app.js
script https://evil.example.net/x.js
img https://images.example.org/a.png
style inline
connect https://api.example.com/v1

Input — Page origin (self)

https://www.example.com

Result — CSP

default-src 'self'; script-src 'self' https://cdn.example.com 'unsafe-inline'; img-src 'self' data: https:; object-src *; frame-ancestors 'self'

Result — Directives

Directive | Sources | Meaning
default-src | 'self' | Fallback for other fetch directives
script-src | 'self' https://cdn.example.com 'unsafe-inline' | Script sources
img-src | 'self' data: https: | Image sources
object-src | * | <object>/<embed> sources
frame-ancestors | 'self' | Who may embed this page (clickjacking)

What this tool does

CSP is the strongest defence against the impact of XSS, but a wrong policy breaks the site. Build, audit and test it here.

  • Build: strict / SPA + external API / typical-site presets, add script, style, img, connect and frame sources, upgrade-insecure-requests, report-uri and Report-Only
  • Audit: unsafe-inline and unsafe-eval, wildcards (*), http: sources, missing object-src, base-uri and form-action
  • Test: give the page origin and a list of requests (type URL) to see which are blocked, per directive
  • Falls back to default-src and matches 'self', hosts and schemes the way browsers do
  • A table explains each directive

💡 Tips

  • Start with Content-Security-Policy-Report-Only to collect violations before enforcing.
  • If you need inline scripts, use a nonce or a hash (sha256-…) instead of unsafe-inline.
  • object-src 'none'; base-uri 'self'; are safe additions for almost every site.

Frequently Asked Questions

Adding CSP broke my site.

Inline scripts and styles, external CDNs or analytics got blocked. Use Report-Only to list the violations and then allow only the sources you need.

Can I use a meta tag for CSP?

Some directives work, but frame-ancestors, report-uri and sandbox are ignored in meta. Prefer the HTTP header.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
