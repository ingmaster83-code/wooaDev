JSON Validator — Find Syntax Errors & Duplicate Keys

Pinpoints the exact line and column of a JSON syntax error and catches duplicate keys that JSON.parse silently overwrites.

Example

❌ Invalid JSON — Trailing commas are not allowed (line 4, col 17)

Input — JSON input

{
  "name": "WooaDev",
  "tools": [1, 2, 3],
  "active": true,
}

Result — Error location

     2 │   "name": "WooaDev",
     3 │   "tools": [1, 2, 3],
▶    4 │   "active": true,
       │                 ^ Trailing commas are not allowed
     5 │ }

What this tool does

JSON.parse() usually reports little more than "Unexpected token", and when the same key appears twice it quietly keeps the last value. This validator reads your JSON with its own parser, so it can explain what went wrong and exactly where.

  • Plain-language messages for trailing commas, single quotes, unquoted keys, comments, undefined and NaN
  • Lists repeated keys within the same object, with the path and position (the later value overwrites the earlier one)
  • Summarises depth, object/array/string/number counts and byte size

If the JSON is too broken to fix by hand, try the JSON Repair tool; to make it readable, use the JSON Formatter.

💡 Tips

  • The line marked ▶ is where the parser first noticed the problem. The real cause is often the line just above (an unclosed quote or bracket).
  • Run the duplicate-key check on config files, where the same key is easy to paste twice by mistake.
  • Leading zeros (007), hex numbers (0xFF) and Infinity are not allowed in JSON.

Frequently Asked Questions

JSON.parse errors don't tell me where the problem is.

Error wording differs between browsers and often has no position. This tool uses its own parser and shows the line, column and surrounding lines, so you can find the mistake immediately.

Are duplicate keys invalid JSON?

RFC 8259 only says keys SHOULD be unique; it doesn't make duplicates a syntax error. But parsers differ (most keep the last value), which can lead to unintended settings, so they are reported separately.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
