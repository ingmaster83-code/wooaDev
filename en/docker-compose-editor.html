Docker Compose Workbench & Checker

Paste a docker-compose.yml to get a service table and line-numbered findings: host port conflicts, missing or cyclic depends_on, undefined networks and volumes, duplicate container_name, typos, latest images, privileged mode and plain-text secrets, plus the start order.

Example

⛔ 5 error(s), 2 warning(s) — 3 service(s)

Input — docker-compose.yml

version: "3.8"
services:
  web:
    image: nginx:latest
    ports:
      - "8080:80"
      - "127.0.0.1:9000:9000"
    depends_on:
      - api
      - cache
    networks: [front]
  api:
    build: ./api
    container_name: api
    ports:
      - "8080:3000"
    environment:
      DB_URL: postgres://${DB_USER}:${DB_PASS:-secret}@db/app
    depends_on:
      db:
        condition: service_healthy
    volumes:
      - data:/var/lib/app
      - ./conf:/etc/app:ro
    networks: [front, back]
  db:
    image: postgres:16
    privileged: true
    networks: [back]
    volumes:
      - pgdata:/var/lib/postgresql/data
networks:
  front: {}
volumes:
  pgdata:
  unused:

Result — Services

Service | Image / build | Ports | depends_on | Networks | Line
web | nginx:latest | 8080:80, 127.0.0.1:9000:9000 | api, cache | front | 3
api | build: ./api | 8080:3000 | db | front, back | 12
db | postgres:16 | — | — | back | 26

Result — Findings

ℹ️ Line 1: The version field is obsolete in Compose v2+ and ignored
ℹ️ Line 1: Variables without defaults (DB_USER) must be defined in an .env file or the shell (otherwise an empty-string warning)
⚠️ Line 4: Image "nginx:latest" uses latest; pin a version
⛔ Line 8: depends_on refers to missing service "cache"
⛔ Line 16: Host port tcp 8080 conflicts between "web" (line 6) and "api"
ℹ️ Line 19: Unless the "db" image ships a healthcheck, service_healthy waits forever; define a healthcheck in compose
⛔ Line 22: Service "api" uses undefined volume "data" (declare it under top-level volumes)
⛔ Line 25: Service "api" uses undefined network "back"
⚠️ Line 28: Service "db" is privileged: true, which grants host-wide power; use only when necessary
⛔ Line 29: Service "db" uses undefined network "back"
ℹ️ Line 36: No service uses volume "unused"

What this tool does

Find errors in a compose file that would otherwise show up only at run time. Your file is not uploaded.

  • Service table: image or build, ports, depends_on, networks and line numbers
  • Ports: short and long syntax, no conflict when host IPs differ, range checks, warning for unquoted NN:NN
  • References: depends_on targets and conditions (service_healthy needs a healthcheck), network and volume definitions, unused ones, cycle detection and a topologically sorted start order
  • Typos in service keys, the obsolete version field, duplicate container_name and scaling, restart values, and the list of interpolated variables (${VAR:-default})
  • Security: latest or untagged images, privileged, network_mode: host and plain-text secrets in environment

💡 Tips

  • Quote ports like "8080:80"; YAML 1.1 parsers can read NN:NN as a base-60 number.
  • depends_on alone does not wait until a service is ready; combine condition: service_healthy with a healthcheck.
  • Keep secrets in an .env file or secrets and add it to .gitignore.

Frequently Asked Questions

Can I delete the version field?

In Compose v2+ version is obsolete and ignored, so removing it changes nothing.

Is a shared host port always an error?

Using the same protocol and port on the same host IP (or no IP) conflicts; binding to different host IPs is fine.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
