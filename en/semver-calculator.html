💡 Tips

  • Bump major for breaking API changes, minor for backward-compatible new features, patch for bug fixes.
  • Before 1.0.0 (0.x.y), the API is implicitly allowed to change at any time.
  • Prerelease versions (e.g. 2.0.0-beta.1) always rank below the plain release.

Frequently Asked Questions

What is Semantic Versioning (SemVer)?

A versioning scheme in the format major.minor.patch. Bump major for breaking API changes, minor for backward-compatible feature additions, and patch for bug fixes.

How are prerelease and build metadata compared?

A version with a prerelease tag (e.g. 1.0.0-alpha) ranks lower than the plain release (1.0.0). Build metadata (starting with +) has no effect on version precedence.

Are inputs stored on a server?

No. All calculations happen entirely in your browser and inputs are never sent to a server.
