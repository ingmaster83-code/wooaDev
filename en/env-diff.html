ENV Diff — Find Missing, Added and Changed Variables

Compares two .env files, shows variables that exist on one side only or differ in value, and gives you the missing keys ready to paste.

Example

🔍 Missing in B 1 · Only in B 1 · Changed 3 · Same 2

Input — Reference file (A) — e.g. .env.example

# app
NODE_ENV=development
PORT=3000
DATABASE_URL=postgres://user:pass@localhost:5432/app
REDIS_URL=redis://localhost:6379
JWT_SECRET=changeme
SENTRY_DSN=

Input — File to check (B) — e.g. .env

NODE_ENV=production
PORT=8080
DATABASE_URL=postgres://app:s3cret@db.internal:5432/app
JWT_SECRET=changeme
SMTP_HOST=smtp.example.com
SENTRY_DSN=

Result — Comparison

Variable | Status | A | B
NODE_ENV | Changed | development | production
PORT | Changed | 3000 | 8080
DATABASE_URL | Changed | postgres://user:pass@localhost:5432/app | postgres://app:s3cret@db.internal:5432/app
REDIS_URL | Missing in B | redis://localhost:6379 | 
JWT_SECRET | Same | changeme | changeme
SENTRY_DSN | Same |  | 
SMTP_HOST | Only in B |  | smtp.example.com

Result — Keys missing in B (ready to paste)

REDIS_URL=

What this tool does

The classic onboarding or deployment failure is one missing environment variable. Paste a reference file (A) and the real one (B) to see the differences at a glance.

  • Classifies each variable as missing in B / only in B / changed / same, with colours
  • Parses export prefixes, quotes, inline comments (# …) and multi-line values correctly
  • "Mask values" lets you compare while sharing your screen without exposing secrets
  • Collects keys missing in B as KEY= lines ready to paste
  • Duplicate keys and malformed lines are flagged as warnings

💡 Tips

  • Use .env.example as A and your real .env as B to check only for missing variables.
  • Turn off "Compare values too" to check key presence only — useful when values legitimately differ per environment.
  • Enable "Mask values" before showing files that contain secrets.

Frequently Asked Questions

Is the content of my .env stored anywhere?

No. Everything is processed in your browser; nothing you type is sent to a server or stored.

Are quoted and unquoted values compared differently?

No. KEY="a b" and KEY=a b are equal if the parsed values match.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
