MongoDB ObjectId Decoder, Generator & Date-Range Query

Breaks a 24-hex ObjectId into creation time, per-process random value and counter, generates new ObjectIds and builds ready-to-use _id bounds for a date range.

What this tool does

The first four bytes of a MongoDB ObjectId are a timestamp, so time-range queries work without a separate createdAt field.

  • Decode: splits 12 bytes into [timestamp 4][random 5][counter 3] and shows the time in UTC and your zone
  • Accepts ObjectId("…") and {"$oid": "…"}; several lines are sorted to show creation order
  • Generate: N ObjectIds with a per-process random value and an incrementing counter, like real drivers
  • Date range → bounds: enter a start and end to get a find({_id:{$gte,$lt}}) query and a JSON query
  • Implausible times (before 2009 or after 2040) are flagged as probably not ObjectIds

💡 Tips

  • An _id range query uses the default _id index, so it is fast without a createdAt index.
  • The time has one-second resolution; the counter orders ObjectIds within the same second.
  • An ObjectId reveals when it was created; consider that before exposing it as a public ID.

Frequently Asked Questions

How is an ObjectId different from a UUID?

It is 12 bytes (24 hex digits), shorter, and sorts roughly by creation time. UUID v4 is fully random with no order.

Can ObjectIds collide?

The counter separates IDs within one process and the random part separates processes, so collisions are practically impossible.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
