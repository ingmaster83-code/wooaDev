JMESPath Tester

Run JMESPath expressions such as people[?age > `30`].name against your JSON and inspect filter, projection and function results.

Example

✅ Result type: array (2)

Input — JSON data

{
  "people": [
    { "name": "Kim", "age": 29, "state": { "name": "WA" }, "tags": ["dev", "ops"] },
    { "name": "Lee", "age": 41, "state": { "name": "NY" }, "tags": ["dev"] },
    { "name": "Park", "age": 35, "state": { "name": "WA" }, "tags": [] }
  ]
}

Input — JMESPath expression

people[?age > `30`].{name: name, state: state.name}

Result — Result

[
  {
    "name": "Lee",
    "state": "NY"
  },
  {
    "name": "Park",
    "state": "WA"
  }
]

What this tool does

JMESPath is the query language behind the AWS CLI (--query), Azure CLI, Ansible and Terraform output handling. Try your expression on a real response before using it in a command.

  • Filters people[?age > 30], projections people[*].name, slices items[1:3]
  • Multiselect {name: name, state: state.name}, pipes a | b
  • Official functions such as length(), sort_by(), max_by(), join(), contains(), keys(), values()
  • Literals use backticks (30, "text"); string comparisons use single quotes ('WA')

If you also need matched paths, use the JSONPath Tester; for one exact location, the JSON Pointer tool.

💡 Tips

  • Check an AWS CLI --query expression here first, then wrap it in single quotes in your shell.
  • Use backticks for number/string literals and single quotes for strings compared with fields.
  • A null result usually means a misspelled field or wrong letter case.

Frequently Asked Questions

How is JMESPath different from JSONPath?

JMESPath is a separate, strictly specified language with projections, pipes and built-in functions; JSONPath is an XPath-like path notation. Their syntaxes are not compatible.

How are errors shown?

The syntax error reported by the library is displayed as-is. Check that brackets, backticks and quotes are balanced.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
