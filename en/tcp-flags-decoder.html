What this tool does

Use it to decode the flags value you see in Wireshark or tcpdump, or to get the bit value when writing a firewall rule or packet filter.

  • Input: 0x12, 18, 0b010010, SYN+ACK, SYN,ECE,CWR, tcpdump notation S. / P. / FPU
  • Output: the set flags, hex/decimal/binary values, tcpdump notation and meaning (0x02 = connection request, 0x12 = accepted)
  • Known combos: SYN / SYN+ACK / ACK, PSH+ACK, FIN+ACK, RST, NULL (0x00), XMAS (FIN+PSH+URG), FIN scan, ECN setup
  • 9-bit flags (including NS) and a per-bit reference table

💡 Tips

  • For a tcpdump filter such as tcp[tcpflags] & tcp-syn != 0, use this tool to confirm the numeric values.
  • Many packets with SYN but no ACK can indicate a SYN flood or a port scan.
  • In tcpdump a '.' means ACK ([S.] = SYN+ACK).

Frequently Asked Questions

Which flags make up the three-way handshake?

Client SYN (0x02) → server SYN+ACK (0x12) → client ACK (0x10).

Why are NULL and XMAS scans suspicious?

They use flag combinations (0x00, FIN+PSH+URG) that never occur in normal traffic to slip past simple firewalls and probe for open ports, so IDS systems flag them.
