What this tool does

When Athena is too heavy for a quick check, turn a few log lines into something readable. Logs are processed only in your browser.

  • Auto-detect: ALB (http / https / h2 / ws …), NLB (tls), CloudFront (#Fields header + tabs) and S3 server access logs
  • ALB: 30-field CSV, summary of time, client, request, ELB / target status and processing time, with 5xx, 502 without target response and slow requests marked
  • CloudFront: CSV using the header's field names, edge location, result type and cache hit ratio
  • S3: field names from bucket owner to TLS version, with operation, key and status
  • Quoted values (request line, user agent) are split correctly

💡 Tips

  • An ALB 502 with target status - means the target closed the connection or sent no reply; check health checks and keep-alive timeouts.
  • A CloudFront Error result can be an origin or a request error; look at x-edge-detailed-result-type.
  • For bulk analysis create an Athena table and query with SQL.

Frequently Asked Questions

My log is a gzip file.

Decompress it first and paste the text; this tool handles text only.

What if the CloudFront header is missing?

The #Fields line is needed for the names; paste the first two lines (#Version, #Fields) with the entries.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
