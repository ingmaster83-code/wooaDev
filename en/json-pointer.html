JSON Pointer (RFC 6901) Tool

Resolve a JSON Pointer such as /users/0/name to its exact value, and generate pointers, URI fragments and JSONPath forms for every value.

Example

✅ Found a value (string)

Input — JSON data

{
  "users": [
    { "name": "Kim", "tags": ["a/b", "c~d"] },
    { "name": "Lee" }
  ],
  "a/b": { "m~n": 100 },
  "my key": true
}

Input — JSON Pointer

/users/0/tags/0

Result — Pointer info

Normalized pointer: /users/0/tags/0
URI fragment form: #/users/0/tags/0
JSONPath form: $['users'][0]['tags'][0]

Result — Value

"a/b"

What this tool does

JSON Pointer (RFC 6901) is the standard way to address a single value inside a JSON document; JSON Schema's $ref and JSON Patch (RFC 6902) both use it.

  • Enter /users/0/name to get the value, normalized pointer, URI fragment (#/users/0/name) and JSONPath ($['users'][0]['name'])
  • The ~1 (for /) and ~0 (for ~) escape rules are applied automatically
  • URI fragment input such as #/my%20key is supported
  • "List all pointers" shows the pointer, type and value of every node

For conditional lookups that return many values, the JSONPath Tester is a better fit.

💡 Tips

  • Paste a $ref value (e.g. #/definitions/User) to see exactly which schema fragment it points to.
  • A key containing / must be written as ~1 — copy the normalized pointer from this tool.
  • Array indexes start at 0, and "-" (the position after the last element) can't be read.

Frequently Asked Questions

What's the difference between JSON Pointer and JSONPath?

A JSON Pointer addresses exactly one value; JSONPath is a query language with wildcards and filters that can return many.

What does the empty pointer "" refer to?

The whole document (the root).

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
