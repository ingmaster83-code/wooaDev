PromQL Validator, Formatter & Explainer

Paste a PromQL expression to check its syntax and types (instant / range vector, scalar, string) by Prometheus rules, wrap long queries neatly and get an inside-out explanation. It also flags common mistakes such as too-short rate ranges, a missing le in histogram_quantile and counter / gauge mix-ups.

Example

⛔ 1 error(s), 1 warning(s) - result type instant vector

Input — PromQL expression

histogram_quantile(0.95, sum by (job) (rate(http_request_duration_seconds_bucket{job=~"api.*", status!~"5.."}[5m]))) > 0.5
and on(job) sum by (job) (rate(http_requests_total[30s])) > 100

What this tool does

Validate and understand a query in the browser before sending it to Prometheus. The query is not uploaded and no Prometheus server is contacted.

  • Parser: selectors (4 matcher types, offset, @), ranges and subqueries, aggregations (by / without before or after), binary operators (bool, on / ignoring, group_left / right), unary operators, 80+ functions and durations (1h30m)
  • Type checks: function argument types and counts, aggregation parameters, set operators with scalars, where bool is allowed, and final range-vector results
  • Formatting: only expressions wider than your limit are wrapped, at function, aggregation and operator boundaries
  • Explanation: numbered inside-out table of types and meanings (with second conversions) plus a syntax tree
  • Lint: too-short rate range, long irate range, histogram_quantile le / rate / _bucket, counter vs gauge, avg of avg, count() == 0, needless regex

💡 Tips

  • Use a rate() range of at least 4x the scrape_interval; for 30 s scrapes that means 2m or more.
  • Always keep le in the by list: histogram_quantile(0.95, sum by (le, job) (rate(x_bucket[5m]))).
  • Label matcher regexes are fully anchored automatically, so ^ and $ are unnecessary.

Frequently Asked Questions

Does it run the query?

No. It only checks syntax and types and explains the query; it cannot know whether a metric exists or what the result values are.

Does it support new Prometheus 3.x features?

Widely used newer functions such as histogram_avg, mad_over_time and limitk are included, but not every experimental feature. Unknown functions are reported as errors.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
