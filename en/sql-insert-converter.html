SQL INSERT Converter — INSERT to JSON & CSV

Reads INSERT INTO … VALUES (…),(…) statements from mysqldump or SQL files and turns them into JSON, CSV or JSON Lines with column names. Handles string escapes, NULL, numbers and multiple statements.

Example

✅ users: 3 row(s) · 6 column(s)

Input — SQL INSERT statements

INSERT INTO users (id, name, email, active, score, note) VALUES
  (1, 'Kim', 'kim@example.com', true, 3.5, NULL),
  (2, 'O''Brien', 'ob@example.com', false, 10, 'says "hi", ok'),
  (3, '이영희', NULL, 1, -2, 'line1\nline2');
INSERT INTO `orders` (`id`, `user_id`) VALUES (10, 1), (11, 2);

What this tool does

Use it when you want the data from a dump's INSERT statements in a spreadsheet or code without loading it into a database. The input never leaves your browser.

  • Multi-row VALUES (…),(…), several INSERT statements and comments (-- , /* */)
  • Values: strings ('O''Brien', backslash escapes), numbers (negative, exponent), NULL, TRUE / FALSE; function calls are kept as «…»
  • Identifiers: backticks, double quotes and brackets; db.table uses the table name
  • Without a column list columns are named col1, col2 …; a column / value count mismatch is an error
  • Table filter and an option to turn numbers and booleans into JSON types

💡 Tips

  • A big dump can have thousands of rows in one INSERT; pick only the table you need with the filter.
  • If Excel garbles non-ASCII text from the CSV, a UTF-8 BOM may be needed.
  • Files exported with column names (complete inserts) convert most accurately.

Frequently Asked Questions

Does INSERT … SELECT work?

No. Only statements with literal VALUES are converted; SELECT forms are skipped.

What about ON DUPLICATE KEY UPDATE?

That clause is ignored and the VALUES rows are extracted.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
