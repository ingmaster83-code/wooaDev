GCP Resource, GCS URL & Service Account Parser

Analyses resource names like projects/…/locations/…, gs:// and storage.googleapis.com addresses, service-account emails and key JSON. The private key is masked and exposure risks are flagged.

What this tool does

Google Cloud APIs use resource names like projects/{id}/locations/{loc}/…, and Cloud Storage alternates between gs:// and HTTPS addresses.

  • Resource names: split into collection / ID pairs and warn when the pairs do not line up
  • GCS: accepts gs://, storage.googleapis.com/bucket/object and bucket.storage.googleapis.com and converts to every form plus gsutil
  • Service-account email: separates account ID and project ID, warns about the default Compute Engine account
  • Key JSON: checks type, project_id and client_email, masks private_key and flags missing required fields
  • Checks bucket-name rules (no goog / google and so on)

💡 Tips

  • A service-account key (JSON) is a permanent credential when leaked. Prefer Workload Identity or an attached service account.
  • The default Compute Engine service account often has Editor rights; create a dedicated one.
  • storage.cloud.google.com is the signed-in browser view; storage.googleapis.com is the API / public-access address.

Frequently Asked Questions

What if the key JSON is exposed?

Delete that key at once and issue a new one (IAM → Service accounts → Keys). If it reached a repository, remove it from history too.

How do I reach a gs:// object over HTTP?

Use https://storage.googleapis.com/bucket/object; the object must be public or you need a signed URL or auth header.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
