What this tool does

PLCs, sensors, serial links and formats like ZIP, PNG or Ethernet each use a different CRC variant. Polynomial, initial value and reflection differ, so pick by name and compare them all at once.

  • CRC-8 (MAXIM, CDMA2000), CRC-16 (ARC, MODBUS, USB, CCITT-FALSE, XMODEM, KERMIT, X-25, GENIBUS, DNP)
  • CRC-32 (zlib / PNG), CRC-32C (iSCSI), BZIP2, MPEG-2, JAMCRC, XFER, CRC-64/XZ, Adler-32, Fletcher-16
  • Input is UTF-8 text or hex bytes, and each algorithm's standard check value is shown to verify the implementation
  • Enter a value to highlight the matching algorithm
  • Byte-swap option for protocols such as Modbus RTU that send the CRC-16 low byte first

💡 Tips

  • Modbus RTU transmits the low byte of the CRC-16 first; use the byte-swap option to see the wire order.
  • Same-named CRCs can differ in initial value between implementations, so first confirm the check value 123456789.
  • Hex input tolerates spaces and 0x prefixes.

Frequently Asked Questions

Why are there so many CRC-16 variants?

Each standard picks its own polynomial, initial value, bit reflection and final XOR. Match the name in your device's documentation (for example CRC-16/MODBUS).

Can a CRC protect against tampering?

No. CRCs detect accidental errors only and are easy to forge. Use SHA-256 and HMAC for security.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
