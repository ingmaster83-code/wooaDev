SQL DDL Viewer & ERD Generator

Paste CREATE TABLE, CREATE INDEX and ALTER TABLE statements to get tables, columns and keys in a table, plus foreign-key relationships as an ERD diagram and Mermaid erDiagram code. Design problems such as missing tables, type mismatches and unindexed foreign keys are listed with line numbers.

Example

⛔ 1 error(s), 1 warning(s) — 4 table(s)

Input — SQL DDL (CREATE TABLE, CREATE INDEX, ALTER TABLE)

CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  email VARCHAR(255) NOT NULL UNIQUE,
  name VARCHAR(100),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE posts (
  id BIGINT NOT NULL,
  user_id INT NOT NULL,
  title VARCHAR(200) NOT NULL,
  body TEXT,
  category_id BIGINT,
  PRIMARY KEY (id),
  CONSTRAINT fk_posts_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
);

CREATE TABLE tags (id INT PRIMARY KEY, label TEXT NOT NULL);
CREATE TABLE post_tags (post_id BIGINT NOT NULL REFERENCES posts(id), tag_id INT NOT NULL REFERENCES tags(id), PRIMARY KEY (post_id, tag_id));
CREATE INDEX idx_posts_title ON posts (title);
ALTER TABLE posts ADD CONSTRAINT fk_posts_cat FOREIGN KEY (category_id) REFERENCES categories(id);

What this tool does

See a database structure at a glance from the DDL script alone. Your SQL is not uploaded.

  • Parsing: CREATE TABLE (inline and table constraints), CREATE [UNIQUE] INDEX, ALTER TABLE ADD FOREIGN KEY / PRIMARY KEY / UNIQUE / COLUMN
  • Dialects: MySQL backticks, PostgreSQL double quotes, SQL Server brackets, comments and semicolons inside strings
  • Output: ERD (SVG), table / column list (type, NULL, key, default, comment), relationship table (ON DELETE / UPDATE, required / optional), Mermaid erDiagram
  • Checks: missing tables or columns, FK type mismatch, no primary key, unindexed FK, ON DELETE SET NULL on a NOT NULL column
  • Hints that can be turned off

💡 Tips

  • Index foreign-key columns to speed up joins and parent-row deletes; PostgreSQL does not create these indexes automatically.
  • Keep referencing and referenced column types identical, especially integer size and signedness.
  • Paste the Mermaid code into a Markdown file or GitHub README to render the ERD.

Frequently Asked Questions

Does it support every SQL dialect?

Common CREATE / ALTER statements from MySQL, PostgreSQL, SQLite and SQL Server are parsed. Views, triggers and functions are skipped, and some dialect-specific syntax may not be understood.

Does it connect to a database?

No. It only parses the DDL text you paste and never connects to a database.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
