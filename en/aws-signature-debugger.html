AWS Signature V4 Debugger

Enter a request URL, headers, body and a test key to see the SigV4 canonical request, string to sign, the date → region → service → signing key chain, the final signature and the Authorization header (or presigned URL). Compare with an expected signature to find where it diverges.

What this tool does

See which step is wrong when you get 403 SignatureDoesNotMatch. Keys and requests never leave your browser.

  • Modes: Authorization header signing and presigned URL (query string)
  • Steps: canonical URI (double-encoded except S3), canonical query, signed headers, payload hash, string to sign, kDate → kRegion → kService → kSigning, final signature
  • Payload: body SHA-256, UNSIGNED-PAYLOAD and STREAMING modes
  • Enter an expected signature to diagnose which input (header, query, body, time) differs
  • Verified against the official AWS test vectors such as get-vanilla

💡 Tips

  • The Host header and X-Amz-Date must be signed and must equal the values you actually send.
  • Non-S3 services encode the canonical URI twice, which often breaks paths with special characters.
  • A signing time more than 15 minutes from the server clock is rejected even if the signature is correct.

Frequently Asked Questions

Is it safe to enter a real Secret Access Key?

Calculation happens only in your browser and nothing is sent, but use test keys only. If you entered a real key, rotate it.

When do I need signing without an AWS SDK?

When calling AWS APIs over plain HTTP, on embedded devices or in other languages: compare this tool's intermediate values with your implementation to debug it.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
