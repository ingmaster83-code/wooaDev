Mobile Deep Link & Intent URI Builder

Builds a custom scheme like myapp://product/42, an https universal / app link and an Android intent:// URI with a fallback URL in one go, with AndroidManifest, assetlinks.json and AASA samples and test commands.

Example

✅ Deep links built

Input — Query parameters (key=value per line)

id=42
ref=email campaign
utm_source=news

Input — Link to analyse (URL or intent:// URI)

intent://product/42?ref=mail#Intent;scheme=myapp;package=com.example.shop;S.browser_fallback_url=https%3A%2F%2Fshop.example.com%2Fproduct%2F42;end

Result — Links

# Custom scheme (iOS / Android)
myapp://product/42?id=42&ref=email%20campaign&utm_source=news

# Universal link (iOS) / App link (Android)
https://shop.example.com/product/42?id=42&ref=email%20campaign&utm_source=news

# Android intent URI (open the app from Chrome + fallback URL)
intent://product/42?id=42&ref=email%20campaign&utm_source=news#Intent;scheme=myapp;package=com.example.shop;S.browser_fallback_url=https%3A%2F%2Fplay.google.com%2Fstore%2Fapps%2Fdetails%3Fid%3Dcom.example.shop;end

# Test commands
adb shell am start -a android.intent.action.VIEW -d "myapp://product/42?id=42&ref=email%20campaign&utm_source=news" com.example.shop
xcrun simctl openurl booted "myapp://product/42?id=42&ref=email%20campaign&utm_source=news"
adb shell am start -a android.intent.action.VIEW -d "https://shop.example.com/product/42?id=42&ref=email%20campaign&utm_source=news"
xcrun simctl openurl booted "https://shop.example.com/product/42?id=42&ref=email%20campaign&utm_source=news"

Result — Components

Item | Value
scheme | myapp
host | product
path | /42
query | id, ref, utm_source
web | shop.example.com
package | com.example.shop

What this tool does

For making links that open a specific screen of your app on each platform.

  • Build: scheme, host, path, query (percent-encoded automatically), web domain, Android package and fallback URL
  • Output: custom scheme URL, https universal / app link, intent://…#Intent;scheme=…;package=…;S.browser_fallback_url=…;end
  • Config samples: AndroidManifest intent-filter (autoVerify), assetlinks.json, apple-app-site-association and iOS Associated Domains
  • Testing: adb shell am start -a VIEW -d and xcrun simctl openurl booted
  • Parse mode: break a URL or intent URI into components and check for a missing package or fallback

💡 Tips

  • Do not pass sensitive values such as login tokens through a custom scheme; another app can claim the same scheme.
  • On Android 12+ web links open the app only after assetlinks.json domain verification passes.
  • Serve iOS's apple-app-site-association without an extension as application/json.

Frequently Asked Questions

Custom scheme or universal link?

Universal / app links are safer and fall back to the web; custom schemes are simple but fail when the app is missing.

Where is intent:// used?

In browsers such as Chrome on Android to open the app and fall back to a URL on failure. It does not work on iOS.

Is my data uploaded to a server?

No. Everything is processed inside your browser; what you enter is never sent to or stored on a server, so you can safely paste data containing personal information, internal settings or API keys.
