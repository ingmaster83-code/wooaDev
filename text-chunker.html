텍스트 청킹 도구 — RAG · 임베딩 전처리

긴 문서를 임베딩과 검색에 쓰기 좋은 청크로 나눕니다. 글자 수·토큰(추정)·문단·마크다운 제목·문장 기준과 겹침(overlap)을 지원하고, 단어·문장 경계에서 자르기, 청크 표와 JSON 출력, 너무 짧은 청크 경고를 제공합니다.

사용 예시

✅ 청크 2개 · 평균 210자 · 전체 ≈165 토큰

입력 — 나눌 문서

# RAG 소개

RAG(Retrieval-Augmented Generation)는 외부 문서를 검색해 LLM 의 답변을 보강하는 방식입니다. 문서를 적당한 크기로 나누는 청킹이 검색 품질을 좌우합니다.

## 청킹 전략

고정 길이 청킹은 단순하지만 문장이 중간에서 잘릴 수 있습니다. 문단·제목 기준 청킹은 의미 단위를 유지합니다. 겹침(overlap)을 두면 경계에서 문맥이 끊기는 문제를 줄일 수 있습니다.

## 주의사항

청크가 너무 작으면 문맥이 부족하고, 너무 크면 관련 없는 내용이 섞여 검색 정밀도가 떨어집니다. Chunks that are too large also cost more tokens when they are placed in the prompt.

이 도구로 할 수 있는 일

벡터 검색용 문서를 나눌 때 청크 크기와 겹침을 바꿔 가며 결과를 바로 확인합니다. 문서는 브라우저 밖으로 나가지 않습니다.

  • 기준: 글자 수, 토큰 수(추정), 문단(빈 줄), 마크다운 제목(#), 문장
  • 글자·토큰 기준에서는 겹침과 단어·문장 경계에서 자르기 지원
  • 문단·문장 기준은 작은 단위를 크기 한도까지 합치고, 제목 기준은 제목마다 새 청크 (겹침은 적용하지 않음)
  • 토큰 추정: 영어 약 4자/토큰, 한국어 약 1.5자/토큰, 혼합은 자동 (정확한 값은 모델의 토크나이저로)
  • 청크 표(범위·길이·토큰·겹침·미리보기)와 JSON(id, start, end, text), 짧은 청크 경고

💡 Tips

  • 일반적으로 200~500 토큰에 10~20% 겹침에서 시작해 검색 결과를 보며 조정합니다.
  • 표나 코드 블록은 중간에서 잘리지 않도록 문단·제목 기준을 쓰세요.
  • 한국어는 영어보다 같은 글자 수에서 토큰이 훨씬 많이 듭니다.

자주 묻는 질문

청크가 너무 작거나 크면 어떻게 되나요?

너무 작으면 문맥이 부족하고, 너무 크면 관련 없는 내용이 섞여 검색 정밀도가 떨어지고 프롬프트 비용도 늘어납니다.

토큰 수가 모델과 다른 이유는요?

글자 수로 추정한 값이라서입니다. 정확한 값은 tiktoken 같은 해당 모델의 토크나이저로 계산하세요.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
