JSON 유효성 검사기 — 문법 오류 위치·중복 키 찾기

JSON 문법 오류가 몇 번째 줄 몇 번째 칸에 있는지 알려주고, 조용히 덮어써지는 중복 키까지 찾아냅니다.

사용 예시

❌ 유효하지 않은 JSON — 후행 쉼표(trailing comma)는 허용되지 않습니다 (줄 4, 열 17)

입력 — JSON 입력

{
  "name": "WooaDev",
  "tools": [1, 2, 3],
  "active": true,
}

결과 — 오류 위치

     2 │   "name": "WooaDev",
     3 │   "tools": [1, 2, 3],
▶    4 │   "active": true,
       │                 ^ 후행 쉼표(trailing comma)는 허용되지 않습니다
     5 │ }

이 도구로 할 수 있는 일

JSON.parse()는 오류가 나도 "Unexpected token" 정도만 알려 주고, 같은 키가 두 번 나와도 아무 말 없이 마지막 값으로 덮어씁니다. 이 도구는 JSON을 처음부터 끝까지 직접 읽으면서 오류가 생긴 줄·열 위치와 원인을 쉬운 말로 설명합니다.

  • 후행 쉼표, 작은따옴표, 따옴표 없는 키, 주석, undefined·NaN 같은 흔한 실수를 구체적인 문장으로 안내
  • 같은 객체 안에서 반복된 키를 경로와 위치까지 목록으로 표시 (뒤의 값이 앞의 값을 덮어씀)
  • 최대 깊이, 객체·배열·문자열·숫자 개수와 파일 크기를 함께 요약

구조가 심하게 깨진 JSON은 JSON 복구 도구로 고치고, 보기 좋게 정리하려면 JSON 포맷터를 쓰세요.

💡 Tips

  • 오류 위치의 ▶ 표시 줄이 문제가 처음 발견된 곳입니다. 실제 원인은 바로 앞 줄(닫히지 않은 따옴표·괄호)인 경우가 많습니다.
  • 설정 파일처럼 같은 키가 실수로 두 번 들어가기 쉬운 JSON은 중복 키 검사로 점검하세요.
  • 숫자 앞의 0(007), 16진수(0xFF), Infinity는 JSON 규격에서 허용되지 않습니다.

자주 묻는 질문

JSON.parse 오류 메시지만으로는 어디가 틀렸는지 모르겠어요.

브라우저마다 오류 문구가 달라 위치를 알려 주지 않는 경우가 많습니다. 이 도구는 자체 파서로 줄·열 번호와 앞뒤 몇 줄의 코드를 함께 보여 주므로 틀린 곳을 바로 찾을 수 있습니다.

중복 키가 있으면 JSON이 잘못된 건가요?

RFC 8259는 키가 유일해야 한다고 권고할 뿐 문법 오류로 보지는 않습니다. 다만 파서마다 처리 방식이 달라(대부분 마지막 값 사용) 의도하지 않은 설정으로 이어질 수 있어 따로 알려 드립니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
