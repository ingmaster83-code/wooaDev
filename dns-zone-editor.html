DNS 레코드 생성 · BIND 존 파일 편집기

BIND 형식 존 파일을 읽어 정렬된 형태로 다시 쓰고, 레코드를 추가하고, SOA serial을 올리고, 흔한 설정 실수를 찾아 줍니다.

사용 예시

⚠️ 레코드 9개 — 확인할 항목 1개

입력 — BIND 존 파일

$ORIGIN example.com.
$TTL 3600
@   IN SOA ns1.example.com. admin.example.com. (
        2026101601 ; serial
        7200       ; refresh
        3600       ; retry
        1209600    ; expire
        3600 )     ; minimum
    IN NS  ns1.example.com.
    IN NS  ns2.example.com.
    IN MX  10 mail.example.com.
@   IN A   203.0.113.10
www IN CNAME @
mail IN A  203.0.113.20
@   IN TXT "v=spf1 mx -all"
ftp IN CNAME www.example.com

이 도구로 할 수 있는 일

직접 운영하는 BIND·NSD·PowerDNS 존 파일은 괄호 안의 SOA, 상대 이름과 절대 이름, 끝 점(.) 누락 같은 실수가 잦습니다. 붙여 넣으면 구조를 읽어 검사하고 정리해 줍니다.

  • 지원: $ORIGIN, $TTL, 여러 줄 SOA(괄호), ; 주석, 이전 이름 이어쓰기, A·AAAA·CNAME·MX·NS·TXT·SRV·CAA·PTR 등
  • 출력: 이름·TTL·종류가 정렬된 존 파일, 레코드 표
  • 레코드 추가: 종류·이름·값·TTL을 입력하면 파일에 추가 (TXT는 자동으로 따옴표 처리)
  • SOA serial: 그대로 / +1 / 오늘 날짜(YYYYMMDDnn)로 갱신
  • 검사: SOA·루트 NS 누락, CNAME과 다른 레코드의 공존, 루트 CNAME, A/AAAA 값 형식, MX 형식, 끝 점이 없어 도메인이 덧붙는 대상, TXT 255바이트 초과, TTL 형식

💡 Tips

  • CNAME 대상 이름 끝에 점(.)을 붙이지 않으면 $ORIGIN이 덧붙어 www.example.com.example.com. 이 되는 실수가 가장 흔합니다.
  • 존 파일을 수정한 뒤에는 SOA serial을 반드시 올려야 보조 네임서버가 변경을 가져갑니다.
  • $INCLUDE·$GENERATE 지시자는 해석하지 않고 건너뜁니다.

자주 묻는 질문

루트(@)에는 왜 CNAME을 못 쓰나요?

루트에는 SOA·NS 같은 다른 레코드가 반드시 있어야 하고, CNAME은 같은 이름의 다른 레코드와 공존할 수 없기 때문입니다. A 레코드나 업체의 ALIAS/ANAME 기능을 쓰세요.

TXT 레코드가 255자를 넘으면 어떻게 하나요?

하나의 문자열은 255바이트까지라서 긴 값(DKIM 키 등)은 "..." "..." 처럼 여러 문자열로 나눠 한 레코드에 넣습니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
