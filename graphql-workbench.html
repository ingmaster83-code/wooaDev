GraphQL 스키마 · 쿼리 작업대

GraphQL SDL 을 붙여 넣으면 타입 표와 스키마 오류(미정의 타입, 인터페이스 구현 누락, 미사용 타입)를 알려 주고 보기 좋게 정리합니다. 쿼리를 함께 넣으면 필드·인자·변수·프래그먼트를 스키마에 맞춰 검증하고 오타에는 추천 이름을 보여 줍니다.

사용 예시

⛔ 오류 6건 · 경고 1건 — 타입 8개

입력 — 스키마 (SDL)

schema { query: Query mutation: Mutation }

"""사용자"""
type User implements Node {
  id: ID!
  name: String!
  email: String
  posts(first: Int = 10, after: String): [Post!]!
  role: Role!
}
type Post { id: ID! title: String! author: User! tags: [String!] }
interface Node { id: ID! }
enum Role { ADMIN EDITOR VIEWER }
union SearchResult = User | Post | Comment
input NewPost { title: String! body: String authorId: ID! }
type Query {
  user(id: ID!): User
  users(role: Role): [User!]!
  search(term: String!): [SearchResult!]!
}
type Mutation { createPost(input: NewPost!): Post! }

입력 — 쿼리 · 뮤테이션 (선택)

query GetUser($id: ID!, $unused: Int) {
  user(id: $id) {
    id
    nane
    role { name }
    posts(first: "5") { title author { email } }
    ...UserBits
  }
}
fragment UserBits on User { email, missing }
mutation { createPost(input: { title: "Hi" }) { id } }

결과 — 스키마 타입 목록

타입 | 종류 | 필드·값 수 | 역할·구현 | 줄
User | type | 5 | → Node | 4
Post | type | 4 |  | 11
Node | interface | 1 |  | 12
Role | enum | 3 |  | 13
SearchResult | union | 3 |  | 14
NewPost | input | 3 |  | 15
Query | type | 3 | Query  | 16
Mutation | type | 1 | Mutation  | 21

결과 — 점검 결과

⛔ 스키마 줄 14: union SearchResult 의 멤버 Comment 이(가) 정의되지 않았습니다
⚠️ 쿼리 줄 1: 변수 $unused 이(가) 사용되지 않습니다
⛔ 쿼리 줄 4: 타입 User 에 필드 "nane" 이(가) 없습니다 — "name" 을(를) 말씀하셨나요?
⛔ 쿼리 줄 5: "role" 은(는) 리프 타입(Role)이라 하위 선택을 할 수 없습니다
⛔ 쿼리 줄 6: 인자 first 의 값 "5" 이(가) 타입 Int 와 맞지 않습니다
⛔ 쿼리 줄 10: 타입 User 에 필드 "missing" 이(가) 없습니다
⛔ 쿼리 줄 11: 인자 input 의 값 {title: "Hi"} 이(가) 타입 NewPost! 와 맞지 않습니다

이 도구로 할 수 있는 일

서버 없이 스키마와 쿼리를 브라우저에서 검증합니다. 입력은 서버로 전송되지 않습니다.

  • 스키마: 미정의 타입 참조, 인터페이스 구현 누락, 중복 정의, 입력/출력 타입 규칙, 미사용 타입
  • 쿼리: 존재하지 않는 필드(추천 이름 제시), 필수 인자 누락, 변수 타입, 프래그먼트, 선택 집합 규칙
  • 타입 표: 종류, 필드·값 수, 구현 관계, 줄 번호
  • SDL 과 쿼리를 정렬해 다시 출력
  • 권고(끌 수 있음)

💡 Tips

  • 필드 이름에 오타가 있으면 '~을(를) 말씀하셨나요?' 로 가장 비슷한 이름을 알려 줍니다.
  • extend type 과 directive 정의도 해석하므로 연합(federation) 스키마의 일부를 붙여 넣어도 됩니다.
  • 정리된 SDL 은 팀의 .graphql 파일 형식을 통일하는 데 쓸 수 있습니다.

자주 묻는 질문

모든 GraphQL 검증 규칙을 구현했나요?

자주 쓰는 스키마·쿼리 규칙을 구현했지만 graphql-js 의 전체 규칙은 아닙니다. 서버에 배포하기 전 공식 라이브러리로 한 번 더 확인하세요.

쿼리 없이 스키마만 넣어도 되나요?

네. 쿼리 칸이 비어 있으면 스키마 검사와 정리만 수행합니다.

입력한 데이터가 서버로 전송되나요?

아니요. 모든 처리는 브라우저 안에서만 이루어지며 입력한 내용은 서버로 전송되거나 저장되지 않습니다. 개인정보나 사내 설정값, API 키가 들어 있는 데이터도 안심하고 붙여 넣을 수 있습니다.
